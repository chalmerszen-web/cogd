# AOQ Session and fixed speech trial host tests

Run from the repository root on Linux or WSL:

```sh
bash tests/aoq_session/run.sh
```

Requires Bash, GCC/G++, POSIX threads and the compiler's AddressSanitizer and
UndefinedBehaviorSanitizer runtimes. `CC` and `CXX` may select other compatible
compilers. The script uses only checked-in source, builds in a temporary directory
and removes that directory on exit. It needs no ESP-IDF SDK, credentials, recorded
audio, allocation response, device or network. Assertions remain enabled.

| Test | Production code exercised | Replaced boundaries |
| --- | --- | --- |
| `test_session.cpp` | `aoq_session.cpp`, transport identity, stream window, wire/object/media-control codecs | Allocation is an explicitly enabled synthetic response for `open()` tests and aborts otherwise; QUIC and sockets are inert mocks; clock, task delay and PSRAM allocation are host substitutes. Other tests enter a constructed accepted Session and inject frames. |
| `test_tts.cpp` | `aoq_tts_trial.cpp`, PCM object properties codec | Session emits synthetic task events/PCM/terminals, including reordering and wrong identities. No service TTS or audio device is used. |
| `test_asr.cpp` | `aoq_asr_trial.cpp`, the real `aoq_pcm_fixture.cpp` FIR conversion | TTS cache contains a synthetic signal; Session emits synthetic results; Base64 API, random and clock are host substitutes. No recognizer or microphone is used. |
| `test_dialogue.cpp` | `aoq_dialogue_trial.cpp`, the real FIR conversion | Session emits synthetic model events and audio; upload accepts mocked frames. No native audio network or model inference is exercised. |
| `test_conversation.cpp` | `aoq_conversation.cpp`, response/media ownership | Synthetic Data/Audio/terminal order exercises early PCM, completion, cancellation and overlapping responses. No model or device is used. |
| `test_speech.cpp` | `aoq_speech.cpp`, general independent ASR/TTS adapter | Synthetic tasks exercise late PCM after task completion, quiet/terminal drain, partial reads, task identity, backpressure and resource bounds. No generic speech-provider hardware result is implied. |

The production `.cpp` files are included directly, not copied. Session tests use
private-state access only in the test translation unit to inject boundary states.
The concurrent cancellation test exercises pointer replacement versus the stable
atomic epoch; ASan/UBSan do not establish freedom from every possible data race.
The mocks do not establish a successful TLS handshake or server interoperability.

The Opus platform boundary is scripted, not a codec implementation. Session
cases check 48 kHz metadata normalization to 24 kHz PCM, decoder failure,
incomplete input consumption, wrong decoded length/rate/channels/sample width,
and decoder cleanup. Actual Opus decoding remains a P4 hardware test. This
harness also checks receiver-task creation failure and starts/joins the actual
idle receiver body using a host thread with inert sockets. Worker sleeping
does not advance the owner's synthetic clock. This is not FreeRTOS timing or
real UDP validation. The separate packet-queue tests cover the host SPSC queue.

Session coverage includes partial writes, zero acceptance on full queues,
fragmented and duplicate receive frames, Audio held until server media selection,
transactional selection failure, object terminal versus FIN, reentrant callbacks,
token deadline after acceptance, cancellation and stream caps. Some synthetic
frames are generated by the production encoder; independent wire compatibility
must be established separately from these round-trip checks.

Literal control TLVs also exercise the actual `Session::open()` path with
ServerSetup, Notify and GoAway both coalesced and fragmented across poll ticks.
The synthetic GoAway payload is 109 bytes; it is not a captured server reason.
Acceptance followed by this rejection must return `server_goaway`, with media
selection false and no task object sent. A future GoAway arriving after `open()`
has returned is necessarily handled by subsequent polling, not predicted here.

Diagnostic tests cover long synthetic tokens/signed SIDs, URL/address redaction,
quotes, backslashes, control bytes, UTF-8 input, one-byte output capacity and
maximum string truncation. Output must remain bounded printable ASCII and parse
as JSON. These tests validate the current redaction policy, not detection of all
possible secret formats.

TTS coverage includes matched task lifecycle, fresh cache generations, Busy retry,
PCM capacity and contiguous transport object IDs, the single-PCM-tuple restriction, and rejection
of an EndGroup/EndTrack from another stream or before the PCM tuple exists. An
arbitrary FIN cannot complete the fixed trial.

The explicit model-finished plus bounded receive-drain alternative is tested
separately, including new PCM extending the drain wait and buffered gaps blocking
completion. A quiet-window policy is not proof that arbitrary future packets
cannot arrive. The dialogue trial requires this drain even after a segment ends.
Its tests also cover model readiness, Busy upload, PCM arriving before the Data
response event, rejected extra responses, wrong completion identity, missing
objects, cancellation, and exact retained-generation playback admission.

The microphone adapter adds partial capture reads, empty input, playback open/
write/join failures, cancellation after playback begins, required drain, and
rejection of a second independently ordered audio stream. Its existing audio
owner is mocked here; ASan checks the ring remains alive until finish joins.
The capture-clock regression models a 1.5-second connection delay and a live
16-kHz producer. It verifies that bounded catch-up preserves every PCM sample,
order and capture timestamp, never sends future timestamps, and clears the
backlog with both normal acceptance and a Busy retry. This is a host scheduling
test, not a measured cloud or device latency result.
Endpoint-cue regressions delay response PCM by 700 ms after speech-stop, require
the existing playback owner to open before that response, ignore a duplicate
speech-stop without replaying the cue, and require a joined cleanup if the model
never sends an answer. The board cue waveform itself needs acoustic validation.
The fixed video tests require actual negotiated JPEG permission, two frames and
the distinct expected color/shape. Session tests also cover the one-frame queue,
Data priority, partial writes, pending FIN, timestamp bounds and failed FIN.
The dialogue mock rejects a video send before it has delivered the cloud
speech-start event. This guards the observed real-camera image-before-audio
failure; audio socket acceptance alone does not satisfy the gate. Live camera
cases also reject old timestamps and cancelled sources without opening playback.

TTS tests also propagate a failed Session open with GoAway without sending a task
or retaining PCM. A report stress case combines both maximum diagnostic strings,
maximum-width tuple IDs and large counters; it prints its required capacity and
checks rejection at 1536 bytes and success with the current 2048-byte minimum. Capacity failure
remains an explicit error, never a truncated success report.

ASR coverage includes exact source generation, the eight-second input bound,
200-frame maximum, drain-before-finish, Busy retry with identical event ID,
heartbeat/interim exclusion, final sentence deduplication and ordering, UTF-8 and
text limits, cancellation/provider failures, and exact fixed-text comparison.
Wrong words such as `原声` versus `原生` fail even if the task transport completes.
The fixed test phrase is `原生语音测试成功。`; it is input data, not a claim of success.

## Official ASR contract and remaining live checks

The [exact-model server event reference](https://platform.qianwenai.com/docs/api-reference/speech-recognition/qwen-audio-asr-streaming/server-events)
specifies normal sentence IDs starting at 1 and heartbeat IDs of 0. The parser
ignores heartbeats before validating final sentence IDs; it does not assume that
all other DashScope models use the same range.

The [AOQ ASR tutorial](https://platform.qianwenai.com/docs/developer-guides/tutorials/realtime/aoq-asr-streaming)
explicitly describes sending buffered PCM faster than real time over Data and
draining it before `finish-task`. It does not specify an unlimited rate or promise
that any particular multiplier is accepted. This trial sends bounded 40-ms PCM
chunks with queue backpressure; it is not paced microphone capture. Actual server
rate acceptance, recognition accuracy, TLS/protocol compatibility, PSRAM timing,
acoustic quality and playback remain live acceptance items. Passing these tests
does not replace those results or any existing failed hardware evidence.

Arbitrary provider error messages, raw JSON payloads, task UUIDs, SID and tokens
are not returned by the production reports. Synthetic marker strings check that
private provider messages are not copied into reports. Dialogue failures may
report a bounded identifier-shaped error code and a fixed vocabulary of error
keywords, never the original message. Bounded input transcripts and answer text
are intentional diagnostic fields. These tests are not a complete information-flow audit.

The TTS regressions separately exercise constant/jumping internal LOC cursors and missing/repeated transport object IDs. Internal cursor changes do not imply missing Segment PCM; object order, payload duration, task identity and the declared completion policy remain required. Diagnostic output now requires 2048 bytes. Trial state and ASR encoding scratch use the PSRAM allocator boundary to avoid placing large objects on the shared network worker stack.
