# UX175：现有频谱特征能否支撑轻量续说分类

2026-09-29。本轮完成一次512步本地小模型试验，**没有通过集成条件，未改设备固件**。
相比继续试静音阈值，本轮取得了另一类证据：旧回放数据的标签位置与当前采集条件
都不足以直接支撑一个可靠的续说分类器。下一步先做当前条件下的时间标定，暂不扩大训练。
完整交互目标和稳定一秒有效回答仍未完成。

## 一次固定小试

复用KWS开发阶段保存的76份6秒设备录音和对应合成源文件；其KWS“负例”也是人声，
没有错误地把“嗨乐鑫”等非目标词当成VAD静音。保持原声音划分：8个训练声音、2个
验证声音，均为合成回放素材；没有真人盲测。246个来源身份检查未发现跨集合复用。

先按已有时间对齐记录的相关度不低于0.5筛选：61份有可用测量，其中训练39份、验证
22份；另外15份（训练9、验证6）明确不评分，全部是粤语素材。**因此后面的分数只适用
于参与评分的代理标签，不能代表全部76份，也不能用来宣称双语识别率。**

标签来自播放源而非设备能量：源32ms窗RMS超过`max(32,峰值/32)`，且前后48ms都满足
时，标记为回放人声存在；源前200ms或源后300ms以外才作背景代理，录音前200ms排除，
其余未知。未人工确认背景中没有其他声音；这是可错的回放存在标签，不是逐帧人声真值。

特征复用当前C代码的Q15 FFT、512点窗、256样本步长和40个log-mel频带。
两帧因果输入经80→16 ReLU→1 logit，共1313参数；只在电脑使用PyTorch浮点训练。
TRAIN标注帧计算均值/标准差，标准差下限0.25、归一化截断±4；验证数据不选检查点。
固定种子20260929，AdamW学习率0.003、权重衰减0.001，512步，每批64正/64负随机取样。
固定0.5判据，没有阈值搜索、追加训练或根据诊断样本更新权重。

环境为WSL、PyTorch2.6.0+cpu、NumPy1.26.4、4线程。单次优化循环记录0.246秒，
不包含特征提取；不是设备推理耗时。保留最后模型、全部配置、脚本和训练记录。

## 结果没有达到预定门槛

| 代理标签分组 | 人声帧命中 | 背景帧被接纳 |
| --- | ---: | ---: |
| 训练合计 | 1550/1692，91.6% | 630/9652，6.5% |
| 验证合计 | 873/1029，84.8% | 345/5344，6.5% |
| 验证普通话 | 574/646，88.9% | 278/2907，9.6% |
| 验证粤语 | 299/383，78.1% | 67/2437，2.7% |

预先写入的进入后续集成筛查门槛是验证人声帧至少90%、背景误接纳不超过5%。
两项总体均未通过，不按某一种语言或某一份好结果改变判据。帧之间相关，不能把这些
计数换算为独立样本数、每小时误唤醒率、完整对话成功率或提升百分比。

## 为什么不继续加训练轮数

训练结束后保持模型不变，对原61份做独立三频段时间对齐复核，沿用既有门槛：
各频段包络相关度≥0.75、主峰与竞争峰差≥0.05、三个偏移相差≤30ms。
只有27份通过（训练18、验证9），其偏移与原对齐都相差不超过20ms。
其余34份只是未能独立确认，不能断言其标签必然错误；也不能把原来的±48ms余量
当作已经证实足够。**未删除或改写原标签、分数，没有利用较好子集重新训练或改记通过。**

另外将冻结模型用于11份此前保存的诊断录音，使用原始幅度、原始PCM和同一C特征，
仅看输出分布，不做端点修改或模拟新的设备对话。六份完整改口中：

| 诊断录音 | 3000–3240ms内高于0.5 | 最后1秒高于0.5 |
| --- | ---: | ---: |
| UX142第1/2/3份 | 9 / 9 / 8，分别共15帧 | 41 / 33 / 30，分别共63帧 |
| UX132第1/2/3份 | 3 / 2 / 2，分别共15帧 | 3 / 4 / 3，分别共63帧 |

保存的背景尾段最后1秒为29/63；数字静音为0/63。诊断区间不是人工标签，但这些差异
不足以支持把0.5输出直接当作续说依据。弱区特征被归一化截断的比例约0.4–1.7%，
不能简单归因于整个输入都超出数值范围；也尚未将原因归于单一硬件参数。
旧KWS采集与当前并发Wi-Fi、Flash、扬声器状态并不相同，不能直接把旧数据的小试分数
推到当前工作链路。本轮没有为此再拟合模型。

## 下一步的具体边界

先建立当前收音链路的有限时间标定，使用播放源前后两个已知同步声测量偏移和时钟差，
避开同步声及其余响来标注人声和背景；不可继续仅靠弱语音包络猜时间。
应保留实际ASR上传与采集时的射频/Flash条件，不能直接复用会关闭联网语音路径的
`capture_prompt.py`，把安静录音误当并发场景。若新增诊断出口，必须默认关闭、在回复/
工具/历史写入之前结束，并使用原完整备份和应用恢复流程，保护剩余上下文空间。
先至多三份时间标定采集，不进行云端回复生成或新模型训练；对齐和帧完整性先通过，
才讨论训练集扩充。标定录音不算三轮连续对话验收，后者仍须在正常固件另行完成。
