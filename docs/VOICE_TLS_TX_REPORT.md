# UX308–309：实际工作区与 TLS 发送缓冲核对

2026-10-02。这两项有限实验已结束，未采用实验固件。现场误唤醒仍未修好，不能据三次正确唤醒认定误触率下降。

UX308 使用 ESP32-C3 编译器分别编译原布局和仅减少 512 字节候选前缀的原型。采集结构从 28,216 降到 27,704 字节，但复用引擎需要 29,836 字节，两种配置的实际分配均为 29,836 字节。该改动不能释放堆，已否决，没有修改任务栈。

UX309 仅把 TLS 发送内容上限从 4,096 改为 2,048 字节。接收仍为 16,384 字节，动态缓冲、证书验证、超时和失败后不重放的策略保持。`AGENT_TLS_TX_COMPACT` 默认关闭；启用时要求配套 SDK 配置。保持上下文、输入与回复预算、24/24/48 声学模型、阈值、判定窗口、VAD 和全部任务栈。

提取当前固定 SDK 的原写入函数进行主机验证，未改 SDK。两种缓冲各九项 ASan/UBSan 检查覆盖大请求、短写、WANT_READ/WRITE、零返回及硬错误，18 项通过。初编因 SDK 的有符号/无符号条件表达式告警失败，尚未执行测试；原日志保留，只在测试中为该 SDK include 隔离告警。初次构建冻结检查错误地要求独立 KWS 组件携带 main 组件宏，原失败脚本保留，修正检查作用域后通过，没有重建或改固件。

单次正常构建应用 1,533,120 字节，距工程预算余 6,976 字节。SHA256：`a7360f42e0f819d9161c9db9233f59e23c7f325f6cd1dd157cb758fb809b2db3`。生成配置与 UX301 逐项比较，仅发送上限不同；实际链接保留两个 ASR 优先协作回调。

唯一一组正常业务使用公开普通话、粤语、普通话唤醒素材，各一次尝试，命名请求为“记住……小星星”。后两次唤醒在前轮完成后约 266/281 毫秒发起，未等待 ready、未逐轮查询或导出录音，也没有补跑失败轮。

UX301 SDK 最低值为 47,728 字节。本轮只多 128 字节，仍差 1,296 字节达标；两个不同业务运行的差额不是受控的纯缓冲收益。首次记录到最低值的是第一轮 `tts_done`，累计最小值不说明那一刻才发生低点。这项修改没有充分的实测收益，保持默认关闭，不再换另一发送上限或减栈凑数。

外部实录与本地独立 ASR 保留。第一、三轮的应答语能量起声候选距输入结束约 2.765/2.676 秒，最终回答候选约 7.275/6.286 秒；第二轮输入波形没有通过固定匹配门槛，延迟保留未知。应答语、最终回答分别计时，以上均不是人工首音素标注；三轮 `within_one_second` 均为未知，不记为通过。

两次 Flash 写入都经 `flash_guard` 新鲜完整备份并验证 4 MiB，只写应用，应用读回及全部非应用字节核对通过。184.56 秒设备执行已结束，恢复 `0.11.72-summary`，自动唤醒和自动语音关闭，USB 已释放。新增六条事件保留：1,350→1,356，已用 924,392→927,140 字节，下一记录 4,583，世代 18；2 MiB 上下文分区、204,800 字节历史预算、128 最近轮、摘要、灯状态及音量 80 保持。原始录音、备份和构建材料继续排除在 Git 外。

误触的当前有效证据仍为 UX302 同板对照两版均 2/10，以及 UX303 对误词输入的逐块复核。UX306–307 的新模型因固定准入条件失败没有烧录。双语、ASR/VAD、流式回复、连续重唤醒和动态话题的完整目标仍继续；本阶段不是完成验收。
