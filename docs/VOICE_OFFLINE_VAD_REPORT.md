# UX173：用离线模型检查弱语音与噪声

2026-09-29。上一轮已否决ASR活动辅助弱帧的候选，本轮停止门槛与等待时间扫描。
用一个独立离线模型检查11份既有录音，随后仅比较现有C滤波器这一确定差别。
**结果不支持直接替换当前端侧VAD，未修改生产代码、训练模型或烧录。**

## 可复现设置

参照为[Silero VAD官方源码](https://github.com/snakers4/silero-vad/tree/5cd7945676eb32225748052e2e6a0580e4686a08)，
固定v6.2.3提交`5cd7945676eb32225748052e2e6a0580e4686a08`。MIT许可证、源码与模型
下载在本地证据目录，未上传录音。模型2327524B，SHA256：
`1a153a22f4509e292a94e67d6f9b85e8deb25b4988682b7e174c65279d8788e3`。
这只是电脑端ONNX模型文件大小，不是量化后C3权重、固件或RAM预算。

原版OnnxWrapper与VADIterator在CPU运行，ONNX Runtime1.18.0、PyTorch2.3.1，
单线程。固定16kHz、每块512样本，阈值0.5/0.35、700ms静音，无增益归一化。
每份输入重置循环状态。不足512样本的尾块省略并记录，未补零来推算未知结束。
共2313个完整块，每种预处理各一次，不增加独立样本数。本文时间均相对保存
录音起点，不是说完到回复的延迟。

11份输入：UX169清单的8份（完整改口、两个短问候、背景尾段、数字静音、UX142
三段改口），再加UX132三段完整8秒诊断录音。全部WAV、元数据及模型先固定哈希。
它们是合成声音在设备旁回放的采集或注明的控制，不构成真人双语泛化证明。

## 原始PCM与现有滤波的配对

| 输入 | 现有C端点/EOF ms | 原始PCM参照首次结束决定 ms | 现有滤波后的参照 ms |
|---|---:|---:|---:|
| 旧完整改口UX90 | 6680 | EOF仍在语音 | EOF仍在语音 |
| 短问候RF18 | 2600 | 5088 | 6176 |
| 短问候gate19 | 3040 | EOF仍在语音 | EOF仍在语音 |
| 背景尾段 | 4000，仍在收音 | 未检出语音 | 未检出语音 |
| 数字静音 | 4000，NO_SPEECH | 未检出语音 | 未检出语音 |
| UX142改口1 | 6220 | 7872 | EOF仍在语音 |
| UX142改口2 | 3300 | EOF仍在语音 | EOF仍在语音 |
| UX142改口3 | 3240 | EOF仍在语音 | EOF仍在语音 |
| UX132改口1 | 2940 | 3904，随后再次起声 | EOF仍在语音 |
| UX132改口2 | 5880 | 3808，随后再次起声 | EOF仍在语音 |
| UX132改口3 | 3240 | 3904，随后再次起声 | 7072 |

原始PCM下，UX132三段都被分成两段；再次起声的观察时刻均4000ms，与前一结束
决定分别相隔96/192/96ms。不能把第三段的第二次结束时间6784ms当作完整第一轮
的成功收尾，因为如果照首次决定停止，后续修正仍会丢失。

第二种预处理只调用现有`agent_voice_filter`和`agent_voice_reject_cue`，没有新
系数、降噪模型或阈值调整。实际C程序在ASan/UBSan下处理11份输入，共3703个20ms
帧，平均绝对能量与冻结C3元数据逐帧完全一致；证明使用了同一滤波，而非Python
浮点近似。滤波后不再出现三段UX132的中途结束，但其中两段到8秒文件末尾仍在
语音。短问候RF18还比原始参照多等1088ms。保持完整尾音与及时结束两项未同时满足。

背景控制未检出语音是一个局部结果，不等于在已开始说话后的噪声尾部也能正确
退出。EOF结果一律未知，没有延长录音、拼接静音或挑选模型阈值来补成绩。

## 原始播放素材与采集域的区别

同一模型只跑一次当时实际使用的`prompt.wav`，SHA256为
`00b609500feb24061cfdf850bb35685a24c10c4b3953f0f74f8fa864bd6f5d49`，时长5895ms。
处理中途没有发出结束事件；末尾仍未结束，不能据此宣称收尾速度通过。

素材中三处中间连续数字零段为145、275.125、290ms，末尾零段665ms。
数字零不等于人工音素边界，不能据此排除所有低声或自然停顿；至少没有证据把
三段录音的分句简单归咎于素材内插入了超过700ms的数字静音。

使用既有三频带包络对齐门槛（相关≥0.75、与竞争峰差≥0.05、频带位置差≤30ms），
UX142三份及UX132第一份通过，偏移分别700/760/700/720ms；UX132另两份未通过，
没有降低门槛或用估计偏移填成已验证时间。该对照提示采集后的信号条件会影响
判断，不能精确归因于某个硬件噪声源，也不能证明新模型可直接部署到C3。

## 一个证据命名修正

核对`provisional-end-ux133/provider_probe.py`发现，送给ASR的测试输入是原始录音
WAV复制，保存的PCM哈希不含WAV头。UX172结果字段`filtered_input_pcm_sha256`
名称不准确，应理解为原始`retained_input_pcm_sha256`。旧结果与哈希保留，不覆盖
已冻结证据。本轮明确区分原始录音、实际C滤波输出和仅用于对齐的播放源。
当前运行时代码也将原始录音上传，滤波用于本地检测；本轮没有改变上传行为。

首次素材对照误把原始TTS文件与测试时保存的leveled prompt当成同一哈希，前置
断言在推理前拒绝。核对原试验报告后改用实际prompt文件，在独立目录完成；原
失败日志和脚本保留。没有为此改变输入音量、阈值或重录素材。

## 决定与状态

不移植此完整模型，不开始学生模型训练，也不以本轮数据宣称修复。下一项有限
验证应针对ASR增量文字：原始与现有滤波PCM是否改变修正词首次到达时刻，以及
旧端点是否能收到该提示。它与此次电脑模型分句是不同问题，仍需新的协议证据，
不能仅凭本轮滤波后“未中断”就更改设备上传链路。

本轮零云端推理、零录音、零烧录。407份生产C/H/CMake及正常/无音频二进制与203
保持一致，因此未重复不涉及代码变更的70项主机回归。只读USB确认设备仍为72，
联网、fast/capture/listening、reuse开启、prefetch关闭，DMA丢失0、COM5释放。
1297事件/1042352B上下文全部统计保持，活动区余6224B；分区、历史预算与录音槽不变。

证据：`artifacts/voice-fast/offline-vad-ux173/`中的plan/reference、两份逐块概率、
原素材对照、实际C滤波及3703帧一致性、只读设备状态和closure.json。
整体语音目标、一秒有效回复、完整输入与48KiB最低堆验收继续保持未完成。
