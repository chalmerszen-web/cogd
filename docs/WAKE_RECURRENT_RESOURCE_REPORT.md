## 实现与验证

默认关闭的 `AGENT_KWS_GRU_RESOURCE_ONLY` 将新 C11 `kws_gru32` 接入原 40 带 log-mel 前端。E/L 与验证模型的归一数组逐项一致且记录来源 hash。测试保持全部 Agent、Wi-Fi、ASR/TTS、上下文、音乐与 GPIO 代码；没有用独立小程序、降低上下文或放宽应用预算获取空堆。生成的探针固定种子 `2026100475`，权重与归一 C 源 SHA256 为 `89c72bc59ac5558a06751ca559cd10eb1b82fcff6bd01fa2ebe10d175680f964`。

设备 USB 使用原 `agent kws begin/frame/end`。本模式响应增加 `gru:1, trained:false, resource_only:true`；`trace` 明确为 188 B：40×INT16 log-mel、40×INT8 输入、32×INT16 Q15 状态、2×INT16 Q8 输出，均小端。旧 DS-TCN 格式保持原条件分支。不能把新字段当作旧网络逐层输出。错误序号和 CRC 在推理前拒绝，随后 frame0 仍与独立参考完全一致。

主机使用 ASan/UBSan 验证 512 帧前端一致、256 次 feed/step 分块一致、断钟恢复、无效参数以及极大正分数仍不触发唤醒；INT64 NumPy GRU 参考核对固定 512 帧的 16,384 个隐藏值与 1,024 个输出。主机工作区为 4808 B，设备实际为 4,800 B，不能混用两个 ABI 的大小。主机对实际推理路径包装 malloc/calloc/realloc/free，调用数为零；未把 KISS 库未调用的通用分配导出符号误作帧内分配。

首次主机测试脚本漏写 `-lm`，产生链接错误，保留 `sanitizer-initial-link-failure.log`；补齐测试链接项后，另一检查把共享库未调用的 KISS 通用入口符号当作推理分配，保留 `host-symbol-scope-failure.json`，随后改为执行路径分配计数。两项均为测量脚本错误；未改变前端、模型、输入、识别目标或设备门槛。正常固件构建仍只有一次，实机组仍只有一次。

完整应用 SHA256：`97c9e5052375d252bb3ecd3525a8bf6255e79e4290241fbe86873ffa353f3bc3`；548 个源文件的快照 SHA256：`f86e2266b941fc55f8b4a1a444f76ec8bed8058248ae2167081d3ed5e6df532f`。`build-inspection.json` 记录实际 C3 编译的最后标准为 C11及逐函数栈使用；逐函数使用不是整个任务栈的峰值。

## 证据和限制

证据目录：`artifacts/voice-fast/wake-recurrent-resource-ux476/`，包含 plan/probe、固定 PCM 与参考、host/parity/build/inspection receipts、全部 512 帧设备输出、60 秒 profile/heap/DMA 记录、安装回滚校验和 closing-state。上述命令与原始文件供本地复查；备份与产物不进入 Git。

监听堆余量不能证明完整网络对话的最低堆；恒 false 是诊断权限限制，不能算误唤醒率为零。无训练、DEV/TEST 读取、私人录音、刺激播放、模型云调用或工具执行。普通话＋粤语识别效果、每小时误醒、真人泛化和三轮业务目标都未验收。误唤醒仍未修复，完整目标不标完成。

下一步仅在这些门槛通过后，另行冻结一次小规模本地 GRU 训练试验；先检查新的序列表示是否能区分完整唤醒与近似词，再决定扩大训练。已有失败记录保持，不能靠阈值调高或重用同源回放声冒充改进。
