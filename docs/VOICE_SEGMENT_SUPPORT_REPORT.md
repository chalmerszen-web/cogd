# UX172：提前备答所需的完整输入检查

2026-09-29。现有代码可依据ASR中间结果异步准备一个回复，将音频留在静默缓存，
再由最终输入决定采用或丢弃。此次只检查结束检测能否保住后半句改口；没有新增
推测请求、云调用或实机录音。**两个候选均未通过部署条件，未构建或烧录209应用。**

## 方法与边界

使用UX133保存的94条真实ASR事件（32/35/27），与UX132三段各8秒录音的C3逐帧
元数据配对。实际C解析器与端点在主机运行；按事件到达时已上传的样本数映射到
下一个20ms边界。它能检查同一输入与协议下的规则差别，不能冒充C3调度或实际
说完后的声学延迟。重放不使用当时服务端输入额外附加的700ms数字静音。

当前活动只取经过身份和顺序校验的最新OPEN声段有意义文字；新空段、短修订、
speech_stopped、final或错误撤销活动。旧段最终文字不能当作当前段仍在说话。
活动不再借用pending等待，也不改变起声、能量阈值、700ms静音、1000ms累计
等待额度或10秒录音上限。

第一版允许活动声段支持当前两个强帧，越过原320ms严格续说窗口。第二版增加
同一活动条件下四个当前弱帧支持。两版都只作用于已接纳的语音，不以文字独立
起声或延长收音。生产者fast采样上界同时改为两票宽松能量事件，防止消费者
仍在收音时被旧四票上界提前截止；classic不变。

## 配对结果

| 输入 | 基线结束 ms | 两强帧版 ms | 增加四弱帧版 ms |
|---|---:|---:|---:|
| 改口1 | 2940 | 2940 | 3720 |
| 改口2 | 5880 | 7700 | 7760 |
| 改口3 | 3240 | 3240 | 6760 |

固定本地SenseVoice分别核对每段完整8秒、基线裁剪与候选裁剪。两强帧版没有
修复首尾截断，中段增加1820ms但没有增加转写内容，因此停止进入硬件。

四弱帧版的第三段保住了完整“不要蓝色，改成绿色”；第一段只多保住“不对”，
仍缺最后颜色要求；中段增加1880ms，但基线已经包含同样改口。完整第一段的
本地识别为“改成黑色”，第二段有“红水”误识别，全部原文保留；本地ASR也会
出错，不能把这些结果写成真人理解或最终工具执行通过。

另外五段固定控制使用实际本地元数据，在原TEXT出现时人为保留OPEN活动位，
检查活动滞留的风险。**这是保守协议压力测试，不是声称服务端实际发出了这些
活动事件。** 结果如下：

| 控制输入 | 基线结束/EOF ms | 四弱帧版 ms | 差值 ms |
|---|---:|---:|---:|
| 旧完整改口 | 6680 | 6680 | 0 |
| 短问候RF18 | 2600 | 3060 | +460 |
| 短问候gate19 | 3040 | 3060 | +20 |
| 背景尾段 | 4000 | 4000 | 均到文件末尾仍未结束 |
| 数字静音 | 4000 | 4000 | 均NO_SPEECH |

背景文件末尾状态未知，不能算抑噪通过。短问候多等460ms，且首段改口仍截断，
触发原先约定的硬件前退出条件。本轮不继续扫描门槛或延时，不追加实机三轮。

## 对提前备答的结论

关键词可以提前选择连接、路由与候选内容；仅关键词相同不足以放行回复，例如
“蓝色”与“不要蓝色”。提前下载的接话语音不等于有效回答，动作也不能提前执行。
已有证据说明部分候选确实能在VAD结束前准备好，当前主要缺口仍包含完整输入与
候选可用性的衔接。这次声段辅助规则没有同时解决漏尾句和多等待，不能发布。
