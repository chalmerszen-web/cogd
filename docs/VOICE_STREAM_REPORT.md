# 千问实时语音实测：0.9.0-qwen-stream

2026-09-22，同一台 ESP-HI / ESP32-C3 / 4 MiB Flash。已在原 Agent 上接入
Fun-ASR-Realtime 与 Qwen-Audio-3.0-TTS-Flash，使用用户指定的本机
qianwen-model-suite Key，音色 longanhuan_v3.6。DeepSeek、分区与 200 KiB 历史预算保留。

## 响应结果

六组相同合成语音经过电脑扬声器→板载麦克风→设备云端调用→板载扬声器。
普通话/粤语唤醒各三组，后续指令以普通话为主。输入 SHA256、扬声器增益、
外部麦克风和设备音量 80 与 0.8.1 对照一致。

| 测量 | 0.8.1 文件语音 | 0.9.0 实时语音 |
|---|---:|---:|
| 输入播放结束→首 PCM，中位数 | 19.031 s | **9.7345 s** |
| 同指标范围 | 14.218–40.843 s | **7.750–13.688 s** |
| 同指标均值 | 24.3225 s | 10.1095 s |
| 输入结束→扬声器提交首数据，中位数 | 未按相同口径记录 | 9.910 s |

匹配样本的中位等待下降 **48.8%**。这是固定六个样本在不同时刻的观测，
云端负载、网络和累计历史没有随机交错控制，不能把全部差异归因于代码或当作 SLA。
基线仍完整保存在 artifacts/voice-speed/conversations-03、04。

新增的连接准备发生在开始提示音之前：从检测到唤醒到开始采集为
**1.751–1.850 s，中位 1.789 s**；旧版对应通常约 0.6 s。该额外等待明确保留，
不能只看说完后的指标。使用时应听到开始提示音再说话。

首 PCM 指固件拿到第一块可播放音频，扬声器时间指开始向 DMA 提交该数据。
两者之间还有预填充，音频本身也可能有前导静音，均不等于逐采样测得的可听见人声
起点。输入结束与设备时钟通过即时 USB 事件对齐，含串口接收/轮询误差。
回溯发送的 speaker_start 只使用其板上时间，不拿收到它的电脑时间做锚点。

## 时间花在哪里

以下是最终六轮**均值**的组成，合计 10.293 s（到扬声器首数据），可相加。
它与上表中位数采用不同统计口径。

| 阶段 | 均值 | 占比 | 当前原因与测量边界 |
|---|---:|---:|---|
| 输入结束→采集结束 | 3.064 s | 29.8% | 本地人声确认、静音判定、采集/Flash/网络调度；这里是合计，未隔离各因素 |
| 采集结束→最终识别交给 Agent | 1.181 s | 11.5% | 校验/结束提示音、剩余 PCM 发送、等待最终 ASR 事件与关闭连接 |
| DeepSeek 与工具 | 4.294 s | 41.7% | 历史/工具定义发送、模型首响应、工具续轮和最终文本生成，未分离云排队与推理 |
| TTS 建立连接 | 1.094 s | 10.6% | DNS/TCP/TLS/WebSocket 的合计；不能直接认定为纯 TLS 计算时间 |
| TTS 任务启动、提交文字到首 PCM | 0.474 s | 4.6% | 启动约 69 ms，其余约 405 ms，包括网络和服务端生成 |
| 播放器预填充→首数据提交 | 0.184 s | 1.8% | 小扬声器输出初始化、静音预热与有界队列 |
| Agent/服务间移交 | 0.004 s | <0.1% | 状态与资源所有权切换 |

识别连接准备已在开始提示音前完成。六轮首次 PCM 上传比采集结束早
**3.29–7.56 s**，证明实际录音期间在上传。首次 TTS PCM 比服务端 task-finished
早 **1.12–14.75 s**，证明实际在完整合成结束前播放。

剩余主要瓶颈是 DeepSeek/工具往返及采集结束等待。下一步应先分别测量
DeepSeek 请求发送、首响应与工具续轮，再评估按需选择历史和合并必要工具回查；
保留现有持久化容量。VAD 与实时上传共用单核 C3，后续应单独剖析采集结束等待。
当前网络/音频数据尚不足以把模拟麦克风噪声与 CPU 调度的贡献定量分开。

当前 TTS 协议支持输入文字流和输出 PCM 流，但 Agent 等 DeepSeek 工具轮次完成
后才提交最终回答，`llm_to_tts_overlap=false`。这样保持单条活 TLS 与消息缓冲所有权。
本版没有播放时打断、回声消除或连续全双工；仍按“唤醒—指令—回答—再次监听”工作。

## 实现与失败处理

- C11 专用 duplex 状态机及 ESP-IDF WSS 适配，固定官方域名，验证证书和主机名。
  独立 NVS 保存千问配置，原 Vocalign、DeepSeek 和 Wi-Fi 凭据保留。
- 16 kHz PCM 以 64 ms 块发送。VAD 与 ASR 借用互不重叠的工作区；独立 Flash
  解码游标只读已经发布的不可变记录。最终录音校验通过后才执行 Agent。
- 识别连接就绪后再发开始提示音。现有人声确认仍必须通过；另外允许非空的
  ASR 最终句子结束已确认的录音，采用 1000 ms 静音断句，关闭语义断句。
  该补充路径用于避免本地结束判定拖长，未绕过 CRC、取消或长度限制。
- 单网络 worker 双向收发。发送缓冲满且一字节都尚未发送时返回 BUSY，继续读取
  服务端事件，再尝试发送该帧；已部分发送或结果不确定的帧只报错，不自动重放。
- 24 kHz PCM16 TTS 直接进入 12 KiB 有界队列，处理奇数分块并保持背压。
  文本 1800 UTF-8 字节、录音 10 秒、播放 90 秒等原有边界保留。
- USB 控制优先于网络/VAD；上传低于本地确认，冷握手临时与其同级。
  VAD 栈从 6144 降至 4096 B，依据实测水位，最终剩余至少 2208 B。
- 同一域名的已关闭 TLS 票据缓存最多 60 秒，修改凭据清除。没有同时保留两条
  活 TLS，也没有自动重连重播模型任务；未单独证明本平台票据恢复的延迟收益。

保留了失败诊断：01 的测试指令受低优先级 USB 延迟；02 录音达到 10 秒；
03/04 能完成但上传常在录音后；05/06 暴露实时发送阻塞。04 六轮的中位数虽为
9.688 s，也没有冒充流式验收结果。最终 07 在收取下行事件的发送背压修复后，
按同一六条顺序完整通过。初期 PC 客户端的中断会话也保留，原因未被确定。

## 验证与资源

- 最终固件六轮全部完成，蓝/绿灯控制、颜色与名字记忆、回答和恢复监听通过。
  外部麦克风的回复段用本地 SenseVoice 核对，未检出满幅采样；这是合成源验证，
  不是新的真人唤醒率、粤语整句识别率或主观音质验收。
- 29 项 C11/ASan/UBSan 测试通过；覆盖事件/UTF-8 分片、重复最终句、错误任务 ID、
  奇数 PCM、超限、取消、双向背压和不能凭未确认文本完成录音。6 项 USB 测试通过。
  ESP32-C3 音频版和关闭音频版均构建成功，91 个固定依赖文件校验通过。
- 实机 ASR 传输取消通过。空闲/采集/播放取消后恢复监听分别 609/1438/1125 ms，
  采集与播放的 USB 确认分别 203/204 ms；恢复时间包含模型重载和测试轮询。
  显式关闭后保持关闭，取消中的录音没有生成历史对话。
- 最低空闲堆 **47,480 B（46.37 KiB）**，worker 最小剩余栈 **2572 B**，
  VAD 最小剩余栈 **2208 B**；六轮无复位、PCM 欠载或 ADC DMA 丢失。
  **没有达到历史 48 KiB 最低堆目标**，差 1672 B。没有降低上下文容量来补数字，
  也不把有限通过扩写为长期压力验收。
- TTS 与麦克风音量检测并发 8.215 s，通过本地外部录音转写核对，无 PCM 欠载、
  ADC DMA 丢失或满幅采样。普通 USB 流式/非流式 DeepSeek 两条路径通过。
- 闲置观测 125 秒：空闲堆从 99176 B 恢复到 100168 B；约 61 秒回收 624 B，
  约 122 秒再回收 368 B，符合短时 TLS 票据和连接收尾状态的有界回收。
  恢复监听后空闲堆 73448 B。本轮未见闲置期间持续下降，但不替代长期泄漏检查。
- 硬复位后语音开关与千问配置恢复；关闭 COM5 的整轮声学对话通过，设备独立
  唤醒、改蓝灯、播报并回到监听。之后查询为 1 次成功、0 次失败、0 次欠载，
  固件 0.9.0、Wi-Fi 在线。外部录音从电脑指令结束 1 秒后截取，核对了设备回复。
  交付时语音开启、COM5 已释放，电脑无需充当语音中转。
