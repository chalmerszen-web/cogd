# UX86：改口后的候选语音复用

2026-09-27。**118已在设备上实现改口后复用通用准备语，三轮均完成；完整提速
验收仍未通过。设备已恢复72监听，118源码和固件单独保留，正式安装包未变。**

候选请求“请准备调整灯光，具体颜色稍后确定”不包含RGB参数。原实现收到
“不对”或新的ASR句子编号便取消候选，导致原本仍然适用的准备语被丢弃，
只能静默等待DeepSeek规划和最终TTS。116的三轮颜色修正均出现此路径。

新实现保留这类候选，等完整录音和最终转写校验后再决定是否播放。只有完整的
灯光设置语句（包括已说完的颜色修正）能通过；候选语音仍只允许表达准备，
不能含颜色、数值或完成声明。最终硬件动作仍由DeepSeek根据完整输入执行。
取消或改成其他已识别任务会不可逆地丢弃候选。未完成修正、语言变化、未知
后缀、多动作和问题句也不能借此播放。SELF和REMEMBER的修订规则保持原样。

117第一组仅1/3完整收音。前两轮止于“请把灯调成蓝色。不对。\n”，设备询问
需要什么颜色，只有状态查询，没有设置蓝色。第三轮正确执行绿色，但候选仍
被拒绝：严格灯控语法把ASR附带的句尾换行误判成额外指令。该失败已保留。

118修复句尾空白兼容，不放宽实际后缀；候选回落遇到未完成修正时，显式进入
现有工具禁用的澄清阶段。原生准备语结束后增加`progress_end`事件，供声学分段。
未修改VAD阈值。原计划第二组SELF改为修正后的三轮灯控，合计六轮，没有继续重跑。

随后DeepSeek按照完整改口执行绿色并给出最终语音。电脑麦克风实录的本地ASR
识别出了三段准备语和三段绿色结果答复；这证明有相应语音内容，不等同主观听感。

两组外录均未通过既定的重复声源对齐门槛。原始分析保留`unknown`，没有放宽
门槛、挑选一轮或用提示音计算一秒达标。另存的事件范围裁剪仅用于内容诊断，
没有发布起声延迟。咻音排除同时覆盖直接回答和候选准备语，源对齐失败或咻音
无法分离时不发布准备语延迟。
