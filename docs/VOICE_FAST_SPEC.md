# 千问快速语音与 DeepSeek 分流

2026-09-22，用户授权自主烧录、扬声器回放、麦克风采集，不再等待真人测试。
在既有双语唤醒与流式语音目标上，增加说完后 1 秒内开始回复的目标。

- FF-01：以用户声音结束到设备扬声器首个有用回答的声学间隔为目标，
  不把提示音、占位回应或首个 SSE/PCM 数据包当作已达到 1 秒。
  记录每条样本和失败；网络波动、冷连接与连续会话分别记录，不能只报最优值。
- FF-02：普通对话优先千问快速路径；复杂推理、多步规划和不支持的任务
  交 DeepSeek。工具结果决定动作成功播报，音频参数/JSON 通过校验后执行。
  先核实当前账号和接口，比较短上下文文字路径与实时语音路径，禁止假设
  单纯模型首 token 小于 1 秒就等同于设备端达到目标。
- FF-03：评估并消除 ASR、LLM、TTS 串行握手；先连接/上传，再处理后续
  返回。保持 TLS 验证，取消和失败后不盲目重播有副作用的请求。
- FF-04：VAD 必须与 1 秒预算一致；旧 800 ms 静音加 160 ms 观察没有
  留出足够回答时间。缩短门限需实测短词、句中停顿和误截断，记录取舍。
- FF-05：保留普通话/粤语唤醒、DeepSeek、GPIO、音乐和现有 2 MiB
  上下文分区/200 KiB 历史预算。快速路由可选取较短工作上下文，但不删除
  本地历史；复杂请求仍能调用既有完整上下文和工具链。
- FF-06：仅更新应用；烧录前备份并验证，保留 0.9.0 和已装 0.10.0 回滚。
  C3 的 Flash、峰值堆、任务栈与播放连续性随版本记录，不以桌面结果替代。

先做有界账号/协议探测和旧/新唤醒模型同板回放，再按测得瓶颈实施。
资料、脚本和失败结果保存在 artifacts/voice-fast；凭据/录音不提交 Git。
未达 1 秒的样本如实保留。没有设备声学证据前不标记完成。

## 连续对话与进度确认（2026-09-22）

- FF-07：每组实机对话至少连续三轮；整个组保持 voice on。除首轮外，
  下一次唤醒从上一轮终止事件后约 250 ms 开始，不等待 fast_ready，
  不以额外静置掩盖重新加载模型或网络预连接造成的监听中断。
  保留每轮前三次唤醒尝试、实际播放时刻、状态、失败和外部录音。
- FF-08：复杂请求在完整 ASR 和无副作用的明确转交后，可播放缓存进度确认，
  同时启动 DeepSeek。确认不得持久化为最终回答，不计入有用答案延迟。
  执行硬件工具、开始最终 TTS、取消和错误退出都必须释放确认音频的所有权。
- FF-09：默认将快速连接建立放在已命中唤醒的录音期间；保持既有锁及
  TLS 校验，不因后台预连接关闭监听。idle 预连接只作为临时对照配置。
- FF-10：PDM/PA 采集对照保留单一可回读开关，默认维持原行为。
  新增连续唤醒故障优先；尚未执行该开关的声学对照，不得声称降噪有效。
- FF-11（2026-09-23 用户补充）：慢任务由快模型生成简短、贴合本轮问题的
  复述和自然语气词，再衔接高智能模型的最终答案。普通快答不机械加确认。
  0.11.6 的固定缓存短句只验证并发与资源所有权，是过渡实现，不能据此
  标记本项完成。确认不得宣称尚未执行的动作已经成功；取消后不得续播。
- FF-12（2026-09-25 协议实测）：快模型可先返回确认文本/PCM，再以新的
  response ID 返回原生 function_call。在未播放PCM且未执行工具时，允许
  一次转为工具响应；新响应的首个输出项必须是函数。完整ASR可能稍后到达，
  在本轮ASR验收之前不得播放、转交或执行工具。
  旧ID、第二次切换、伪造文本调用、参数错误及混合副作用均不得放行。
  未满足下述原生确认条件时，工具前导PCM不外放，最多消费6秒。
  固定备用确认与模型生成确认须有不同事件记录，失败不能算动态确认成功。
- FF-13（2026-09-25 原生确认，0.11.14更新）：完整ASR、唯一具名原生delegate
  输出项和有界确认转写到齐后，可以直接流式播放模型的简短确认PCM，免去再次TTS。
  0.11.13实测工具参数可能晚于PCM，因此过渡语音不再等待ack JSON收齐。正式转交
  必须等待全部参数通过schema和最终调用一致性校验；非法参数导致终止，不能执行工具。
  原生确认转写的前后空格/换行不代表可听内容，只在独立的已说文本副本中去除，
  不修改流式累积原文或工具参数。内部控制符、标记和超长内容仍不放行。
  这里只允许过渡语音，不能提前执行GPIO等工具；仍须核对arguments.done和最终
  response.done的一致性。其后出现参数变更、混合工具、取消或断流必须终止，
  已播放部分不重试、不回退重播。此前已经丢弃非零PCM时不得播放截断后的后缀。
  原生确认最长6秒，转写最多24字符/96字节。最终回答接续实际播放的转写，
  不把工具参数中可能不同的复述当作已经说过的话。确认须完整结束并释放借用内存
  才能进入当前DeepSeek引擎；此步骤只去除重复合成，尚不证明原生确认与DeepSeek并发。
- FF-14（阶段诊断）：语音事件同时记录当前堆、启动以来最低堆、最大连续块和
  实际堆采样时刻，不能将延后输出的DMA时间戳当作堆采样时刻。原生确认失败后
  的音频仍归为确认，不能计作正式回答。记录首次原生确认回退原因、消费与丢弃
  样本数，以及实际上传PCM的峰值、平均绝对幅度和零样本数；不输出凭据。
  诊断版本维持VAD/唤醒阈值、历史容量和既有连续三轮测试规则。
- FF-15（端点与转写失败）：独立的input_audio_transcription.failed必须立即
  终止本轮并保留错误分类，不得继续等最终转写或让回调覆盖原始错误。只记录
  有界状态、类型、原因和错误码，不输出message/param等可能含私密内容的字段。
  0.11.16实验将semantic_vad替换为server_vad，仍为threshold 0.1、静音800ms，
  其余采集/上传/历史/唤醒参数不变。至少三轮不中断监听的设备对照，以完整输入
  和真实起声共同判断；改善未获证据前不得宣传修复或提升正式安装包。
- FF-16（0.11.17本地收尾实验）：快路径仍边采集边连接并上传，关闭云端自动
  断句，使用已有生产者的20ms频谱/滤波能量记录判定本地结束。噪声基线在唤醒
  前冻结，7/8帧起声、800ms静音、4秒无语音和10秒上限按样本计时。该路径的
  confirmed只表示本地频谱/能量起声，不能宣称TEN神经确认；经典路径不改。
  全部录音（含最后不足一块的压缩页）发布、采集任务退出且CRC提交成功后，
  才发送一次input_audio_buffer.commit和response.create。取消、无语音、限时、
  存储或网络失败均不能触发回答；服务端返回自动断句配置必须拒绝。
  不增大常驻缓冲、不缩减历史。先验证完整句及三轮连续唤醒，再评估声学速度；
  当前800ms为可靠性起点，不作为稳定一秒回复完成证据。
- FF-17（0.11.18采集功率实验）：快路径录音期间，在已连接AP且RSSI不低于
  -55dBm时，临时将Wi-Fi发射功率上限降至2dBm；原设定已经更低则保持。
  弱信号保持原功率。原始设定保存在网络工作任务内，采集退出后恢复并回读，
  正常回复、工具执行及监听不沿用临时功率；不写入NVS。
  取消、连接失败和设置失败同样尝试恢复；恢复失败须保留原值以便重试，
  不能静默开始下一轮并把2dBm当作原值。仅用于当前采集噪声对照，RSSI门槛
  不代表已证明弱信号上行性能。至少三轮连续对话核对每轮设置与恢复事件。
- FF-18（0.11.19快路径能量保护）：0.11.18尾部实录中，冻结噪声159而滤波后
  噪声常在250–300，超过起声后降低到约240的保护线，造成延迟收尾。
  快路径起声后保持起声时的2倍冻结噪声门槛（最低240），继续要求频谱和
  去音调后能量同时满足；经典神经确认路径的滞回不变。保留800ms结束静音
  及600ms句中停顿检查，不改原始录音、上传PCM、唤醒模型或历史容量。
  用三轮快答及三轮历史查询验证输入完整、连续唤醒及实际起声，不以主机
  帧测试代替实机效果。新增capture_joined资源事件区分采集与功率恢复区间。
- FF-19（0.11.20网络缓冲对照）：ESP-IDF6.1本地Kconfig说明动态TX缓冲按
  实际发包申请并在发送后释放，当前默认上限32。仅将其上限改为8，保持TCP
  窗口、TLS缓冲、采样、VAD、历史预算和任务栈不变；不把配置上限直接换算成
  已节省RAM。构建后核对生效值，运行三轮快答及三轮历史查询，比较完整输入、
  发送阻塞/错误、首声、最低堆及DMA丢失；若退化则恢复冻结的0.11.19。
