# UX100：网络任务分支栈与提前备答复测

2026-09-28。本轮在已有提前备答实现上，减少网络任务常驻栈预留2048B，
没有缩小上下文、录音或回复缓冲。减栈版132的串口检查通过，但三轮弱音
改口只有一轮完整，另两轮提前停录；观察堆低点44912B，仍低于48KiB。
源码和构建保留132实验版，设备已恢复0.11.72-summary监听，整体目标未完成。

## 改动与测量顺序

原网络任务把命令输出数组、实时ASR会话和闲时预热的局部对象合并进常驻
栈帧。对 `context_command`、`voice_live_asr`、`voice_fast_idle` 增加
禁止内联边界，将乐谱上传放进独立 `upload_song_job`；普通文字对话直接
进入engine，不经过携带命令输出数组的包装函数。命令解析、错误处理、
取消、加锁、工具与上传缓冲清理顺序保留，未新增堆分配。

LTO后正常版网络入口帧2608→144B，诊断版为256B；命令2208B、上传1040B、
ASR1056B、闲时预热32B、voice_run928B、TTS416B。入口帧不是完整调用链
用量，不能据此直接减任务栈。

131首先保留11264B网络栈，测得串口和三轮语音的最低剩余3900B。
随后独立构建132，将预留降为9216B，预测剩余1852B；复测实测1852B，
超过本阶段1536B检查线。TTS仍预留7168B，132三轮剩余2296/2240/2208B。
覆盖有限，不构成所有工具、网络异常和递归库调用的穷尽证明。

为保持既定Flash上限，仅合并重复USB帮助文字，LLM提示词未改。
131编译中间版本和过预算失败均保留；最初 `candidate-0.11.131` 是未烧录
的过预算产物，不能用作安装包。实际烧录的131-heap使用稍长的旧帮助文字，
此差别已记录；132正常/诊断归档源码一致，只有构建选项不同。

每版只跑一组三轮，gain0.25，idle预连接、prefetch ON、reuse OFF。

“请把灯调成蓝色，不对，不要蓝色，改成绿色。”

## 对“说完之前先准备回复”的验证

131三轮准备语PCM比ASR最终结果提前3608/3228/3956ms到达；132成功轮提前
3263ms。准备语为不指定颜色的“嗯，我来调整一下灯光。”，完整指令核对后
再播放，实际工具仍由最终输入授权。132截断的两轮候选没有被播放，转为追问。

设备日志中，VAD结束事件到准备语送往扬声器，131为389/392/402ms，132成功轮
507ms；最终回答分别为5746/7595/6298ms和7469ms。VAD事件包含本地结束之后的
上传收尾，且没有本轮声学起声验收，因此这些数字不等于用户真实说完后的延迟，
也不构成稳定一秒达标。提前准备已发生，可靠完整收音和最终接话仍是未解决项。
