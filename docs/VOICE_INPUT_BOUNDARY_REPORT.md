# UX146：提前备答的输入边界验证

2026-09-29。完成一次有限的问法覆盖实验，**未通过，已撤回186，恢复185源码和72设备固件**。
只测试一组三轮，没有为提高成绩重跑。稳定一秒有效回答、完整输入和48KiB最低堆门槛均未通过。

用户提出的提前推测，在现有实验源码中已对应临时转写、候选意图、异步生成、音频缓存、
最终输入校验和撤销。准备候选不获得播放、GPIO执行或历史提交权限。这次验证的是它的前提：
不能为了先回复而丢掉用户后半句，也不能把准备语的起声算作正式答案。

## 原始材料与假设

固定本地合成素材“现在灯是什么颜色？请简单回答。”长4825ms。本地SenseVoice能识别两句；
UX144和145末轮设备录音分别2488/3288ms，同一识别器均只识别第一句。
按20ms帧计算，源素材1920–2800ms有880ms低于−60dBFS的间隔。这个阈值仅供离线诊断，
没有写入固件，也不作为人声标注或跨录音精确对齐。它比当前700ms基本静音结束时间长。

现有句间提示只覆盖“为什么、如何、點解”等，漏了“什么、咩”。186仅增加普通话、繁体和
粤语what类词汇，保留已知短自我介绍例外。沿用整轮共享的400ms句间额度、1000ms待续额度、
700ms基本结束、10秒上限、严格起音票数和源音频覆盖边界；没有扩大等待额度或降低能量门槛。
这会让相关单句最多多等400ms，事前已记录该代价。它不是语义结束模型。
