# 0.6.3-context：满盘对话恢复

2026-09-20，COM5，ESP-HI/ESP32-C3。已仅更新应用并完成实际 DeepSeek 对话验证，设备可交还用户测试。

## 原因与处理

Wi-Fi、Key 和系统时间均正常。LOCAL 上下文活动区已用1,048,452/1,048,576字节，仅剩124B；1611个事件含440轮完整对话，其中还有601条历史记忆写入。因为所有未同步记录均受保护，普通压缩无法回收；新用户消息持久化失败后返回 `full`，并未发出云端请求。

先读取完整4MiB Flash并校验，随后将原始2MiB上下文及全部1611事件导出至 `context-archives/2026-09-20-full/`。校验CRC、代数、记录序号和SHA后，通过新增的USB LOCAL归档入口提交导出边界2049。归档保留最近128个完整轮次、已有记忆/tombstone、摘要及其原始来源轮次；源轮次位于最近窗口之外，所以原历史共有129轮逐字节留在设备。原始全部历史同时保留在电脑。未改云端ACK、分区和128KiB历史请求预算。

归档后活动区空闲871,876B；两批实际对话结束后仍空闲 **855,288B（约835KiB）**。归档水位与新快照采用原双区提交协议，不需要向满盘旧区再写一条ACK。没有自动丢弃未导出的记录，也没有把本地备份当成云同步。

首次流式问候虽然成功完成，却误称旧音乐/时钟正在运行；直接读取实机证明音频停止、显示关闭，作为语义失败保留。补充提示词约束：问候不主动报告硬件状态；报告当前运行状态前须在本轮查询。最终问候没有再作该错误声明，实际状态查询使用了音频/显示工具，并正确报告两者关闭。该有限检查不保证模型所有未来回答都准确。
