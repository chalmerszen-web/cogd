# 小言：20条有限诊断结果

本轮已完成20个固定来源录音的检查，没有新增训练、改变阈值、改写原成绩或烧录。
**优先问题是词结束标注偏晚；另有部分词/近似词区分问题。不能简单把原来所有
“提前触发”解释为模型没听完，也不能据此宣称双语模型已通过。**

## 证据与范围

样本在信号检查前固定：两个粤语声音各6条不同提前量失败、1条粤语无触发、
2条普通话提前失败、2条粤语成功对照和全部3条误触发负样本，共20个录音来源。
不是随机抽样，不能由这20条推算全体的新通过率；原测试已经揭盲。

脚本：`tools/kws/boundary_diagnosis.py`。本机产物在
`artifacts/kws-boundary-diagnosis/`：selection.json、analysis.json、summary.csv、
score-diagnostics.json、20张包络/频谱/原始分数图及本地音频对照网页index.html。
完整片段和截至触发时刻片段是同一来源的派生音频，不增加独立样本数。

信号检查使用10ms RMS帧，并同时计算相对峰值低20/30/40dB三个固定门槛的最后
活跃时刻。它们只是能量证据，不是人工确认的音素边界。SenseVoice完整/前缀转写
与此前筛选共享模型，不能当成独立真人听审。本轮没有声称直接听过这些声音。

## 1. 粤语提前计分存在明确的标注问题

12条粤语提前样本均满足：
- 触发发生在上述三个能量门槛的最后活跃时刻之后。
- 以最保守的低40dB门槛计，触发晚于活跃末端10–175.94ms，中位数103.44ms。
- 原标注结束比该活跃末端晚40–335ms，中位数177.44ms。
- 触发后剩余能量最大仅为整段能量的0.001025%。
- 触发前音频与完整音频均被本地ASR识别为完整“你好小贤/小然”等既有粤语同音形式。

代表样本01（af_heart-1-010）：原结束1685ms，触发1461ms，被原计分判为提前224ms；
低40dB末端1350ms，触发反而在其后111ms。频谱也显示主要谐波已结束，后面主要
是低能量尾部。这反驳了“提前224ms本身证明没有听完末音”的推断。

代码原因可直接定位：`training/tts/curate.py`在末字与承接句之间寻找能量最低点，
然后把整个裁切长度写为`wake_end_sample`。`training/kws/data.py`又以该长度确定
训练标签和评价时间原点。裁切范围需要保留余量，但这个范围的末端不等于末音结束。
最低点可落在一段近似静音的不同位置，导致标签包含可变长度的静音尾巴。

本轮只证明选中的12条具有该现象；没有把剩余27条粤语提前事件自动改判为成功，
也没有输出放宽时间窗后的“新准确率”。原72.79%和失败关卡文件保持不变。

两条普通话提前样本也能在触发前转写出完整词，但低30/40dB门槛后仍有弱能量尾部，
剩余能量分别0.0580%和0.0140%。它们可能包含低能量末音或合成噪声，不能用本次
能量检查确定准确音素结束时间。

## 2. 近似词与部分词高分是独立问题

| 原文本 | 完整/截至触发的自动识别 | 保存分数中的现象 |
|---|---|---|
| 你好小杨 | 你好小杨…… / 你好小杨 | 2.048s触发，峰值Q8分数960，门槛425 |
| 小言 | 小贤…… / 小然 | 2.048s触发，峰值938，缺少“你好”仍得到高分 |
| 你好小智 | 你好小子…… / 你好小子 | 2.304s触发，第70和72块超门槛，中间一块未超 |

第三条实际合成后的ASR文字与请求“小智”不同，不能宣称这是正确“小智”发音的
专门验收。自动识别仍支持它不是目标短语，但音素真实性未人工确认。

前两条恰在64块/2.048s预热结束时触发，且预热中已有高分；这不是仅有一个
过期投票造成的现象：第64、65块也连续高于阈值。因此只在预热边界清除投票，
不能消除这些高分区间。第三条是既有“最近三块中两块超阈值”规则正常触发，
没有发现主机模拟与C检测器的规则差异。不能仅凭这三个例子改为连续投票后宣称通过。

给触发器加固定延时或等静音，也不能区分已经说完的“小言”和完整目标词。
需要改善模型对完整四音节的区分，并对训练数据中的近似词、部分词做平衡抽样。
现有训练已包含这类文本，问题不是简单“忘了放负样本”；后续应核查它们的采样
比例、发音质量、位置、尾部承接句与正样本是否匹配，而不是只追加数量。

## 3. 一个未触发样本及成功对照

粤语af_heart-1-105完整转写符合既有目标规则，但设备对应32ms采样块最高分406，
低于冻结阈值425，没有任何可投票的超阈值块。这是冻结检测规则下确实未触发，
不能靠改结束标注解决。图中的16ms中间帧不是设备每32ms实际判断的全部候选点。

两条成功对照均在原标注结束后正常触发，说明同一网络与检测器能完成流程。
它们与失败样本的尾部静音长度不同，进一步提示应分离裁切与音素时间标注。
没有因单个未触发样本而降低全局阈值，避免扩大已经观察到的近似词高分问题。

## 修正方案及下一轮最小范围（尚未执行）

1. **先修数据契约。** 分离`crop_start/end`与`target_start/end`，后者允许一个明确
   的边界不确定区间。保存完整录音作为上下文，不再用裁切文件长度当词尾。
   先在这20条开发材料上验证边界算法和导出一致性；新规则必须在新测试评分前冻结。
2. **再修训练构造。** 训练标签以可信的目标结束为原点；不确定边界帧可屏蔽损失，
   不能因任意静音尾长惩罚已经完成的词。正负样本使用一致的起始位置和背景/承接句
   分布；明确平衡完整词、缺“你好”、缺末字、近似词和自然负样本。保持现有C前端、
   网络宽度、量化方式和内存预算，先不增加设备端复杂度。
3. **只申请一轮新训练。** 数据/标注先通过一致性检查，再进行一次固定预算训练。
   阈值仍只用验证集选择；本次所有20条和原保留测试都属于开发证据。新的验收必须
   使用事先隔离的来源，分别记录完整词命中和部分词/近似词误触发，不能复用这批材料
   当盲测。若独立材料或标注质量不足，停在数据关卡，不扩大到多日循环。
4. **通过后才恢复实机验收。** 最终权重数值对齐、资源/业务回归和有限声学检查仍
   必须完成；本轮不替代这些证据。纯合成来源仍不能证明真人普通话/粤语泛化。

具体判断：应优先修正**标注及训练样本构造**；现有证据不支持先改GPIO、扩大
网络、增加固定延时或放宽原标准。触发逻辑仅作为之后固定验证集上的候选变量，
本轮未改动。若要实施上述方案，需确认新的单次训练范围。

20条均有逐条证据；原Phase2归档27项文件的SHA256在前后核对相同。分析脚本
执行版本另存analysis-script-used.py，图表展示修正只增大时间轴余量，不重新
识别或计算模型。模型、阈值、原成绩、训练源与设备固件没有修改。
