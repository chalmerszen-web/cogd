# 提前生成与完整转写：UX52 协议诊断

2026-09-27。本轮在电脑端复现了缺少最终转写的现象：同一连接三次发送完整
介绍录音，三次都收到提交确认和生成的回复，却在提交后等待 8 秒仍没有收到
`conversation.item.input_audio_transcription.completed`。这不是实机提速验收，
没有烧录、播放、录音或执行工具。设备保留此前已验证的 72、预取关闭。

## 固定条件

沿用 `qwen3.5-omni-flash-realtime`、Tina、16 kHz PCM、手动收尾、无工具和搜索；
从当前 `voice_fast.c` 读取实际预测提示词，没有额外输出 token 上限。
服务端配置回显的内部转写模型为 `qwen3-asr-flash-realtime`。

只开一个连接，连续三次使用已有的“请用一句话介绍你自己”合成素材。
每次原文件 29440 样本，加 400 ms 前导、700 ms 尾部静音，共 47040 样本。
按真实时间每块 464 样本上传，最后 176 样本完整保留；在第 37120 样本后请求
一次回复，全部上传后才提交。无重连、生成重试、新 TTS、麦克风或扬声器。

预检查不读取密钥、不联网；保存实际执行脚本和配置、素材及源码哈希。
每轮最多 35 秒，整连接循环上限 120 秒；实际含关闭为 34.36 秒。
仅在已收到提交确认且回复正常完成、但 8 秒仍无最终转写的诊断条件下，
主机才记录失败并清空缓冲继续下一轮。这个观察行为没有加入设备。

## 三轮原始结果

| 轮次 | 请求到首 PCM | 首 PCM 早于完整提交 | 提交确认耗时 | 最终转写，等待 8 秒 | 完整输入验收 |
| --- | ---: | ---: | ---: | --- | --- |
| 1 | 422 ms | 218 ms | 79 ms | 无 | 失败 |
| 2 | 422 ms | 219 ms | 78 ms | 无 | 失败 |
| 3 | 437 ms | 203 ms | 78 ms | 无 | 失败 |

每轮 102 个上传包、47040 样本；收到的三份 PCM 分别为 52480、39680、44800
样本，均与保存 WAV 和哈希逐字节一致。回复文本均为“我是小言，ESP-HI语音助手。”
21 个临时转写事件中，每轮最后的预览都包含完整测试句子，但预览不等于最终
确认，不能用它替代最终输入验收。三个回复都正常结束，没有收到协议错误或
接收线程异常。保留的 93 个服务端事件中，最终转写事件数量为零。

本实验请求时间已经晚于原文件加前导静音的标称结束约 56–57 ms。这里的“提前”
是相对完整上传提交，不证明在用户说完前就准备好了回复；也不包含板上播放、
提示音或真人首音素延迟。三轮协议 `complete=false`，退出码 1 是保留的失败结果。

## 能确认与不能确认的结论

提交确认、转写完成和回复完成是三个独立事件，见阿里云
[客户端协议](https://help.aliyun.com/zh/model-studio/client-events)和
[服务端协议](https://help.aliyun.com/zh/model-studio/server-events)。当前组合不能
仅凭回复完成或临时文字完整就认定用户的最终输入已确认。

电脑直接接收的原始协议已经出现同类缺失，因此这种现象不以 C3 的 VAD、
Flash 收尾、CPU 或 WebSocket C 解析器为必要条件。本次三轮连第一轮也失败，
不能继续将其单独称为“第二轮复用故障”。这仍不证明 89/90 实机两次恢复的
所有原因完全相同，也不证明所有网络和客户端问题均已排除。

此前 84 的协议组使用不同提示词、200 ms 尾部静音及不同的三条录音，三轮均有
最终转写，首 PCM 在提交之后。本轮三次首 PCM 均在提交之前。这个事件先后关系
是下一步的诊断线索，但多项配置和云端条件不同，不能据此宣称已经找到因果。
下一步应保持本轮素材、配置和上传方式不变，仅改变请求与提交的相对时机做
有限对照；本轮没有擅自追加该云端试验，也没有放松完整输入或取消保护。
