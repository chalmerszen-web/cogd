# UX108：把 ASR 建连提前到空闲期

2026-09-28。144 实验版复用现有候选任务，先预建 ASR 连接，再预建回复连接。
相同录音各三轮，停录后的上传尾部从 456–711ms 降到 108–177ms；外录起声诊断
候选从 1.56–1.87 秒降到 1.13–1.21 秒。**仍未达到稳定一秒目标**。

源码与构建保留 **0.11.144** 实验版，正式安装包未更新。实测后设备已恢复
**0.11.72-summary** 监听，全部持久化上下文及分区保持。没有继续增加实机轮次。

## 为什么先改建连

143 的三轮普通话自我介绍均首次唤醒、完整转写并正确使用普通话，修复了142的
非请求粤语回复。然而 ASR 在唤醒后才开始握手，耗时1306/1293/1329ms，配置完成
晚于开始录音1063/1061/1115ms。录音持续上传时必须追赶这段积压。

这三轮的候选生成请求实际晚于本地停录405/384/474ms，首批候选PCM又晚于最终
ASR145/42/31ms。因此已有“根据临时转写提前备答”的机制仍被晚到的输入拖住。
本轮保持VAD、提示词、上传包长和最终确认规则不变，只提前连接工作。

## 实现与所有权

- 空闲预连接开启时，现有候选任务先连接隔离ASR槽，再连接回复槽。复用两个
  既有传输对象，不增加任务或音频缓冲，不扩张16576B候选工作结构。
- 预连阶段不读取ASR的session.created、不配置会话、不发送音频。结果通过C11
  原子变量发布，唯一的ASR上传任务接管后才读取、配置和上传。
- 唤醒与握手重叠时，只有网络任务等待交接，录音继续；等待有5秒上限。预连
  失败可在发送音频前新建连接；不重放已经上传或提交的对话。
- 未接管的连接在候选任务退出并join后关闭；接管后的连接由ASR任务关闭。
  取消、空闲到期、其他命令收回工作区均保留原有所有权边界。
- 关键词提名仍只用于备答。完整录音校验、最终转写、改口/取消检查通过后才
  播放或调用硬件。复杂任务继续走原有Agent；没有提前执行猜测的GPIO参数。

两个交接字段放在小型协调对象中。初版把字段加进借用结构，使主机诊断布局的
静态容量断言失败，已修正，没有扩大工作区。网络/TTS等任务栈配置保持不变。
