# UX112：用待续说意图辅助短音节

2026-09-28。149在原有短窗口内，用ASR确认的待续说意图辅助两个真实强语音帧，
避免把紧接着的短音节全部当作停顿。**本轮三次都收到了蓝色改绿色的修正，只执行
绿色；仍未达到稳定一秒回应，完整文字检查也仅1/3通过。**

源码和冻结包保留149实验版。设备已恢复0.11.72-summary，fast/capture监听、reuse开、
prefetch关、Wi-Fi正常、灯灭、COM5释放；安装包未更新，已有上下文保留。

## 改动与边界

UX111保存的失败帧表明：一个真实短音节只有两个强帧，没达到既有四帧支持要求。
149仅在已经由ASR辅助确认的语音里，且意图仍待续说时，让这两个强帧计作延续。
作用窗口仍为最后一次严格连续语音后的320ms，辅助确认不能刷新这个窗口。

弱帧或文本本身不能重新计时，新的语音起始门槛不变。经典模式继续用原规则；
空识别撤回、取消、10秒上限、700ms静音及累计1000ms续听额度保持。
没有新增缓冲、线程或状态字段，应用只增加16B，未减少上下文容量。

主机检查覆盖支持窗口内外的边界、缺少ASR确认、缺少待续说意图、弱噪声、
重复双脉冲不能无限续听、撤回、取消和经典接口兼容。全部65项ASan/UBSan通过，
23.50秒。固定8份真实帧及原ASR时刻重放：6份原有结束结果不变；2份越过旧截断点
后到达文件末尾，后续仍未知。没有补零或虚构未录到的后半句来计作成功。

使用原修正句“请把灯调成蓝色，不对，不要蓝色，改成绿色。”、原声音和0.25增益。

仅作灯色只读查询，间隔已记录实际值。三轮均在最终识别后只执行一次绿色动作。
没有检测到复位、DMA丢失、播放欠载或USB日志丢失。

原report.complete保持false。语义修正与严格逐字完整性分别报告，未改检查门槛。
该小样本支持保留修正继续开发，不构成通用识别率、真人双语或长期再唤醒证明；
没有与旧固件交错进行随机A/B，不能把三次成功直接换算成提升百分比。

外录三份输入均通过原波形对齐；本地ASR识别回复为“灯光设置好了/好啦”。起声值

仍为null；第一轮虽估计低于一秒，也不能替代整组完整输入与速度验收。

第三轮结束并关闭监听后另行导出最后录音，107648样本、6.728秒，SHA和PCM校验
通过。前两份设备原始录音未逐轮保留，因此“请”的缺失尚不能归因于收音或ASR。
