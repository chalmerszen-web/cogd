# 唤醒词前缀与连续采集

## UX485：前缀合同已通过，尚未接入固件

新增 `plugins/audio/preroll.c/.h`：16 kHz 单声道、512 样本独立包、64 包（2.048 秒），复用现有 IMA4bit 和 CRC。每包保留首样本、预测索引、版本与 CRC；先写入，再 seal，随后按源时钟读取。丢帧清除旧历史，重复或倒退时钟拒绝；损坏读取不推进游标或修改输出。

调用方负责串行化及 arena 生命周期。本模块没有线程、分配、I/O 或隐式内存回收；seal 不是线程间撤销机制。接入时必须先停止并等待写入者，在 ASR 读取完毕前禁止 candidate/engine 清零或复用该区域；取消、文本请求、同步、录音和错误退出均须覆盖。当前没有修改这些固件路径。

| 检查 | 结果 | 限制 |

首轮构建在测试夹具的短对象别名输入处被 GCC `-Werror=stringop-overread` 拒绝，未执行测试。只改夹具为足够大的重叠 union 后构建成功，四组原生测试只运行一次。初始夹具、失败日志及前后源码快照均保留，没有通过重复运行挑选结果。

## 实际覆盖边界

沿用 UX250 的原始 C 触发及原始 ADC 输入，未重新检测、训练或调用 ASR。普通话六条原始 WAV 区间全部落在触发前缀内；粤语六条中四条完整，两条在原触发时尚有 WAV 尾部未到达，全部样本的头部均被保留。

这些边界来自原始 WAV 容器及已有回放时钟，**不是人工音节标注**。不能据此断言漏了几个音节、ASR 是否能识别，或这是误唤醒的唯一原因。扩大回看缓存不能保留未来的声音；下一步须检查触发、初始化、提示音到正式录音之间的持续采集和所有权，再做完整唤醒词确认。

压缩误差指标记录在 `coverage-report.json`，属于编码波形误差，不是背景信噪比或人耳/ASR 质量验收。当前未启用固件、未烧录、未调用云 ASR，没有现场误唤醒改善或一秒响应结论。原设备应用、分区、上下文及录音保持。

证据：`artifacts/voice-fast/wake-prefix-contract-ux485/` 下的 `plan.json`、初始 `check-receipt.json`、`repair-receipt.json`、前后 source manifest/delta zip、`test.log`、C3 对象及 `.su`、`coverage-plan.json`、`coverage-report.json`、`coverage-receipt.json` 与 `closure.json`。
