# 语音响应提速：有限实机对比

沿用 0.8.0 的设备直连链路、VocalignTech、DeepSeek、200 KiB 历史选择预算和
全部持久化数据。目标是缩短说完后到听到有效回答的时间，不能用提前播放无内容
提示语冒充实际回答提速，不改为依赖电脑代算的产品流程。

基线：voice-cloud 中相同已保存合成素材和最终固件实测。18 个带阶段时间的旧样本
中位数：上传 7.558 秒、提交 ASR 3.438 秒、等待及下载识别 16.888 秒、LLM
4.009 秒、TTS 到首 PCM 4.978 秒；VAD 后首 PCM 中位数 38.514 秒。
各阶段中位数不可简单相加得到整轮中位数。0.8.0 固件/源码保留可回滚。

实施顺序：

1. 有界复用同一事务内、同一鉴权源的 HTTPS 连接；切换提供方或事务结束都关闭
   活连接。平台的关闭连接句柄和 TLS 会话票据最多缓存 120 秒，用于下次恢复；
   错误、到期和凭据变更清除对应缓存。公有签名 URL 不缓存。不同时打开多条 TLS。
2. 上传 PCM 从 512 字节小块改为 2048 字节；测量栈和上传时延。
3. 短 ASR 任务先每秒查询，再退避到 2/5 秒；保留 180 秒截止、安全 GET 重试，
   不重放不确定的收费 POST。增加上传/识别完成阶段时间，分清云等待与网络开销。
4. 语音默认简短自然回答，用户要求详细时仍可详细。保持 200 KiB 历史与工具链。
5. 先主机检查，备份后只烧应用，执行同素材有限声学对比，再检查取消、重入、
   内存和原接口。若提速不明显，根据测量限定下一次改动，不开启无限调优。

首次候选实际只降低首 PCM 中位数 1.6%，保留失败目标记录。第二次候选采用 IDF
已有的 TLS 会话恢复，合并发送小块 JSON，并禁用 TCP Nagle 延迟；合并发送复用
原 1 KiB 接收缓冲，不增常驻大缓冲。新增不同缓冲边界、最终尾块、长度错配、
发送失败和取消的主机校验。必须测量缓存的内存代价、到期释放和正常恢复。

验收记录：VAD 到首个实际回答 PCM、整轮耗时、输入结束到 VAD、各网络阶段；
确认实际回答的外录、模型识别内容、工具动作、自动恢复监听；同时记录最低堆、
栈、丢帧、取消及异常。至少三组匹配素材，目标中位数降低 25%，如未达成如实说明。
数据为有限合成回放，不作为真人泛化或服务时延 SLA。

平台最新文档已重新读取并保存 artifacts/voice-speed/docs：Qwen ASR 明确是异步
文件服务，不支持实时流式识别；当前 TTS 仅支持非流式生成。固件优化不能消除
云端排队与模型生成时间。此阶段不换服务商、不上传额外真人录音。
