# UX135：SDK 降噪资源筛查

当前 SDK 的传统降噪模块不适合直接加入现有收音链路：C3 实测单个句柄分配
41552B（40.58KiB），超过本次预先规定的8192B筛查上限。尚未进行录音效果对照，
不能声称它能修复弱续说截断或噪声拖尾。生产端点、提前备答策略和内存预算均未修改。

本次目的是检查一种可能的输入改进，不是回复速度验收。提前生成与缓存回复仍须等待
完整意图确认后播放；收音截断导致漏掉后句修正时，候选撤销机制也无法补回缺失输入。

## 固定方法与实际失败

沿用固定的ESP-SR库，SHA256：
`3473d612da471232b8f5ce69470d3ef73aa706d4c4b2372ff626164c9d619d79`。
新增默认关闭的`REPLAY_NS`诊断选项，独立USB程序不使用麦克风、扬声器、Wi-Fi或写入数据分区。
原始滤波后PCM与降噪PCM各接独立MODE2 VAD，保留原20ms周期和前两帧跳过约定。
计划固定比较8份已有录音，先检查内存和处理耗时；不扫描阈值或反复采集。

首次175版本依照头文件的10/20/30ms说明调用`ns_create(20)`。实际C3库在初始化断言
`frame_length_ms==10`并复位，未产生有效处理结果。失败串口和固件包完整保留。
随后记录一次接口修正：176版本创建10ms句柄，每个20ms输入顺序调用两次160样本处理，
保持VAD周期与原输入不变。这是按实际API要求修正，不是降噪强度调参。

176在160MHz C3上完成32个20ms数字静音帧（共640ms输入）：

| 实测项 | 结果 | 解释 |
| --- | ---: | --- |
| NS句柄堆分配 | 41552B | 超过预设8192B上限，拒绝继续集成 |
| 每个独立VAD句柄 | 760B | 与NS分开测量；诊断用了两个VAD |
| 每20ms输入的NS耗时 | 中位3037µs，最大3134µs | 两次10ms调用之和，仅数字静音 |
| 诊断主任务剩余栈水位 | 2824B | 不是并发Agent栈证明 |
| 单次析构前后空闲堆差 | 88B | 原因未归因，不宣称泄漏或无泄漏 |

32帧输出均为零，帧序、长度及输入/输出CRC通过。本次因内存门槛停止，8份录音实际执行
**0份**，后续设备协议12项检查也未执行；没有弱音节保持、噪声抑制、语言泛化或一秒响应
结论。静音上的3134µs不能作为真实语音或Agent并发条件下的最坏耗时。
诊断静态导出缓冲、第二个VAD与USB开销也不能当作生产集成成本。

## 验证与恢复

- 6项已有主机协议检查通过。首次编译的缩进告警修复后，ON/OFF构建均通过；失败日志保留。
- 三次应用写入均先完成4MiB备份和设备校验，再写入、读回核验，并验证非应用区域不变。
  依次测试175、176、恢复72；第一次诊断的断言复位明确记为失败。
- 恢复后的完整4MiB镜像与首次备份逐字节相同。随后验证72的Wi-Fi、fast/capture/listening、
  reuse ON、prefetch OFF、灯灭；串口已释放，未留下录音程序。
- 上下文1084事件、939864B、generation17、next_record4182保持；2MiB分区、204800B历史预算、
  448KiB录音槽不变。生产源文件与正常172标签应用哈希均与本轮开始时相同。
- `REPLAY_NS`已关闭，重建的独立诊断ELF不含NS符号；主工程四个诊断开关保持OFF。
  正常安装包未更新。本轮0次真人/回放对话、0次云调用、0次新录音，不替代三轮对话验收。
