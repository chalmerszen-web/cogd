# M3 音乐实录与调优报告

设备：COM5，ESP32-C3，4 MB Flash。音乐由设备向 DeepSeek 请求生成，设备本地合成；耳机麦克风 `麦克风 (Misiom-Shooter)` 以 44100 Hz、16 位单声道录制实际扬声器。原始录音不归一化、不降噪、不上传。电脑参考 WAV 使用与固件相同的 C 渲染代码。

实现已烧录，**技术与客观声学验收通过，主观听感尚未验收**。当前会话没有直接音频试听输入，以下是信号测量、乐谱检查与设备遥测，不等同于“听起来已经很好”。M0 的实机 Gateway 与真实拔插断电验收仍未完成。

## 实际改动与对照

| 项目 | M2 基线 | M3 |
|---|---|---|
| 乐曲 | 单声部，最长 30 秒 | 主旋律、低音、拨弦琶音、轻鼓；最长 75 秒 |
| 编排 | 音符顺序列表 | 两小节乐句库加播放顺序，重复引用 |
| 表情 | 固定短边沿，等强度 | 每音力度、发音长度、自然衰减、平滑释放和结尾淡出 |
| 音色 | 正弦/三角 | 三组四谐波 Flash 波表、三种轻鼓合成 |
| 内存 | 短谱与控制计划 | 独立 710 字节乐曲、208 字节渲染状态，无整曲 PCM 缓冲 |
| 长历史 | 128 KiB 请求历史预算、1 MiB 有效日志区 | 保持相同容量，修复多次重启的去重索引耗尽 |

1. 首次实录发现首音约前 150 ms 被削弱。增加 300 ms 数字静音预热后，测试音符的音量包络相关性达到约 0.99，首音完整。
2. 只调整低音衰减常数，实录窗口的低音衰减从 2.65 dB 增加到 4.61 dB。后续混音提高低音和琶音的相对权重，主旋律、鼓和总音量保持不变。
3. 同曲混音对照显示前奏仅增加约 1.1 dB，说明总权重调整不足以弥补低频表现。最后增加低音的高次谐波比例，并将编曲低音保持在小扬声器更容易表现的音区。最终校准中低音仍保留 4.14 dB 自然衰减，没有用升高总音量掩盖问题。
4. DeepSeek 早期乐谱有全休止符、输出超限、两小节伴奏只写了一小节、和弦错配等问题。先写具体音乐方案，再以紧凑乐谱提交；通过乐句时值和逐小节和弦检查提出修订，最后一次修订也由设备调用 DeepSeek 完成。

原版：`artifacts/music/baseline/`。预热、包络和混音对照：`calibration-01` 至 `calibration-06-final`、`calibration-03b`、`mix-comparison-02`。早期分析中受首音缺失影响的强弱差不作为通过证据。部分录音的背景瞬态、耳机端处理和噪声门会影响相对信噪比；没有标定 SPL，也不把相关性当成音色评分。

## 最终校准

`artifacts/music/calibration-06-final/evaluation.json`：同一个 A4 音，力度 64 与 112，比较相同发音后 70–170 ms 窗口；衰减比较 70–170 ms 与 550–650 ms。所有测试音量 <=80。

| 测试 | 实录强弱差 dB | 实录衰减 dB | 满幅削波 |
|---|---:|---:|---:|
| 电钢，总音量 40 | 5.62 | 14.05 | 0 |
| 电钢，总音量 80 | 5.18 | 16.74 | 0 |
| 低音，总音量 80 | 5.38 | 4.14 | 0 |
| 拨弦，总音量 80 | 5.15 | 26.87 | 0 |

目标强弱差 >=3 dB 已达到。不同乐器的衰减不同；低音保留约四分之一的持续分量。C 合成的峰值始终小于四分之一满幅，混音有软限幅余量。

这项和声检查只适用于当前根音低音加三和弦琶音的候选，不是通用音乐审美规则。候选的原始提示、设备回复、接受乐谱、固件 SHA、逐次播放状态、参考 WAV 和耳机实录均保留在对应目录；不是用电脑创作结果冒充设备生成。

最后一首的生成实录：拟合独立采样时钟差后约 59.90 秒，包络相关性 0.891，满幅削波 0；背景与频谱明细见 `candidate-05c/evaluation.json`。相对信噪比是本地录音的统计量，含环境和耳机采集链影响。

`artifacts/logs/m3-soak-completed.json` 与 `m3-soak-summary.json`：100 个有完整回复和遥测的轮次通过，每十轮使用非流式，其余流式；最后一轮调用检索工具正确读取最初的独立事实。音乐以最大 128 音符/四声部乐谱静音渲染，ADC 音量检测持续运行，每轮同时改变灯色。

这次是**同一固件上的分段回归**：先完成 37 个验证轮次，第 38 轮触发测试端 100 秒超时，但设备随后返回 OK_038；那次晚到、未完整取样的回复不计入 100 轮。测试端等待调整为 300 秒，以覆盖已有的两次有界 HTTP 尝试，然后从 38 继续到 100。固件超时未放宽，原失败报告保留。网络延迟仍可能较长；有限测试不等于无限耐久保证。

回归后有 1482 条本地待同步记录，占 958696/1048576 字节，预算仍为 128 KiB，模式 LOCAL；本次测试填充仍保留在设备上，没有擅自删除未同步历史。六秒人声录音保持可用。最终 checkpoint 和重启后测试增加了少量记录，最终状态见下面的交付核验。

## 稳定性与回滚

15 组 C11/ASan/UBSan 主机测试、10 组关闭音频测试、6 组 mock HTTPS 测试、8 组迁移/归档辅助测试通过。固件关闭音频独立构建通过；30 个自有 C 编译单元通过边界与 C11 审计。主机覆盖随机分块一致性、最大 128 音符混音、无效参数、引用、CRC/超时/取消和资源冲突。

USB 上传使用空闲请求缓冲区，按长度、偏移、CRC 和 15 秒截止时间校验后才提交。普通对话仍限 2 KiB；上传未提交、损坏、取消或超时不会播放。测试保持原有六秒人声录音不变。

多次烧录后的 `full` 是本地去重索引耗尽，发生时日志只用了 632272/1048576 字节。修复将本机已发出/已退役的序号表示为一个高水位区间，外部设备继续使用精确稀疏区间；40 次重启主机回归和已满旧索引升级测试通过。实机恢复后原有 1276 条记录仍在，随后继续追加，不删历史或缩小上下文。

完整 M3 前备份：`artifacts/backups/esp32c3-before-m3-20260911.bin`，SHA-256 `997941817d850c66eae1966336924447d52442b81be59bbbd34b92b8dbcd47a8`。保留 M2 应用 `artifacts/releases/m2-0.3.0-dev/esp_hi_agent.bin`；回滚只写应用的 `0x10000` 地址，保留当前分区和数据。不要恢复整个旧备份来覆盖后续对话。

## 复现

`tools/music_candidates.py` 通过 USB 让设备创作并录制实际扬声器；`--no-stream` 验证非流式；`--prompt-file` 用单行合并的 UTF-8 提示修订现有曲子。`--replay SONG --repeats 3` 重播已接受的乐谱。它始终区分接单与播放结束，并验证样本数量、作业编号和读回 CRC。

`tools/hardware_m3.py` 运行上传/取消/资源测试及实录校准；`tools/hardware_m3_soak.py` 运行 100 轮真实调用。`build-host/render_music` 使用相同 C 代码生成参考；`tools/evaluate_music.py`、`plot_music.py` 输出分析和图。音频分析依赖 `tools/requirements-music.txt`，可放在项目 `.local/music-python` 虚拟环境；设备脚本使用已安装 pyserial 的 IDF Python。FFmpeg 需在 PATH，选择命名的 DirectShow 麦克风；本地录音不会自动上传。

参考接口：[DeepSeek Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)、[FFmpeg DirectShow](https://www.ffmpeg.org/ffmpeg-devices.html#dshow)。本工程显式关闭 thinking，音频构建上限 4096 输出 token，同时保留所有字节限制。
