# 已存实机录音的结束与上传拖尾

2026-10-03，UX445。本阶段只分析 UX444 最后一轮的已备份录音，没有采音、USB 写入、云调用或模型训练。误唤醒尚未修复。

从 Flash guard 已核验的完整备份中取出 v3 录音槽，生产 C 解码器与独立 Python 解码逐样本一致。记录头及压缩内容 CRC 通过，89024 个样本、16 kHz，共 5.564 秒；样本数与最后一次录音状态及上传计数一致。正常固件没有记录内嵌轮次 ID 或上传 PCM CRC，因此这不是逐字节证明上传内容相同。

固定三频带来源匹配通过，三条包络相关系数为 0.822、0.942、0.940，偏移均为 0.700 秒。沿用来源的能量活动结束点，录音中对应 4.130 秒，之后仍有 1.434 秒样本。本机一次 SenseVoice 转写为“请记住，我给这盏灯取名叫小星星。”，完整输入检查通过。

`vad_end` 事件在上传结束后发出，不能直接作为本地麦克风停止时间。此轮分别存在采集和上传拖尾；提前应答的启动事件也不等于扬声器首个有效语音。能量结束点不是人工音素标注，当前记录没有逐帧 ASR/VAD 提示，不能据此认定底噪、语义等待或任一上传调用是唯一原因，也没有缩短正常 VAD 门槛。

首次编译成功后，WSL 的 UTF-16 代理警告被日志读取器按 UTF-8 解码，分析停止。保留失败脚本和日志，续跑只使用已编译的同一 C 解码器；结构化 stdout 与 stderr 分离。首次来源匹配前，修正不支持单次来源的 `align_repeated` 调用，改用已有 `analyze_latency.align`，原相关、竞争及时间偏移门槛保持。没有重编、重复 ASR 或换匹配条件。

证据位于 `artifacts/voice-fast/voice-source-tail-ux445/`：原计划、修正说明、两次进程记录、CRC/解码、来源匹配、原 PCM/WAV 和 `report.json`。设备仍沿用 UX444 收尾核验的原 `0.11.72-summary`，自动唤醒及语音关闭；此阶段未改变固件、上下文或凭据。该离线分析不能替代误唤醒、连续对话或一秒响应验收。
