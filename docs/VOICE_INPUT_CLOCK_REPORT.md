# UX140：确认实际声源与板上输入的差异

2026-09-29。本轮将问题范围进一步收敛：**三轮真实对话的电脑输出和外部原生麦克风
录音都包含完整输入，板上最终转写仍丢失或错认开头**。修复了一处离线波形对齐问题，
但没有把录音质量改善或一秒回复标为通过。固件源码及179应用未改，设备恢复72联网监听。

## 三次固定采集

保留UX139原素材“你用一句话介绍你自己。”、播放增益0.25和相同设备位置。
在72上关闭语音业务，进行恰好三次7秒定长录音，采样开始至少500ms后播放素材。
它们没有唤醒、VAD和云请求，是声源定位实验，不计入连续对话或速度验收。

每次同时保存：电脑输出loopback、48kHz原生RAW麦克风、44.1kHz DirectShow麦克风、
16kHz板上录音。输出时钟设置为关闭保持／开启数字静音保持／关闭保持，固定ABA顺序。
三次的四条信号均通过原独立模板检查，本地SenseVoice均识别为完整句子。
板上无ADC削波或DMA溢出，RAW/loopback原始包均连续，无补帧。原生麦克风报告的
回声消除、降噪和自动增益效果状态均为关闭；没有修改系统端点设置或音量。

因此，这组没有支持“每次打开电脑播放句柄都会吃掉开头”或“RAW才能录完整”的假设。
它也不能证明并发联网、提示音和正常唤醒采集时同样可靠。

## 三轮真实对话与旁路记录

复用冻结179，无编译或策略修改：idle预连接、prefetch/reuse开启，同一素材、增益0.25，
普通话／粤语／普通话唤醒。原continuous_rewake脚本不变，轮间不等待fast_ready；
三次首次唤醒均命中，下一轮距上轮结束约266/265ms。

另用原接口旁路采集RAW（最多60秒）和输出loopback（最多90秒，不保持输出时钟）。

输出loopback整组有5处设备位置跳跃，原采集器按严格条件报失败，旁路observer也保留失败。
没有补静音或把整组改成通过。输出文件可分成六段内部连续数据；其中三个完整指令段
各自与原素材匹配，三个频带相关性均大于0.9，并独立识别为完整句子。报告只利用这些
已匹配连续段说明电脑实际送出的内容，不宣称整组输出时钟连续或可用于完整速度验收。

RAW剪裁由每个原始包的QPC时间戳定位。微软说明这些值对应包内首帧、单位为100ns；
见[GetBuffer接口](https://learn.microsoft.com/en-us/windows/win32/api/audioclient/nf-audioclient-iaudiocaptureclient-getbuffer)。
额外低频声学定位检查只有约0.53，低于预定0.8门槛；失败保留，没有放宽门槛或据此发布
声学输入结束时刻。剪裁仅用于独立内容核对。最初assert退出的分析日志也保留，随后版本
记录unknown和受限证据，不修改原录音或原始采集判定。

## 修复离线匹配的数字静音问题

原源文件3.055秒，最后非零样本到2.390秒，后面有665ms纯数字静音。
原对齐使用整个文件；设备结束提示音若落入这段静音，可能主导归一化相关性的分母。
新合成反例先在原实现上失败，修复后通过。

`align_repeated`现在只去除文件两端的精确零值，并在非零内容外保留10ms边界。
本素材参考区间为样本[720,38400)，所有非零样本保留，连1LSB的弱音也不丢弃。
结果时间减去参考区间偏移，仍对应原播放时钟；三频带门槛、40ms约束及候选间差值要求不变。
静音源明确拒绝。新增5项检查覆盖提示音污染零尾、无填充文件、极弱非零边缘、静音和无关录音，
连同已有提示音/回答判定共15项通过。没有改变实际播放素材、增益、VAD或固件。

UX139及本轮原外录另存`padding-aware-analysis.json`。修复后分别只有1/3输入副本通过，
两组整体仍unknown；未覆盖旧分析，**仍不公布回复起声速度**。该修复提高测量方法的正确性，
不代表已经解决板上输入问题。
