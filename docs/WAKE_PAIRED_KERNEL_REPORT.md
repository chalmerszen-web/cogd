# 双模型层间交互内核：主机与 C3 资源检查

更新日期：2026-10-01。阶段 UX210–214，**主机数值证明和 ESP32-C3 诊断资源门槛通过；有限训练降低了开发集误触，但损失正确唤醒、未通过识别门槛，没有部署。**

原 E/L 两个 24 通道模型仍使用相同输入前端、独立 stem、深度卷积、各自逐点卷积与末层。新内核逐层计算两个分支，在现有五个逐点卷积位置增加另一分支的 24×24 INT8 输入贡献，用接收通道原量化位移处理结果。原权重、偏置和双末层保留；交互权重为零时行为必须完全一致。

这一结构可以在训练时使用两个分支的中间声学信息，交互部分有 5760 个参数。参数与额外乘加量是结构预算；最终应用的程序代码、对齐和 ESP32-C3 耗时仍须实测。

## UX213：有限训练与停止理由

只训练 5760 个交互权重，原 E/L 的权重、偏置、位移、前端与两个末层不变。训练前对 FP32 的每个可能整数部分和给出上界 1977039，小于精确整数范围 2²⁴；固定零／非零输入的 1085440 个层值、16 个原训练样本的缓存输出和 35 条真实 C 检测器流全部一致，全部新增参数具有有效梯度。原参数在 PyTorch 中以只读 buffer 保存，预检报告中的 `frozen_parameters:0` 表示没有另行声明原 `nn.Parameter`，不表示原权重被移除。

使用原训练集前 15623 条输入，排除 168 条实际监听补充，固定种子、2000 次 AdamW 更新、一次最终 checkpoint；训练约 48.47 秒，没有读取实际输入或验证集来选择模型。训练后全部 7998976 个双末层值与独立 F64 整数参考一致，16 个输入的 2170880 个 C 环形缓冲层值一致。INT8 交互参数范围为 −8 至 9，4673 个非零。

误触样本减少 86.67%，但有效正例数量相对原模型减少约 3.11%／4.48%。未达到各语言保留至少 99.5%、无新增负例和无新增提前事件的冻结门槛，因此停止，不进入已知实际输入、独立验证、测试或实机安装。这些数值是开发训练集检查，不能当成人声泛化或现场误唤醒率。

进一步只审计已保存的训练分数，没有再推理、训练或扫阈值。原本正确而被候选丢失的普通话有 119 条、粤语有 138 条，同时新获得 9／25 条，形成表中的净变化。256 条丢失的有效位置没有达到原固定分类阈值，只有 1 条存在有效投票机会却未在正确区间产生事件；退步遍及八个声音，原始 variant 0 也受影响。后续应明确保留已有正确分类并约束新增负例，不能把这一退步归咎于 USB 延时、仅用延迟等待弥补或删掉困难样本。

两次报告兼容问题保留：预检将 NumPy 导出数组传入 `torch.count_nonzero`；最终计数是 `np.int64`，不能直接 JSON 输出。修复的是检查和报告，原训练脚本、一次最终权重及分数保留。报告恢复没有 optimizer 更新，只补受影响的数值证据，不重复训练。

当前设备已恢复 `0.11.72-summary`，自动唤醒和自动语音关闭，没有留下诊断内核。原历史 1248 事件、876424 字节、下一序号 4475 与灯状态保持，COM5 已释放。
