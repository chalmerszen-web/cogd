# UX123：提前分段是否能缩短备答等待

2026-09-28。本次完成六次有界ASR协议对照。把云端静音分段从700改为400毫秒，能更早拿到
片段定稿，但**没有稳定提前用于备答的完整问题预览**，因此没有据此修改或烧录固件。
设备保持`0.11.72-summary`；源码中的实验固件仍为161。整体语音目标继续开放。

## 实验

同一模型`qwen3-asr-flash-realtime`、阈值0.2、16kHz单声道、464样本上传块，按音频真实时长发送。
先700毫秒后三次400毫秒，各输入每个设置只发送一次，不重试，不生成回复，不开麦克风或扬声器。
三份输入为UX122单句天空问题、UX120原始双句天空问题、UX121最后保存的160设备录音。
后者本来就缺少第二句，本实验不能恢复或证明不存在的音频。

每份输入追加相同700毫秒静音尾部用于观察；两组逐样本哈希相同，提交`session.finish`前上传全部PCM。
保存每次会话的设置回执、片段身份、源时间、临时与最终文字、原始事件和发送块校验值。
400毫秒在[官方ASR客户端参数范围](https://help.aliyun.com/en/model-studio/qwen-asr-realtime-client-events)内；
官方也说明较短静音可能把自然停顿分成多句。这里观察的是ASR分段，不将其视为用户整轮结束。

| 输入 | 首个非空定稿提前 | 完整问题预览提前 | 内容完整 |
| --- | ---: | ---: | --- |
| 单句合成问题 | 328ms | 16ms | 两设置均完整 |
| 原始双句合成问题 | 327ms；末句390ms | −47ms | 两设置均保留两句 |
| 已保存设备录音 | 1218ms | −15ms | 两设置均覆盖文件现有内容 |

正值表示400比700早，负值表示反而更晚。时间均相对每次上传起点，属于电脑协议测量，
没有配对随机化、重复统计或新的实机声学验收。不能把这组小样本差值当作确定的产品加速幅度。

400设置在设备录音上新增了一个最终文字为空的噪声片段。现有C分段器对全部六份真实事件流
进行了ASan/UBSan重放：127条输入事件全部接受，最多两个片段，六个最终合并文本均匹配预期。
双句顺序保留；空片段没有清掉前面的有效问题。身份与上传样本边界仍由实际事件检查。

## 时间归因与决定

UX122外部录音中，知识问题说完到“咻”开始约1.245/2.275/1.190秒；自我介绍约0.330/0.335/0.340秒。
这不是统一固定静音时间：局部人声分类、续听额度及背景噪声会影响结束时刻。
串口事件接收有排队，报告另存接收时刻，仅作诊断，不能替代外录声学时刻。

UX122备答使用临时文字，两个设置的完整问题预览几乎同时到达。提前片段定稿不会自动消除
设备结束收音的等待；直接用片段定稿结束采集，又会把句中停顿误认为整句话结束。
因此不把400设置作为已证明有效的固件优化，不追加参数扫描或重复声学试验。
下一步仍需针对实际收音尾部的延长/漏收原因和完整输入确认路径，而非只调整云端分段数值。

## 交付与校验

只给主机诊断工具`asr_vad_probe.py`增加显式、有界的素材名单，默认旧行为不变；
名单仍须与素材报告顺序一致，最多六项，音频哈希与长度检查保持。相关六项Python检查通过。
没有生产固件C代码、模型、阈值、上下文、分区或运行缓冲变更，因此没有新固件构建或烧录。

首次C重放的PowerShell→WSL循环参数传递失败，产生一个空输出，保留为诊断失败证据；
改用明确参数列表的Python进程调用后，六份重放完成。没有为此再请求云服务。
