# UX181：把漏掉的改口定位到输入边界

2026-09-30。本轮只读上一轮保存的三份音频：原播放提示、持续录制的外部麦克风和第三轮从设备 USB 导出的 60,288 样本录音。不增加唤醒、云请求、录音、烧录或生产代码。目的是区分“源提示没有播放完”和“设备在后半句前停止采集”，再检查前半句中的弱音是否被现有门槛漏判。

预先固定 1.5 秒模板、300–1000/1000–2000/2000–3500Hz 三频带 10ms 包络；至少两个频带归一化相关≥0.35、起点差≤80ms，才接受对齐。外部录音仅在每轮日志播放起点前后各 2 秒搜索。外部 WAV 为 44.1kHz，按整数比重采样到 16kHz；第一次因脚本只允许 16kHz 而在读取时退出，修正读取格式后进行唯一一次完整计算，没有改门槛或音频。

| 证据 | 结果 |
| --- | --- |
| 第三轮设备与播放源 | 三频带相关 0.828/0.971/0.704，起点分散 10ms；播放源起点位于设备录音 0.73 秒 |
| 设备截止 | 录音 3.768 秒映射到播放源约 3.038 秒；播放源最后有声到 5.09 秒，后续约 2.05 秒未进入设备录音 |
| 外部麦克风 | 三轮的提示开头及结尾分别对齐于同一播放起点，3/3 前后模板一致；后半句确实从电脑输出并进入该外部录音 |

用同一播放源的 10ms RMS、固定 2% 峰值与 64/32768 下限形成显示用的有声段；仅把≤100ms 内部间隔合并。四段为 0.12–1.82、2.19–2.54、3.05–3.83、4.28–5.09 秒。设备截止约 3.038 秒，和第三段开始 3.05 秒相隔约 12ms，落在 10ms 对齐与能量格点的不确定范围内，故只称**恰好在下一段开始附近停止**，不称精确提前 12ms。冻结本地 SenseVoice 对源 2.54 秒和 3.038 秒裁剪均读出“请把灯调成蓝色，不对”；到 3.83 秒才加入“不要蓝色”，到 5.09 秒加入“改成绿色”。设备保存录音的本地转写也只到“不对”，与在线 ASR 相符。自动转写不是逐音节真值。

关键是第二个有声段在设备里已经存在，却不足以重置严格静音：映射的设备 2.92–3.27 秒区间有 17 个 20ms 帧，现有 C 滤波器重算的清洁能量中位 216、最高 328；冻结噪声 176 对应强门槛 352，因此强能量 0 帧、弱能量 5 帧。设备报告最后严格续说点在 2.2 秒，之后静音计时一直走到 1500ms 暂定上限。板上频谱 VAD 每帧结果未导出；这里证明的是**强能量必要条件未满足**，不是对全部 VAD 投票的重演。第三轮 ASR 的“不对”临时文字在设备 `vad_end` 后约 335ms 才到达，不能用它事后延长已经关闭的录音。

这组材料排除了“电脑根本没放出改口尾句”这一解释，且说明只提前猜到灯控关键词仍拿不到最终颜色。第三轮的问题集中在弱第二段未被确认、下一段开始时采集已结束；第二轮空转写没有保存设备录音，不能据此归为同一原因。外部麦克风不等于设备麦克风位置，也不能证明第三、四段在设备端会有多少能量。旧 UX172 曾试过“四弱帧＋ASR 活动”并使短问候延后 460ms，仍漏一段，因此本轮不重复移植它，也不把 800ms 扫成更大数字。

下一项有效工作应把已保存的当前域正常录音和背景/短句做配对，设计能辨认弱人声而不延长普通短句的**独立声学证据**，并同时验证生产者采样上界。改动前应确认逐帧声学门槛、ASR 通知到达时机及堆预算；通过固定材料后才准再烧一次三轮连续对话。候选回复仍只能提前准备，最终文字未确认不得播放具体颜色或执行 GPIO。本轮没有声学首答速度或真人泛化成绩。

证据在 `artifacts/voice-fast/input-attribution-ux181/`：预定方案、`audio_align.py`/`alignment.json`、`pause_map.py`/`pause-map.json`、`segment_levels.py`/`segment-levels.json`、`transcribe_crops.py`/`crop-text.json`。原三份 WAV 和整组三轮事件仍在 `artifacts/voice-fast/provisional-firmware-ux180/`，均以 SHA256 关联。最近一次已验证的板上状态为 UX180 恢复后的 `0.11.72-summary` 联网监听；本轮没有重新打开 COM5。
