# UX126：修复预备答案撤销后的连续内存分配

2026-09-28。本轮针对UX125实测的工作区恢复失败实施修复：原来一次申请54416B，
改为分别申请29836B状态和24577B请求缓冲。**容量不变，不靠缩小上下文解决失败。**
这改善的是完成对话的可靠性，尚不能宣称达到稳定一秒响应。

## 修改与边界

消息、模型回复和SSE仍在同一状态块，请求缓冲独立分配。引擎的绑定指针放在借用区外，
采集覆写临时存储不会破坏这些指针。绑定同时更新上下文序列化指针，拒绝重叠、未对齐、
不足容量，以及输出任务或历史选择仍在使用时的迁移。未绑定时，在网络和工具动作前报错。

实际分配代码位于`platform/espidf/engine_memory.c`，由平台持有内存生命周期。
任一分配失败会清理已分配的部分；没有重新请求模型、重播回答或重复执行工具。
普通静态构建继续支持原连续布局，旧TEN及相关采集路径明确按需申请54416B整块。
因此这里只消除了预备答案向正常Agent恢复时的大块要求，不能声称所有模式都不再需要它。

C3 ELF确认：消息16396B、回复13404B、SSE36B，状态合计29836B；完整连续布局仍54416B。
输入、工具参数、模型回答、24KiB请求、204800B历史预算、2MiB上下文和448KiB录音分区不变。
端点、静音门槛和ASR参数未改。普通版本164，固定八秒采集诊断版本165。
