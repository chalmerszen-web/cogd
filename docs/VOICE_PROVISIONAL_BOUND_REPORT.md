# 暂定结束前的采样上界核对（UX178）

2026-09-30。UX176 已证明当前端点在改口前提前结束；UX177 冻结小模型未通过，因此先核对另一条必要条件：采样生产端是否仍会保留后续音频。把原三份 8 秒设备逐帧元数据送入同一份 C `source_bound.c`，保持噪声、阈值、1000ms 生产端保护、10秒上限不变，使用 ASan/UBSan 编译。

| 次数 | 原端点结束 | 原元数据生产上界 | 掩蔽测试扫频后生产上界 |
| --- | ---: | ---: | ---: |
| 1 | 3360 ms | 8840 ms* | 8240 ms* |
| 2 | 3400 ms | 8820 ms* | 7860 ms |
| 3 | 3120 ms | 8780 ms* | 7900 ms |

`*` 表示 8 秒实录之后才到达计算上界，8 秒后的帧只用固定噪声值延伸状态机；不是声称板上实测了额外音频。掩蔽版仅把前后两个同步扫频及其前后 200ms 的**能量字段**代入冻结噪声，其余逐帧信息不动。这是去掉标定声音的反事实，不是真实未播放同步声的再录音。两版生产上界都明显晚于后续四强帧的 3880/3940/3880ms 和约 5.7 秒的原声结尾，因此现有生产上界并未解释本组三次提前结束；消费者端点先终止是主要可见原因。

首次掩蔽实现中，前标记发生在 170/220/180ms，起点减 200ms 的无符号计算在第 1、3 份下溢，仅掩蔽了后标记。该计算和输出 `replay.json`、`replay.log` 原样保留，不能用于上述结论。修正为起点饱和至零后，三份各掩蔽 55/57/56 帧；上表只引用 `replay-corrected.json`。六个修正后 C 重放均完成，没有消毒器报错。

此结果使“可撤销的结束候选”具备采样覆盖前提，但不证明它能兼顾完整改口和低延迟。对所有短句一律多等约 800ms 会直接增加答复等待，与稳定 1 秒有效回答目标冲突。后续只应测试有明确触发条件和一次性配额的候选观察，并用原 ASR 通知、短句、背景、取消一起重放；通过主机门槛后再考虑实机连续三轮。

生产 407 份代码及正常/无音频构建字节未改；本轮无设备交互、云调用、训练、采集或烧录。设备仍以前轮已验证的 0.11.72 恢复状态为最近一次实测，本轮不冒充新的设备状态。完整目标仍未完成。全部输入、第一次错误结果、修正后的二进制与原始输出位于 `artifacts/voice-fast/provisional-bound-ux178/`。
