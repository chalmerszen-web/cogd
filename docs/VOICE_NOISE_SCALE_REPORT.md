# UX134：唤醒前噪声基准与弱续说诊断

2026-09-28。继续验证提前备答所需的完整输入。本轮确认了一个可复现的问题：
**两次普通话唤醒的尾音抬高了后续收音使用的噪声基准。** 但仅换回唤醒前基准仍不能
修复全部截断，另有一轮出现拖尾超时。因此没有降低生产门槛，也没有宣布一秒目标通过。
设备已恢复`0.11.72-summary`联网监听，默认安装包未更新。

## 先排除清洁能量标尺

监听期用`agent_voice_filter`后的平均绝对幅度学习噪声；采集期的清洁能量还经过提示音
陷波、两个窄带陷波和300Hz高通，两条能量门槛却使用同一冻结数值。这一源码事实不等于
它就是截断主因。

对既有七份录音、2102帧做三种固定重放：当前门槛；原始分支不变、清洁门槛降到已有
下限240；完全移除清洁分支限制。后两者仅用于归因，未上板，也没有扫描参数。
三段UX132录音使用实际源帧消费的ASR提示；四份旧控制使用恒定文字压力条件。

背景尾段在三条路径中均到文件末尾仍为SPEECH；数字静音均为NO_SPEECH。不能把前者当成
新回归或负样本通过。两次截断毫无改善，其他输入反而延长，故不实施这条门槛调整。
同一C滤波器重建2102帧的两条能量，与实机元数据逐帧一致；基线状态与上一轮记录一致。
未把采集尾部当作缺失的唤醒前噪声，也未假设分类更宽松就一定单调推迟结束。

## 一次三轮实机采集

新增仅在`AGENT_CAPTURE_PROBE`构建中存在的256×8字节环形诊断记录：监听期每20ms保留
实际能量、当前噪声估计和设备时间，最多5.12秒。音频任务在命中唤醒后停止写入，收音
结束后的观察回调在重新监听之前导出；不在采样中做USB输出。记录与原端点导出共用
原150ms预算，CRC、数量、顺序必须完整，不完整结果不能当成有效证据。

诊断版`0.11.174-protocol-diag`保持172的端点和提前备答策略，固定八秒采集保留后句。
普通话、粤语、普通话唤醒各一次，任务均为普通话“请把灯调成蓝色，不对，不要蓝色，
改成绿色。”，播放增益仍为0.25。每次唤醒播放前增加2500ms无计划播放窗口，并查询
设备时钟，取该标记之前100ms结束的32帧基线。它不证明房间不存在其他声音。
这些额外间隔和固定采集使本组**不能用于响应速度或连续快速重唤醒验收**。

第三低值，全部与设备估计一致。两次普通话唤醒的末段都有大幅能量上升，正落在最近
640ms窗口里。上述是该组三次实际测量，不能推广成语言间固有差异。

只把同一轮噪声参数替换为独立测得的唤醒前值，重放当前C端点和原ASR提示：

第一轮有改善空间，但第三轮仍失败；第二轮即使不改噪声也没有及时结束。投影沿用原ASR
到达顺序和完整八秒元数据，不是新固件的真实收音或响应速度，也没有整合生产者边界。
不能据此直接合入“长窗口取较低噪声”或全局降低门槛。

三次首次唤醒均命中；两轮完成绿灯任务，一轮超时，严格全文匹配0/3。完整诊断录音第1、3轮
各保留128000样本；第2轮未形成可导出的有效提交，只保存400帧元数据和失败日志，**没有
拿上一轮PCM替代它**。本地SenseVoice对两份完整录音都识别出绿色改口，实际截断前缀均
缺后半句；独立尾段却识别成“黑色”，第一轮投影前缀另把“不要”错成“涂要”。这些自动
识别分歧全部保留，不声称真人听感或识别准确率通过。

本组三轮未观察到WDT、panic、复位或DMA丢失。最低堆44600B低于49152B门槛，诊断环形记录
本身还占2052B，不能据此宣称普通固件的堆验收。正常构建不包含此记录或诊断命令。

## 验证、失败与恢复

七项相关主机检查通过（21.96秒），原端点导出解析3项通过；环形缓冲ASan/UBSan检查覆盖
多次回绕、复位和32768边界。首次构建漏了诊断头文件相对路径，保留失败日志后修正。

第一次三轮端点重放发现一个工具缺陷：主机`--shadow`没有重现实机在八秒仍收音时强制
LIMIT，只有第二轮的state不一致。补上该诊断语义及不完整数据拒绝后，三项回归覆盖
强制LIMIT、原有DONE/NO_SPEECH保持、普通非诊断模式不变；第二次重放33/33终态字段一致。
第一次结果仍在`endpoint-analysis`，修正结果在`endpoint-analysis-02`。修复的是主机验证
工具，没有把第二轮实际超时改记成功，也没有为此重新录音。
