# UX118：提前播放已确认意图的准备语

2026-09-28，实验版本`0.11.156`。任务准备语从等待完整生成改为有条件地流式播放，
三轮记忆任务中两轮实际提前起声。**稳定一秒回复和整体验收仍未通过。**

## 修改范围

关键词先触发后台生成，用户说完后仍校验完整识别、意图、语言和取消状态。
准备语必须是已校验的完整短句，只能表示准备，不能带猜测的颜色、记忆内容或报完成。
满足这些条件并收到PCM后，立即写入现有板端Flash音频队列，继续接收后面的音频。
原先此处只有自我介绍可以提前播放，任务准备语要等response.done，容易超过500ms而被丢弃。

没有延长首次放行的500ms窗口；已经开始播放才使用原有10秒尾部截止时间。
文本随后改变、出现工具、断流、取消或Flash错误时关闭播放，不重放已发声的候选。
完整响应仍需校验；只在候选worker退出、队列封口并释放暂存指针后，才恢复完整Agent工作区。
音频队列使用稳定的本轮取消指针，避免指向已经释放的候选内存。
保留生成已完成时的缓存播放、自我介绍连接复用和最终输入的本地灯控路径。

这不是同时启动完整DeepSeek的新增线程。候选生成还持有共享工作区时，正式Agent仍须等它退出；
先接话不等于正式回答完成。没有新增泛化意图分类，也没有用固定接话替代模型生成。
ASR/VAD、模型、音量、证书、栈、缓存容量、上下文和分区均未调整。
