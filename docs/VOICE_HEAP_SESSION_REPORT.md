# 语音结束后内存记录与导出修正

2026-10-04，UX510–511。误唤醒、连续三轮正常对话、整轮 48 KiB 最低堆和一秒应答均尚未通过。当前设备恢复 `0.11.72-summary`，自动唤醒／语音关闭，USB 文本交互可用。

原 UX491 对话结束检查点的 SDK 最低堆为 49204 B，关闭监听后降至 46464 B。旧的分配记录在每个语音任务结束时停止，无法覆盖此后的 USB 命令和空闲工作区恢复。

新增仅用于诊断的显式会话，可覆盖多轮任务与结束清理。分配回调仍不分配内存、不输出日志、不等待；固定环保存最多 16 条分配观察和 16 条阶段观察。额外记录 SDK 历史最低堆，并明确区分它与当时的总空闲堆。SDK 的最低堆是各内存区历史最低值之和，不保证这些最低值发生在同一时刻；跳过与覆盖的记录不能补造。

UX510 主机 9 项原生检查和 6 项解析检查通过，应用 1536656 B，在原预算内。唯一普通话／粤语／普通话实机组失败：首次触发 2/3，完整输入及完整对话 0/3。一次 ASR 返回与测试输入无关的话语。两个实际播放的提示均未通过原来的固定波形对齐门槛，不能确定环境干扰、播放输入或其他因素是唯一原因，也不能据此报告应答速度。未重跑相同组。

结束导出调用通用语音事件函数，其 2304 B 栈缓冲使 USB 主任务溢出。只收到四条分配记录，没有完整汇总；45208 B 的 SDK 最低堆保留为失败结果，不能用残缺记录解释具体来源。原有速度分析器拒绝诊断录音，未绕过这一限制。

UX511 只修正这个新发现的诊断缺陷：专用事件函数使用 512 B 缓冲和明确的 noinline 边界，保持已有 JSON 契约，绕过语音阶段及候选协调逻辑。其最终链接栈帧为 560 B。仅运行一次关闭唤醒／语音的 USB 导出：两份汇总完整，主任务栈剩 1836 B，无复位或 panic。没有麦克风采集、扬声器播放、云调用或另一组对话。这只能证明导出修复，不能证明整轮语音资源或识别质量合格。

应用 1536912 B，SHA256 `b342cebdd4d9de3ca06df7705e055b5f90210bdab92e0cbd455e4a7e4aa8a4a7`，原应用预算余 3184 B。两阶段均通过 fresh 4 MiB 备份、app-only 写入、读回和回滚。UX511 全过程上下文与录音分区逐字节保持；当前 1385 个事件、940428 B、next4612，2 MiB 分区及 204800 B 历史预算保持。原固件 SHA256 `22faca4f0c6bf12030d924db38904d330af9585493ea307e29f18d4da2309c07`，串口释放。
