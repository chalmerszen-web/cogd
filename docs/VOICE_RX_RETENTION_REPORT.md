## 假设与单参数证据

本地IDF固定提交fff9895c82d744c7237be8847347bdd1b07c6643。其
[lwIP配置说明](https://github.com/espressif/esp-idf/blob/fff9895c82d744c7237be8847347bdd1b07c6643/components/lwip/Kconfig#L763)
明确指出乱序包可能占住MAC接收缓冲，并建议按连接数量分摊上限。本工程
动态RX8、静态RX4、每连接乱序保留4、最多5个socket；L2_TO_L3_COPY关闭。
因此尝试上限1，总RX/窗口/应用逻辑不变。这是工程假设，不是故障根因证明。

普通/诊断/无音频构建分别1501568/1504448/1014096B。`single-change.json`
确认两个实际sdkconfig只有OOO上限变化，399份C/H/CMake只改变runtime版本
198→199。主机69项证据沿用UX160，不列为本轮重跑。分区与历史预算未变。

## 唯一三作业

| 轮次 | 候选文本 | 结果 | 正式请求体重叠 |
|---|---|---|---|
| 1 | 嗯，灯的颜色，我想想（无句号） | 收齐39680样本后done | 无 |
| 2 | 嗯，现在灯，我想想（无句号） | 缓存满limit | 无 |
| 3 | 嗯，现在灯是什么颜色，我想想。 | 话题超过6字，protocol | 无 |

第2轮达到49402样本/24576B缓存，最后仍有数据；不是8秒停收。第3轮收齐
47360样本及response.done，校验拒绝8字话题。三个作业都不能作为有效网络
对照；没有取消并不说明网络已经修好。SDK最低46988B、网络栈2388B，不能
与上一组不同路径的45088B直接计算优化百分比。无观察到复位、DMA丢失或
灯效；本组underrun0。23.25秒原始实录保留。

按预先门槛跳过普通199声学组，回退本次参数。下一步应先修复候选完整性与
句号的耦合，以及有来源的中性接话与格式约束之间的失配，保持最终意图校验，
否则对网络做更多随机三轮也很可能没有覆盖待验证分支。
