# 音频驱动的预备回答实验

状态：0.11.77-audio-draft 已完成主机检查、构建及六轮实机实验，**未通过
提速验收**。已恢复冻结的0.11.72-summary，fast/capture监听、reuseON、
prefetchOFF、灯关闭，COM已释放。正式安装包保持0.9.0。

## 已核实的协议行为

同一份6.536秒纠正灯色录音，分别测试普通提交、直接基于未提交音频
生成、把临时转写加入提示词生成，各一次。音频直接生成已能理解最终
绿色要求，无需把临时转写变成系统提示。但是随后再生成一次，模型会
询问还有什么需要帮助，不能把它当作对原问题的重新回答。

独立追加一次有界试验：音频上传后发生成请求，200ms尾静音后在生成
期间提交完整输入；只保留一个回答。最终ASR绑定提交确认的item_id，
完整输入与回答均通过协议检查。首次PCM晚于原文件结束，因此这不是
设备已达到一秒响应或在真人说完前备好答案的证明。

证据目录：`artifacts/voice-fast/draft-source-01177-{none,audio,text,overlap}-01`。
完整原始文件、事件和失败情况均在本机保存，未覆盖旧实验。

## 设备实现与边界

- 不再把临时ASR写入系统角色；产品提示词固定。
- 已确认人声后，源音频连续240ms判为安静，且人声与尾部静音已上传，
  最多发起一次异步回答，静默缓存。任何越过已上传边界的新阳性帧使它
  永久作废。分类器仍可能误判，因此这只是可测量的候选机制。
- 保持录音完整，采集成功结束后提交一次；允许提交与候选生成并发。
  只有最终ASR、响应身份、完整音频及业务约束通过，才能播放候选。
- 不执行猜测的工具。灯控回执中的颜色、数字及开关参数被拒绝；
  实际操作由完整最终意图决定。失效回答关闭会话后交给现有DeepSeek链。
- 借用已有40KiB空间，不新增PCM常驻内存、任务或TLS连接；分区和上下文
  不变。取消、空输入、损坏、异常结束仍有边界检查。

保留所有失败，不靠重复择优。采集外部声音并以本地ASR和信号分析辅助；
主观听感未验收。一秒有效回答、48KiB最低堆仍须独立测量。
若退步或没有有用的提前回答，恢复已冻结72应用；正式安装包不推广。

### 测试判定脚本的修正

原灯控report.json前两轮complete=false，因为内容检查把**最终ASR之后
普通模型生成的正确绿色回执**也当成预判参数。该条件过严。修正为仅
对omni_manual_draft禁止任何颜色；普通正式回执仍拒绝错误颜色，但允许
正确绿色。新增对应反例测试。原始两条false记录保持不变，派生审计同时
保留content_check与content_recheck；六轮内容复核通过仍不改变速度失败。
这不是重跑或用修改后的脚本覆盖失败行。
