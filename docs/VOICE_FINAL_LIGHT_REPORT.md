## 行为和边界

已有链路能在收音尚未提交时，用部分音频请求千问生成候选，并在本地静音
缓存。完整转写到达后才决定是否采用。候选文字、音频和工具提案均不能提前
改变设备；已播放的内容无法撤回，所以改口检查必须发生在播放之前。

本轮新增：完整收到“把灯调成蓝色，不对，不要蓝色，改成绿色”后，直接
解析最终绿色，关闭旧模型连接，再通过原有工具校验、硬件接口和日志执行。
成功后播放已有完成语音，省去再次调用 DeepSeek 的等待。最多接受三次明确
修正；否定、条件、问题、额外动作、未知尾句及未完成的改口继续走原有处理。
这只是有界语法，不是通用语义理解，也无法补回被 VAD 提前切掉的语音。

复核发现 87 对修正标记后的分句边界要求不足：“不是改成绿色”可能被误当
作“不是，改成绿色”。88 强制要求该边界；无法区分时不本地执行。普通话、
粤语否定及旧蓝色工具提案均有主机测试。88 没有新增实机试验，不能引用 87
的结果宣称自己已通过实机验收。

## 验证结果

87：50 项 ASan/UBSan 主机检查全部通过，11.36 秒；应用 1,531,600 B，较 85
增加 432 B。88：50 项全部通过，12.72 秒；应用 1,531,616 B。两版正常及
关闭音频构建通过，关闭音频应用仍为 1,065,792 B。无新增运行缓冲或任务栈；
2 MiB 上下文分区、200 KiB 历史预算、448 KiB 录音槽及分区布局保持不变。

87 只做以下两组三轮连续测试，唤醒语言为普通话、粤语、普通话；业务正文
均为同一份已保存的普通话合成语音。轮间没有切换监听，也没有等待预连接。
实际轮间间隔为 265–266 ms。没有以新试验替换失败轮次。

六轮首次唤醒均成功，完整输入和任务为 5/6。第二轮改口已上传 149,504 样本，
在 `capture_joined` 返回 timeout，没有完整 ASR；缓存中的蓝色话语没有播放，
也没有灯控效果。该次缺少逐帧诊断和独立保存的设备录音，不能断言具体坏帧
或把故障归咎于模型。第三轮外部输入一频带相关系数 0.340，未达到原有 0.65
门槛；即使工具及语音成功，也不给这一轮报延迟。

唯一可报告延迟的改口轮为约 2.57 秒；历史 84 三轮相同输入约为
10.638 / 9.282 / 9.865 秒。它说明可省掉一段等待，但不是随机对照，也不是
稳定提速比例。外录由本地 SenseVoice 和信号分析验证，排除结束咻音；数值
仍是起声候选，未作人工听感或精确首音素验收。

自我介绍三轮均采用候选，首个 PCM 分别在收音 join 后 46 / 464 / 292 ms
到达；第一、三轮在完整 ASR 到达后 3 / 2 ms 提交 PCM，第二轮还等了 168 ms。
这证明异步生成和最终核对能衔接，**不能证明短句说完前已经备好有效语音**。
USB 观察时间还可能因主机播放时未读串口而成批出现，不能拿该时间推断提前量。

累计最低堆 36,496 B，主栈剩余 1,796 B、网络栈最小 7,280 B；DMA 丢失为 0，
没有观察到复位。48 KiB 和稳定一秒两项仍失败，也没有长期无泄漏结论。
后续瓶颈包括收音结束/清理、最终 ASR 以及资源余量，不能只靠候选话语掩盖。
