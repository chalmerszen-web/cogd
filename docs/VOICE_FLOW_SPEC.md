# 双语唤醒与端到端流式提速

2026-09-22。基线为当前实机 0.9.0-qwen-stream；用户反馈普通话唤醒失败、
唤醒后准备与 VAD 收尾慢，要求普通话和粤语均可唤醒，录音期间异步连接
ASR，并让 LLM 的流式文字直接进入语音合成。

## 需求与验证

- VF-01：分别检查普通话和粤语“你好，小言”的模型分数与声学回放命中。
  保留原模型与参数；使用多个独立声源，分别统计漏唤醒、近似词误触发、
  唤醒词音频结束到检测的延迟。合成或回放测试不冒充真人泛化证明。
- VF-02：唤醒命中后有界准备并开始录音，不等待远程 ASR 握手。连接在
  后台进行，使用已持久发布的音频前缀补送；网络故障、取消不能死锁、
  丢开头或重放已不确定提交的请求。分别测录音开始、连接与首音频上传。
- VF-03：分离源音频时间、VAD 推理积压和网络竞争，缩短实际说完到采集
  结束的时间。保留人声确认、CRC、最大录音时长，检查短词、句中停顿、
  静音和连续语句，不能仅降低静音阈值或把调度等待从统计中移走。
  云端结束提示必须带句 ID 和有效源时间，并经过 160 ms 观察；新句文字
  或停顿后重新开口使旧提示失效。使用新采集的 20 ms 帧，不能使用积压
  推理的静音统计。时间缺失或源时钟不连续时仅关闭云端辅助，本地规则
  继续负责收尾。该规则需单独做实机句中停顿验证。
- VF-04：保留 DeepSeek SSE 与非流式诊断；实现最终回答文字到 TTS 的
  有界流式交接。工具参数完整校验和执行结果仍决定成功播报；记录首文本、
  首 TTS 提交、首 PCM 和 LLM 完成，证明合成/播放与回答生成实际重叠。
- VF-05：网络准备按依赖与可用内存排程，优先 ASR。尝试重叠下一阶段
  连接，测量 TLS 峰值，不以同时空开所有连接挤占录音与 DSP 所需资源。
  无需电脑或外置网关参与正常对话，证书和主机名验证保持开启。
- VF-06：C11、现有 2 MiB 上下文分区、200 KiB 历史预算、音乐/灯/GPIO
  和存储数据不变；备份后只更新应用。持久任务不自动重放。
- VF-07：主机覆盖流式回调、缓冲所有权、分片、背压、错误和取消；实机
  覆盖双语唤醒、匹配对话耗时、长回答首句、句中停顿、无声超时、取消、
  资源回收和重启。按新增证据决定是否扩大测试，禁止无因重复长批量。
