# UX116：设备端候选回复跨轮复用

2026-09-28。153实验版已经烧录并完成两组各三轮的扬声器/麦克风测试。
第二、三轮直接回答确实复用同一条千问连接，减少了重新连接的等待。
自我介绍的外录起声估计降至1.22/1.09/1.05秒，**尚未达到稳定一秒**。
记忆任务仍有较长的正式回答等待，因此没有推广为完成版。
设备已恢复`0.11.72-summary`联网监听；153源码、固件、原始录音和失败记录保留。

## 实现

候选工作线程完成直接回复后，先等待最终输入、播放结束及任务加入，再转移连接归属。
仅独立的1080B状态保存区跨轮存活；清除采集工作区中的回调、scratch、transport和sink指针。
下一轮重新绑定这些指针，保留输入ID、响应ID及发送序号，不重复配置或重新握手。
最多三轮，空闲保留有期限；取消、过期、配置改变、改口、错误和普通任务均释放连接。

成功的直接回答可以保留连接。转交DeepSeek的准备语不能同时保留它，因为正式TTS要使用
同一个primary传输槽。没有增加第三个网络槽、保留整个工作线程栈或扩展PCM缓存。
若保留TLS导致Agent工作区恢复失败，会释放该连接，再尝试一次本地工作区分配；
不会重放用户请求、音频或工具动作。

65项ASan/UBSan主机检查通过，24.17秒。新增检查使用实际候选适配器，释放旧工作区并在
不同地址分配下一轮，覆盖三轮一次连接、第四轮新连接、旧ID/PCM、发送序号连续、取消、
过期、设置改变、普通任务接管、改口、分配/持久化失败及线程创建失败。
最初两项测试失败来自测试计数器没有按新轮次重置；修正计数后全部通过，失败日志保留。
检查还发现并修复了跨轮发送序号会重置的问题。

## 应用空间与TLS

首次构建1541232B，超过原1540096B预算，没有烧录。随后尝试对控制代码使用`-Oz`，
构建仍超预算至1541744B，未采用，编译优化已恢复原设置。采样、渲染、DMA、唤醒、
VAD及TLS算术优化没有改动，未通过降低上下文容量解决空间问题。

最终使用当前固定ESP-IDF自带的常用根证书集合：38个根，生成包15905B，原完整包66984B。
电脑仅用这份集合、开启证书和主机名验证，对DeepSeek、千问、Vocalign各完成一次TLS握手；
没有系统根证书回退、Key或应用请求。板上实际ASR、候选生成及DeepSeek/TTS调用继续成功。
Vocalign本轮只有电脑TLS验证，没有额外板上语音调用。

这是信任根集合的缩减，不代表任意公网CA都受支持；以后接入新服务或更新固定SDK，应运行
`tools/voice/verify_public_roots.py --out <新的输出目录>`并验证设备连接。Gateway独立CA配置保留。

`0d53a79f0d43cc002ea5971c3d1397e80104a5671a025233c9a07333b3dda6b6`。

## 六轮实测

每组按普通话/粤语/普通话唤醒，业务句子为普通话。沿用固定源音频和0.25增益，
下一轮在上一轮结束约250ms后开始；无额外诊断停顿或失败重跑。
六次首次唤醒成功，六轮均`@done`，未观察到复位、看门狗、DMA丢失或播放欠载。
这些是固定声音的有限实验，不是新的真人泛化证明。
