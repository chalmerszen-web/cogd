# UX152：为首请求并行拆分序列化接口

2026-09-29。源码已更新为 **0.11.190**：上下文前缀可以逐段写出，原生用户
输入可以直接写入日志事件。改动前后 12 份实际构造的 HTTP 请求共
**1,808,879 字节，逐字节一致**，最大请求 219,929 字节。
设备仍为 0.11.72-summary；本轮没有烧录、云调用或音频测试。

这解决了上一轮内存诊断指出的一项前置依赖。**尚未接入接话与正式请求
并行，也没有测得设备响应提速。** 当前普通对话仍分配原来的完整工作区，
不能把下面的主机结果当成已经节省了整轮 29 KiB 或达到一秒回复。

## 改动

- `core/json.c` 增加同步的 JSON 字符串写出接口，先验证 UTF-8，再按最多
  4096 字节的块输出。复用原有转义规则，遇到首个写入错误就返回，不补写
  结束符或自动重试；原缓冲写入接口保留。
- `plugins/llm/deepseek.c` 将普通消息字段写出集中到一处，存入消息数组和
  直接写出完整消息对象共用该逻辑，保留原工具调用 ID。
- `plugins/context/context.c` 将 system、保存的事实和历史摘要整理为同一个
  顺序访问函数。原来的存储式提示词和新的流式前缀使用同样的内容与顺序。
  新接口保留 16 KiB 消息容量边界，使用原上下文 scratch，不分配堆内存。
- 原生用户输入直接在原事件封装中引用和转义文本，省去中间 content JSON
  对消息工作区的依赖。输入仍限 2 KiB；拒绝与上下文 scratch 重叠的输入。
  自定义 append 适配器仍收到原有 content JSON，没有改变插件函数表 ABI。

没有新任务、库或常驻大缓冲。事件序号、CRC、历史选择与回放、工具校验和
取消机制保持原有契约。直接输入落盘仍使用既有 JSON/WAL 实现；“前缀写出
不分配堆”不代表整个事件存储或历史回放完全不分配堆。

## 证据与边界检查

生产代码改动前，先给原 `long_prompt` 主机套件增加可选请求留档，收集其
实际 HTTP producer 输出。改动后复用同一组固定输入、历史和时钟，所有
12 个文件的长度、字节和 SHA256 相同。请求包含长历史、工具配对、重试和
自定义 replay/composer 路径；测试只连接模拟 transport，不发送云请求。

新增检查还覆盖：

- 固定种子生成的 64 组 UTF-8/转义文本、全部非 NUL 控制字符、跨 4096 字节
  边界的中文、每个输出回调处的失败，以及无效 UTF-8 不产生字符串输出。
- 同一 scratch 中的 system 文本必须先消费再复用；事实 tombstone 和摘要
  顺序不变。前缀调用期间包装 malloc/calloc/realloc，若分配则测试失败。
- 精确 16 KiB 消息边界及多一个字节的拒绝；原容量没有缩减。
- 不持有 engine/messages/reply 工作区的 producer，组合前缀、Flash 历史
  和完整用户输入，得到 **204,125 字节**相同消息；仍使用 204800 字节历史
  预算。测量长度一致，取消、CRC 损坏和锁定期间的写入均覆盖。
- 新旧用户事件路径的完整 Flash 字节与事件 ID 一致，包含最大 2 KiB 输入、
  最坏控制字符转义、WAL 写失败、ID 缓冲不足、无效输入和别名拒绝。
- 自定义 append 仍被调用且收到原 JSON 内容。

全套首次运行 67/68 通过，唯一失败是新测试错误地假定“设置扫描取消标志
后，普通用户事件 append 必须拒绝”。检查既有实现后，改为验证新旧路径
一致保留收到的输入，并另外验证请求测量及历史回放的取消；没有修改生产
取消语义。修正后的新套件通过 ASan/UBSan，用时 0.17 秒。另保留新 fixture
初次未显式格式化空 Flash 的失败及修正记录。其余 67 项已通过的生产代码
在修正测试期间未变，没有为这些修正重复整套运行。

硬件快照，保持原输入落盘和容量检查，在正文发送完成后等待候选退出，
