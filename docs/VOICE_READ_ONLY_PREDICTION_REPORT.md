## 唯一一组三轮实机

仍用先前同一份Huihui合成“现在灯是什么颜色？请简单回答。”，播放增益0.25。
普通话/粤语/普通话唤醒，业务输入均为普通话；idle预连接、prefetch和reuse开启。
没有轮间导出、额外静默等待、补播补分或改变声学对齐门槛。

三个候选均按实测RGB=0/0/0提交“现在灯是关闭的”，模型却生成“嗯，我来调整一下灯光。”。
精确文字检查全部拒绝，**这些错误候选没有播放、没有执行灯控**。三轮分别回退一次
DeepSeek请求，都以`@done`结束，首次唤醒3/3；不能因此把错误候选PCM算作已回答。
三轮ASR都保留了核心问题，但均缺少“请简单回答”，严格完整输入仍0/3。

外录42.85秒，固定全句对齐未通过，实际声学答案延迟保持unknown。上表是软件事件，
负值表示候选PCM早于上传结束标记，不是早于真实人声结束的已验证声学时间。
没有观察到复位、WDT、panic或DMA丢失，SDK历史最低堆48780B，仍低于48KiB的49152B。
三轮和此前203组不是随机实验，不由单组波动宣称整体速度或内存收益。

## 提示词冲突诊断与有限退出

205新增的固定答案规则与旧“没有待续标记才按灯光准备规则回答”发生重叠。206仅在
工作树中将提示词改为互斥分支，先使用相同模型、声音和输出格式在电脑验证，未构建、
未烧录，也未再次跑硬件组。第一次启动因IDF Python没有websocket依赖停止，未读Key、
未建立会话；该空报告保留。改用已有语音环境后实际建立两个会话：

- 普通话关闭状态：模型将说明“这是灯状态查询的已核实答案，不是调灯指令”也念出，
  输出5.52秒、估算IMA缓存44160B，超过设备24576B；精确内容检查失败。
- 粤语红色状态：尚未完整结束即达到本机192000B PCM上限，原始已收数据194560B保留，
  按既定上限退出。第三个预定兼容用例未执行，没有重试未完成会话。

因此停止这条提示词改写实验，不放宽文字检查、不增大缓存、不再扫描提示词。
固定的状态答案应使用明确的TTS文本输入，避免通用对话模型重新解释播报内容；这是
后续实现方向，**本轮没有声称该替代已经部署**。一般问题的投机回答仍需完整输入验证，
工具动作仍应在确认最终意图后执行。
