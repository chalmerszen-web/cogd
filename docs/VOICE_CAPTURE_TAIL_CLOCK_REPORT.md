# UX189：三轮采集、提交与提示音时钟

2026-09-30，完成一组固定三轮诊断，未改变端点或提速逻辑。
设备已恢复0.11.72-summary，联网fast/capture监听、reuse开启、prefetch关闭、灯灭，COM5释放。

## 实机发现

| 轮次 | 录音提交墙钟(ms) | 提示音流程墙钟(ms) | 采集结束到收尾(ms) | 上传EOF到最终ASR(ms) | 最终ASR到首PCM(ms) |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1 | 169 | 360 | 530 | 266 | 80 |
| 2 | 179 | 361 | 540 | 510 | 14 |
| 3 | 175 | 360 | 536 | 200 | 128 |

EOF在采集结束后0/1ms发布；三个物理停止/确认join时钟在毫秒精度下相同。
上传实际到EOF晚194–230ms，ASR结束与提交/提示音流程已重叠，不能相加为总延迟。
第三轮ASR比提示音收尾早106ms，仍等音频所有者join后才允许最终动作。
第二轮云端结果比提示音收尾晚164ms，此轮14ms的本地回复处理不是主要等待。

169–179ms是完整录音提交函数墙钟，包含packed解码、原PCM及编码CRC校验、Flash读写和调度，
不能全部归为Flash耗时。360–361ms是`wake_cue(true)`墙钟，包含冷输出静音预热、180ms扫频、
零尾和DMA提交等待，不能说咻声本身长360ms。旧180ms最低静音预热没有缩短。
该阶段定位了约半秒的明确本地收尾，尚未减少这段时间，不能宣称提速。

首次唤醒3/3(中/粤/中)、最终只执行绿色且读回3/3、@done3/3；第二轮云文本漏“请”，
严格全文2/3保留失败。候选request/PCM缓存仍0。最低空闲堆62212B，DMA0，未观察到
协议错误、看门狗或复位。只是一组固定合成源，非真人泛化或复杂LLM验收。

## 声学结果仍未知

原始32秒级外录及来源文件保留。原固定三频带/共同偏移检查仅一轮通过，
共同对齐需要至少两轮：第1轮高频相关0.629低于0.65，第3轮中频0.481低于0.65。
不降门槛、不追加组，三轮实际有效答复起点均unknown；不能以首PCM替代声学结果。
离线收尾工具仍可独立审计板上时钟，声学字段全部null，未把未知来源提升为有效延迟。

## 诊断契约与改动边界

诊断构建0.11.214-protocol-diag复现UX187端点消费者/header/helper的字节SHA，
保持本地优先、输入/工具准入、栈、上下文和分区。新增默认OFF计时开关，只有24B静态时钟；
无新增任务或自有堆缓冲。收音中不新增USB输出，ASR与采集join后复用已释放scratch发一个tuple。
仍有少量计时指令及一个收尾事件开销，所以不能当零扰动测量。

`capture_tail_v1`的text是11个非负uint32数组，依次为：

| 索引 | 字段 |
| ---: | --- |
| 0 | record_at：开始采集 |
| 1 | stopped_at：麦克风关闭返回成功 |
| 2 | end_at：确认任务join、采集结束 |
| 3 | eof_at：完整尾部flush后EOF发布时刻 |
| 4/5 | commit_begin_at/end_at：录音校验/头部提交前后 |
| 6/7 | cue_begin_at/end_at：结束提示音函数前后 |
| 8 | cleanup_at：录音所有者收尾 |
| 9 | samples：本轮保留原始样本数 |
| 10 | error：最终采集错误 |

零时刻为缺失，不能替代有效结束；记录在join后回报，其USB收到时间不能当声学时钟锚。
审计要求一个trace、明确录音身份、ASR已上传样本数一致、无错误及顺序/35秒本轮边界；
中途/重复/布尔/反向/错样本trace不使用，不能由最后快照遮盖坏trace。支持uint32回绕。

正常/诊断/无音频构建通过，诊断应用1503184B，在原1540096B应用预算内。
9项收尾身份/时钟检查及6项提示音检查通过；初版8项日志保留，新增的是共同声学对齐失败时
只保留板上遥测、不得生成声学成绩的检查。此前固件逻辑测试没有变化，不重复旧73项作新功能证明。

## 备份、回滚与后续

两次flash_guard均全4MiB备份/设备验证，只写应用、读回且全部非应用区相同。
历史1209→1215事件、856696→860288B，新对话保留；恢复前后全部context统计一致。
六临时源文件按冻结SHA检查后恢复，407份当前基线代码一致，默认OFF本地优先保留。
默认重建应用SHA `05fcd2b04adfa7c38a1ab428b5b20da180a46e7332e7ad1c999e0a12b8f9b0ed`；
与试验前hash不同，未宣称二进制字节相同。设备实际使用的72包hash保持
`22faca4f0c6bf12030d924db38904d330af9585493ea307e29f18d4da2309c07`。

下一项有限候选是让扬声器数字静音预热与已停止采集后的录音校验重叠：保持完整CRC/提交、
完整咻音和最低预热，最终输出/工具仍等采集成功join；不继续扫VAD门槛。现有PDM通道
预装零并自动清零提供技术条件，但提前分配驱动资源会改变瞬时内存重叠，须单独验证。
该候选尚未实现或实测，不能认领169ms改善；稳定一秒及复杂接话目标仍未完成。
