# TLS 协作调度有限实验（UX249，2026-10-02）

当前模型的误唤醒未修好。本阶段只改候选连接调度：唯一一组中／粤／中三轮首次唤醒、完整输入与记忆业务均通过，动态应答候选三次采用。但 ASR 连接变慢，最低堆仍未达标，未将实验固件设为用户默认版本。

固件 `0.11.249-cooperate`，应用 1502432 B，正常预算 1540096 B，余 37664 B；SHA256 `e5f0e22bac5d574c4b033c2d72095482f49dcbdadb9e425726c401de94c10b3d`。冻结 489 文件、核对此前 395 编译输入，新输入另列，不将整个快照称为编译文件。源码包 SHA256 `545aab08cfe333c2f62b35ac6671db1b8a9f5e3781a47bd693ecd19f5a054e95`。分区表 SHA256 `03135fff90b8a4983a4a7a758018626dc296756ac79578e5df9c7b8eb64b3179`，2 MiB 上下文、204800 B 历史预算及录音分区保持。

## 实际代码变化

默认关闭的新选项 `AGENT_TLS_COOPERATE` 对固定 SDK 的原 `mbedtls_ssl_handshake_step` 调用前后加回调；原状态机、加密、证书及主机名校验保持。适配器要求精确源 SHA、仅一处调用，变更 SDK 时拒绝生成；只写构建目录，已安装 SDK 未修改。候选连接在同优先级 4 与 ASR 协作，每个返回的 TLS step 后让出一个 tick，连接结束恢复原优先级。其他任务的回调无动作。链接检查确认实际握手中两处回调，没有把 LTO 消失的包装函数当成失败的实现。

九项 ASan/UBSan 主机检查通过；SDK 原文／CRLF 接受及变更拒绝的适配器检查修复后单独通过。初始 include 路径、CMake 分号计数及严格 C11 的 SDK `asm` 兼容失败日志保留；不能称首次或一整组十项一次通过。首次 LTO 包装符号验证错误已修正为真实链接检查，未重编译或重放三轮来换结果。

## 唯一实机组

三轮均使用公开输入“请记住，我给这盏灯取名叫小星星。”，最多一次唤醒、无重试、后两轮与上一轮 `@done` 间隔 265／266 ms，无轮间诊断或 ready 等待。实际输入完整、记忆读回一致、流式 ASR／LLM／TTS 成立。

UX247 历史候选连接约 5.49–5.76 秒，本次约 2.39–2.42 秒；但是 ASR 从约 1.13–1.21 秒变为 2.33–2.41 秒。不是同一网络条件的受控 A/B，不报告因果提升比例。step 墙钟含网络等待／抢占，不能叫纯加密 CPU。

最低堆 47360 B，要求 49152 B，缺 1792 B；KWS 最长 8060 µs／32 ms，DMA 丢样 0，该组未观测到 watchdog／panic／复位。三轮不足以证明所有取消、长语音及长时间稳定性；未改候选 500 ms 等待或牺牲上下文容量。

## 实录边界

三次输入均通过既有固定波形对齐门槛，本机独立 ASR 确认动态应答“嗯，我来记一下。”及最终回复“记住了，这盏灯就叫小星星。”。从真实输入活动结束到应答的能量起声候选为 3.656／4.427／3.585 秒，最终为 7.116／8.177／6.935 秒。动态应答声学接受标记仍为 false，能量点不是已认证的首个有效音节；保留缺失，不放宽门槛将软件 VAD 后时钟冒充真实一秒回复。没有主观听感通过结论。
