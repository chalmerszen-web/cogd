# 误唤醒测试的采放链路校验

2026-10-04，UX513。**误唤醒仍未修复；本次没有训练或采用新模型。** 当前设备已恢复 `0.11.72-summary`，自动唤醒及自动语音暂时关闭，USB 文本交互可用。

此前 UX510 两个实际播放的测试句未通过波形归因，完整输入和完整对话均失败。本次检查其中一种可能：当前电脑播放到设备收音的链路是否能够可靠保留测试句。没有重跑失败的对话组，也没有放宽原门槛。

复用已冻结的 `0.11.471-wake-input` 诊断应用，只导出麦克风送入关键词模型的输入。诊断抑制提示音、录音、后续语音业务及工具动作。使用 UX510 实际播放的同一个 3.68 秒 WAV，以原来的 0.35 增益，在唯一明确匹配的 `Misiom-Shooter` 输出端播放两遍；开启输出后再次验证实际句柄名称。外部麦克风同时以原 DirectShow 配置采集，不更改端点音量或进行自动归一化。

## 结果

共保留 640 个实际输入块、327680 个样本、20.48 秒标称时长。全部序号、CRC、512 样本时钟及原始三头元数据完整；丢帧、DMA 丢失、错误、复位和满幅削波均未出现。最长关键词推理 14.141 ms。这些检查只证明本次诊断输入连续，不能替代正常语音业务的资源验收。

按原有三频段波形／包络及重复播放时钟规则核对：

| 录音 | 第一遍高两频段波形相关度 | 第二遍高两频段波形相关度 | 固定归因门槛 |
|---|---|---|---|
| 外部麦克风 | 0.761 / 0.789 | 0.736 / 0.854 | 两遍均通过 |
| 设备关键词输入 | 0.574 / 0.212 | 0.524 / 0.213 | 两遍均失败 |

设备高两频段的包络相关度分别为 0.883 / 0.913、0.836 / 0.960，未将较强包络匹配替代较差的波形匹配。外部录音通过说明两遍测试句在外部麦克风位置确实可被可靠归因；不能据此认定设备噪声、麦克风位置、采样时钟、频率响应或环境中的某一种是唯一原因。也没有证明 UX510 正常业务中的输入失败已修好。

本次没有新的 ASR、LLM、TTS 请求，没有误唤醒率、真人双语泛化、三轮连续对话、整轮最低堆或一秒回复通过的结论。此前同板近似词误触和所有被拒绝模型继续保持失败。

## 保留与恢复

安装和恢复均先执行 `flash_guard.py` 的新鲜 4 MiB 备份与验证，只写应用并读回验证。试验前后 2 MiB 上下文和 448 KiB 录音分区逐字节一致；1385 个事件、940428 B、next4612 及 204800 B 历史预算保持。最后四项新的 USB 只读查询确认原应用、空闲、自动唤醒／语音关闭，串口释放。

初次登记误把顶层的原始素材摘要当成实际播放 WAV 摘要，校验在 USB、烧录和播放之前拒绝。核对 UX510 两次实际播放回执后，修正为已生成的同一个播放文件；没有换素材、重新处理 WAV 或重复声学试验。原失败记录保留在 `preflight-error.json`。
