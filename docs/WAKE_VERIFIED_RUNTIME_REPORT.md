## 实现

原24通道E/L保留各自的因果卷积历史，增加固定48通道验证器。
三者的输入归一化参数相同，所以每个256样本帧只计算一次FFT和log-mel，
再调用三次整数网络。原E/L平均、三块平滑及原事件拥有权保持；
验证证据可位于原合法事件前后256ms，禁止验证器单独触发业务。
任何16ms半帧进入unarmed都会立即清除投票及待确认事件；时钟间断先复位再处理输入。

独立初态导出工具实际运行128帧zeroPCM，再输出字段明确的C常量。
24通道历史紧凑存储，48通道历史保留完整；不导出指针、FFT临时缓冲或主机对象字节。
消费方必须包含源码与模型SHA256检查；过期初态会使构建失败。
仅fresh init且模型指针匹配、尚未改变阈值/稳定设置时才能恢复初态。
运行时恢复不执行FFT或网络推理。随后把32768的虚拟样本时钟带入实际输入。

该功能通过`AGENT_KWS_VERIFIED`显式启用，默认关闭。
要求编译容量48、注册24混用、训练权重和初态恢复，不与旧fusion/probe/stable混用。
资源诊断另使用`AGENT_KWS_VERIFIED_RESOURCE_ONLY`：照常计算并计数检测，
麦克风命中不启动录音、网络请求或动作；USB输入仍核对完整因果判定。
该诊断标志不能用于声称真实业务唤醒成功。

## 主机证据：UX279

62,206帧、186,618个raw head、16,484,590个首模型有效层值，与UX278独立网络计算完全一致。
包含随机及极值、512PCM帧及恢复后的PCM/特征流、103条已知TRAIN实长流；
后者保留512/656帧几何和实际长度，未读取DEV或项目独立TEST。
平滑分数及UX277因果控制事件逐帧一致。
初态恢复与实际128帧预热的所有因果字段相同，恢复时0FFT/0NN；
ASAN/UBSAN、哨兵、禁止堆分配、错误参数/模型、未训练禁止输出、间断/取消及过期hash检查通过。

| 数据 | 主机64位 | ESP32-C3目标32位 |
|---|---:|---:|
| 指针 | 8B | 4B |
| 单handle（含FFT与48容量网络） | 11,952B | 11,952B |
| 三模型共享运行时 | 24,328B | 24,320B |
| 无指针初态常量 | 12,992B | 12,992B |

handle内的样本计数结构按8字节对齐，目标指针缩小被padding抵消；
三模型运行时另外两个模型指针使总大小减少8字节。
目标尺寸由实际IDF C3编译命令的静态断言确认，不用主机sizeof冒充设备测量。

首个主机生成命令遗漏frontend对象引用的PCEN链接依赖，exit1发生在数值测量前；
原日志和源码保留，补依赖后唯一resume通过。模型及判定规则未改变。
