# UX113：提前备答与扬声器输出接续

本阶段完成有限实验，**未验收、未推广**。151已验证同一轮输出复用，正确灯控一轮的
本地播放启动等待为11ms；但三轮改口仅一轮收全，另一轮误设蓝色。自我介绍外录起声
估计1.08/1.68/1.88秒，仍未达稳定一秒。设备已核验恢复`0.11.72-summary`监听；
151源码、冻结包、失败录音及速度表保留，正式安装包不变。

## 与“边听边猜”的关系

实验路径已有流式ASR、关键词提名、异步千问备答和音频缓存。完整输入通过校验后才
播放候选或执行工具；改口、缺参、取消及不匹配候选进入撤销或正常处理路径。
本次继续检查候选准备完毕后，设备自身是否还在重复等待。

这套校验依赖输入完整：本阶段一轮云端最终转写只有“把灯调成蓝色”，设备执行了蓝色，
用户测试音频后面的绿色要求没有进入最终转写。**最终文本校验不能弥补没有收全的语音。**
不能把这轮的快速执行算作体验成功。

两版六轮自我介绍的候选都成功采用，但第一包候选PCM均在最终ASR之后才到达：
150晚164/979/843ms，151晚238/635/914ms。因此，这组短问题尚未实现用户所说的
“说完前就把响应包抓下来”。长改口测试存在提前收到候选PCM的情况，但明确灯控最终
走本地确认，不使用该候选。没有把这些情况合并为笼统的预测命中或一秒通过率。

## 改动与失败定位

150在成功的实时采集结束提示音之后，短暂保留已启动的PDM/功放，利用DMA自动清零
保持数字静音。音频任务仍独占驱动；同采样率回复接管，取消、网络所有者释放或两秒
未被接管时关闭。两秒是音频任务下次空闲检查的到期条件，不是硬实时释放承诺。
冷启动的200ms预热保留；未在完整输入校验之前发出回复或执行工具。

150六轮实际接续计数为零。随后核对实际头文件发现：`realtime.h`与`progress.h`中
回复均为16kHz，提示音仍为24kHz。此前按24kHz回复设计的假设错误；采样率保护正确
地关闭并重开了通道，所以本地等待仍为161/161/160ms。

151把隔离ASR构建的提示音改为协商的16kHz；其他构建和音乐仍使用原24kHz路径。
提示音生成移入小型C11渲染函数，保持开始音160ms、结束音180ms、音调、10ms起音
包络及40ms零样本尾部，处理16kHz下不足240样本的末块。无新增大缓冲，渲染不分配堆。
保留驱动会改变阶段之间的瞬时内存重叠，不能据此宣称完全没有内存成本。

状态增加`output_held`和`output_handoffs`。151六轮共接续五次；需要较慢澄清的一轮
未复用。所有测试结束后`output_held=false`。错误关闭会先清除采样率标记，防止把
关闭失败或被静音的通道当作已准备好；停止操作也等待保留输出释放。

## 有限实机结果

最初计划为两组普通对话加一组取消诊断，共九次。发现明确采样率不匹配后，仅追加
151两组三轮，共15次；没有继续重复调参。每组唤醒音依次为普通话/粤语/普通话，
业务问题是固定普通话合成音，不代表粤语对话或独立真人泛化验收。

| --- | ---: | --- | ---: |
| 150 蓝改绿 | 3/3 | 三轮均收全改口、只设绿色；均缺“请”，严格文字检查失败 | 0 |
| 150 自我介绍 | 3/3 | 三轮完整输入及回复通过 | 0 |

| 151 蓝改绿 | 3/3 | 第一轮停在“不对”并澄清；第二轮设绿；第三轮仅转写蓝色并误设蓝色 | 2 |
| 151 自我介绍 | 3/3 | 三轮完整输入及回复通过 | 3 |

普通组保留约250ms后再唤醒的原流程，没有逐轮导出录音或插入诊断查询。
取消组使用高频状态查询，不能用于普通延迟/连续再唤醒验收。三次观察到保留状态后，
取消确认耗时32/32/31ms，观察到输出释放耗时63/63/62ms；这是150的24kHz保留输出测试。
两秒空闲到期没有单独连续采样，不能作为硬实时时限已验收；有限轮数也不证明长期稳定性。

首批PCM写入不是人耳起声，上传EOF也不是用户最后一个音节。网络会话之间有波动，
这份数据证明了本地重复预热可以省去，不证明整体延迟有稳定固定比例的改善。
151改口组的整组录音模板匹配未过固定门槛，因此外录延迟全部保留为未知；没有降低
匹配门槛或挑选片段补出成绩。150改口组第二轮同样未得到可信起声候选。

自我介绍外录离线ASR均解出了以“我是”开头的回复，已解码裁剪没有满幅样本。
这只能支持有限的内容/削波检查，不能代替主观音质验收，也不能据此判定没有轻微杂音。

151最后一轮改口录音在覆盖前导出：60288样本、16kHz单声道、3.768秒。离线ASR结果
为“请把灯调成蓝色不对”，与云端最终文本不一致；未获得绿色要求。WAV SHA256：
`3a6f1391e10b70d39c4ff2e610c3306a575b6b246fd4078637af60d8facc630b`。
该证据保留了提前结束与转写差异，未证明更改采样率是失败的唯一原因。
