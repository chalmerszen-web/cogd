# ESP-HI 0.12.0-rc2：语音控制任务的 error limit 修复

2026-10-05，ESP32-C3 / COM5。沿用 rc1 的固定构建配置和唤醒模型。

## 问题与改动

原始录音转写为“你把灯调成蓝色，然后再调成绿色，然后再调成蓝色，间隔是五秒。”设备日志确认：能力查询、启动控制计划、两次即时状态查询耗尽四轮工具调用，第五次请求在 `agent_next_round` 被拒绝，报 `@error limit`。控制计划已启动，错误出现在对话收尾。

- `device_control_status` 对正在运行的任务默认在本地等待至多 15 秒，每 25 毫秒让出处理器并检查取消。可用 `wait_ms=0` 即时查询；超出等待时间返回真实运行状态，不重复执行动作。串口 `agent control status` 仍即时返回。
- 四轮工具调用上限保持不变。流式语音用完四轮后进入禁止调用工具的最终回答，要求明确区分完成、仍在运行和失败；不再请求第五轮动作后中断。
- 控制任务状态附带实时 `light` 数值。计划结束会恢复先前输出，不能把最后一个步骤误报为当前灯色。

## 验证与范围

**已修复本次 `error limit`，尚未修复模型对最终灯色的错误播报。** 三次原始录音复测均无 limit、控制任务均返回 done；交付构建仍说“现在停在蓝色”，但任务结束后的实时灯色为 RGB 0,0,0。中间一轮还输出过 DSML 标记。它们是明确保留的回复质量失败，不能把传输完成当成整轮语义正确；本包仍是用户测试版。

修复后 78 项主机功能回归通过；最终灯色反馈改动涉及的 control、tools、voice_final_stream、tool_repair 四项再次通过。新增检查覆盖五秒间隔序列、等待上限、即时查询、取消、时钟停止前进，以及连续四轮未完成结果的正常收尾。

实机重用设备保留的 7,832 毫秒原始录音，交付构建记录保存在 `artifacts/error-limit-20261005/original-clip-release/`。验证结论及固件哈希以本包 `verification.json` 为准。两个中间构建记录分别保留在 `original-clip-replay/`、`original-clip-final/`。三个目录的 `semantic-review.json` 都明确标记回复失败，未作为整体语义验收。最终回答指令增加直接使用已返回实时灯色、只输出普通话语的约束，但该约束没有消除最终灯色误报。

只更新应用分区；每次烧录先备份、逐字节检查非应用区域，保留联网配置、模型配置、对话历史及录音。没有调整 TLS、安全密钥、证书或 SDK。

这是针对上述错误的测试版，不代表全面产品验收。rc1 的误唤醒、长句截断、一秒有效回复及最低堆目标仍未验收；具体复测资源数据见 `verification.json`。

## 使用与归档

说“你好，小言”后继续测试。需要查看串口时，关闭其它占用 COM5 的程序，再双击根目录 `开始语音测试.cmd`。

- 当前安装文件：`firmware/latest/`。
- 固定发布与源码：`firmware/releases/0.12.0-rc2/`。
- 压缩包：`outputs/esp-hi-0.12.0-rc2-test.zip`。
- rc1 原包：`firmware/releases/0.12.0-rc1/`。
- 构建命令：`tools/build_voice_test.ps1`。

应用大小与 SHA-256 见本包 `manifest.json` 和 `verification.json`；正常应用预算仍为 1,540,096 字节。
