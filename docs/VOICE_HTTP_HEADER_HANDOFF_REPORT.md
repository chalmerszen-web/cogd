# 正式HTTP读头与候选交接：UX158

2026-09-29。诊断196保留在源码，开关默认关闭；本次假设未带来成功交接，
不推广固件。完整语音目标仍未完成。

UX157中只有一轮真正覆盖“预热后继续接收”的成功样本，另两次完整请求并行
后候选接收停止。本轮只试验：在正式请求sent后，先短时间服务其HTTP响应头，
再join候选；不把“未读HTTP导致WSS停顿”预先当成事实。

## 改动及主机验证

仅`AGENT_HANDOFF_PROBE`中新增headers模式与一次性开关。发送内容完全相同，
单次读头超时100ms、外层循环预算500ms；读到头就退出探测，随后调用原交接。
收到正文也不提前feed引擎。SDK保存随响应头一起到达的正文，后续read先消费
这些数据；探测pending时继续同一客户端/解析器，不创建第二个请求。
正式引擎在任一错误出口仍负责join，候选的原10秒期限不续期。

核对的是本地固定IDF源码：`components/esp_http_client/esp_http_client.c`中
`http_on_body`、`esp_http_client_read`、`esp_http_client_fetch_headers`，证据目录
保留文件哈希。500ms是外层循环预算，实际SDK调用时长另由设备时钟验证。

测试覆盖普通时序、读头成功/分片pending、探测预算用尽后接续、网络错误、
取消、交接回调错误、401、一次性开关以及feed前必须交接、正文内容完整。
69项ASan/UBSan通过41.26秒。普通/诊断/无音频构建通过，普通构建不含探测
入口字符串，大小1501568B，与195相同；不增加普通生产路径常驻资源。

## 唯一三作业

| 作业 | 结果 | 实际覆盖 |
|---|---|---|
| 1 | limit | 模型给出8字话题“现在灯是什么颜色”，超出6字限制，未准入后缓存到限额 |
| 2 | cancelled | 候选未完，完整请求已发、HTTP头已读，仍接收停顿到原期限 |
| 3 | limit | 缺句末标点，缓存先到限额，未进入并行 |

第二轮关键证据：候选准备时response_done=false、5120样本。53781B正式
请求在26481ms发出，26629ms记录handoff_headers_ready，耗时148ms；最后
TLS/WS数据27111ms，最后就绪27117ms；候选35189ms结束，最后数据至结束
8078ms。原捕获块在35198ms接管成功。

总计收到20480样本，TLS poll [106就绪,415空,0错误]，58950 TLS明文字节；
0读错误、无半条JSON，response_done=false。最后PCM回调27112→27115ms，
没有占住接收8秒。**确认读到头仍不成功，提前读头本身没有修复问题。**
这不等于排除了正式正文尚未读取、接收停顿长度、缓冲分配或底层TCP状态。
没有把两条未准入候选计为并行测试。

SDK最低堆53768B、网络栈1700B，来自没有真实ASR负载且人工暂停生产者的
诊断，不能标记全负载资源通过。未观察到复位/WDT/panic/DMA丢失/灯光副作用。
外录24.2秒，44.1kHz单声道，音量80；不用于主观听感或一秒有效回答验收。

## 决策

只保留默认关闭的诊断源码，不采用此头部探测作为提速修复。本组三次后停止，
不重跑直到出现成功。下一阶段还需控制两个混杂因素：warm与pass暂停候选
读取的时间不同，pass还新分配请求缓冲。应先做时间匹配/仅分配缓冲的控制，
而不是直接认定HTTP连接、云端或某个TLS缓存有错。当前人工屏障尤其不能
代替正常固件三轮连续声学测试。无标点候选的缓存限额问题独立保留。
