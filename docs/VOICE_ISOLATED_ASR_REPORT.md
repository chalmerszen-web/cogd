## UX57：采用独立连接归属的 C11 模块

新增 `plugins/speech/asr_realtime.{c,h}`，与现有 Omni 解析器分开。实际服务不带
输入 ID 时，以一个新连接只处理一句话来确定归属，不在该连接复用第二个输入。
状态顺序为：核对会话/模型/配置 → 上传 → 成功发送提交 → 提交确认 → 唯一最终
文本 → 成功发送结束 → 服务端结束确认 → 关闭连接并返回文本。

- 临时文本只发出 `asr_partial` 通知，调用方可选择候选，不能据此执行工具。
- 原始最终文本先留在调用方缓冲，直到结束确认才发出 `asr_text`；调用方还必须
  等待采集完整性校验和取消检查成功，才能播放或执行。
- 若服务端提供了 ID，会检查已知 ID 是否相符；没有 ID 时不虚构关联。
- 断流、取消、超时、错误配置、提前/重复最终结果、第二个输入、帧或文本超限
  都关闭连接并清空输出。传输写入结果不确定时不自动重传。
- 发送端仅对明确未发送任何字节的 `BUSY` 排空下行后重试；接收和发送分别借用
  6144 B 与 2048 B 区域，防止半帧接收覆盖待发送的音频包。

51 项 ASan/UBSan 主机检查全部通过，11.52 秒。新增检查覆盖逐字节/随机长度
分片、跨分片 UTF-8、PCM 编码与尾包、改口、取消、背压、缺失结束、重复或
提前的确认、错 ID、畸形 JSON、文本/输入上限和截断超时。实际原始事件重放
核对第一轮前缀，在第 15 个事件、第二个输入公告处按预期拒绝复用；这是前缀
兼容性检查，不能写成三轮设备接入通过。

使用项目的 RISC-V GCC 15.2.0、当前 C3 架构参数、C11、`-Os` 编译独立目标文件：

| 项目 | 结果 | 含义 |
| --- | ---: | --- |
| 目标文件 text | 4724 B | 含该对象的代码/只读数据；不是最终链接后的固件增量 |
| data / bss | 0 / 0 B | 状态由调用方持有，不是整个功能零 RAM |
| C3 会话结构 | 192 B | 不包含借用的缓冲、TLS、JSON 临时分配和任务栈 |
| 单函数最大静态栈帧 | 544 B | 不是整个调用链峰值或实机栈水位 |

该模块借用 8192 B 工作区和已有文本缓冲，不新增整段 PCM 缓存。尚未与 C3
实际 TLS、采集/VAD、候选播放及 DeepSeek 并发运行，不能据此宣称资源达标。

## 当前内存限制与下一步

对当前 90 ELF 的离线 GDB 检查：engine 为 54624 B，可借用区从偏移 184 到
54600，共 54416 B。扣除 8192 B 网络尾区和 3000 B 采集元数据，剩 43224 B；
已有 40960 B 候选缓存占用后只余 2264 B，不能直接再塞入 6144 B 事件缓冲。
共享事件区还要处理两个连接各自未完成的半帧，不能仅让两个解析器指向同址。

`esp_tls_t` 为 2924 B，其中已包含 264 B SSL 上下文，不能重复相加；它也不包含
证书、网络和动态缓冲的全部分配。配置 RX/TX 上限为 16384/4096 B，启用动态
缓冲；这些数字不是第二条 TLS 连接的实测总成本。现有入口已经释放旧 HTTP
连接，不能把再次调用同一释放函数当作新增优化。

最近 90 的实机压力最低堆为 38264 B，距 49152 B 目标差 10888 B；该数字来自
另一组完整流程，尚未隔离到本模块。不能由静态大小推断双连接必然可用，或
反过来认定在所有阶段都不可能使用。下一阶段先接入单轮 ASR、量出真实阶段
峰值，再决定候选缓存/生成连接的内存复用，不缩减上下文来掩盖问题。

UX57 结束时最后一次已验证安装状态仍是 0.11.72-summary、预取关闭；UX57 未访问
USB。后续安装与恢复证据见下节。实际一秒起声、复杂任务接续和 48 KiB 压力堆
门槛仍需验证，完整目标保持未完成。

## UX61：C 端分段合并与撤销

新增 `plugins/speech/asr_segments.{c,h}`，将一个设备输入中的多个 ASR 段落合并，
最多保存 8 个服务端 ID，合计文本仍为 2048 B。每段最终文本按原始语音顺序存放，
用换行保留段落边界；后段最终文本先到，也会等前段到齐并按顺序插入。临时文本
只在前段已到齐时展示，不把缺失的前半句隐藏掉。

新段落开始立即撤销上一个结束候选，不必等新段文本到达。段落标为 final 只代表
当前段落完成；整轮还必须完整上传、发送 `session.finish`、收到全部段落结果及
`session.finished`，调用者最后仍要通过采集 join 与取消检查。VAD 路径不发送
手动 commit，手动模式默认行为保留，当前运行入口尚未选择新 VAD 模式。

重复 ID/最终段、未知 ID、错误的前项关联、重叠活动段、无效时间戳、缺失提交、
空最终文本、超过段数或总文本限制都会清空输出并失败；断流、超时、取消仍关闭
连接，不重放已发送输入。这些检查是输入归属和顺序保护，不是完整语义分类器。
