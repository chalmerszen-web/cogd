# Phase4 实际扬声器到 ESP-HI 唤醒测试

2026-09-21。结论：**新模型能在 C3 上正确运行，但本次真实声学唤醒效果不通过。已恢复原版 0.6.3-context。**
按预先约定的识别失败退出条件结束本轮，没有继续训练、降低阈值或开展新的长时间调优。

## 固定条件与结果

电脑输出端点为 `头戴式耳机 (Misiom-Shooter)`，设备为 COM5 ESP-HI。
声音经过实际播放设备和空气进入板上麦克风；PC 麦克风录音仅用于核对播放。
使用 Phase3 冻结模型、阈值 920（logit Q8=625）、设备输入增益 1。
正式播放增益 0.35；源文件目标 RMS 0.14、峰值上限 0.8，变换与哈希逐条记录。
未对采集录音进行归一化。距离由现有物理摆放决定，未测量或变更距离。

| 测试 | 结果 | 解释 |
|---|---:|---|
| 普通话正样本 | 0/20 | 目标至少18/20，失败 |
| 粤语正样本 | 1/20 | 目标至少18/20，失败 |
| 负样本播放观测 | 1/20触发 | 粤语“你好小燕”；尾部观察窗口不足，不能作为完整误触发率 |
| 部分词观测 | 0/7触发 | 仅限上述窗口，不证明完整负样本门槛通过 |
| 最终固件固定 PCM 对齐 | 512帧、零差异 | 板上中间整数轨迹与 Phase3 主机参考一致 |

60条样本是固定留出材料，包含两种语言和多个合成声音来源，不是真人泛化测试。
正样本计分区间沿用端点下界至上界后800ms；时间来自电脑播放提交与 USB 轮询，
没有校准声卡输出延迟，不能将其解释为精确设备响应延迟。只有1次命中，不报告
具有代表性的延迟分位数。逐条时间在 replay.json 内保留。

## 已定位问题与证据边界

1. 原校准脚本在录音命令返回1秒后播放，此时设备仍处于Flash准备阶段。
   calibration0-run/calibration1 是无效时序尝试，不能据此判定收音或识别失败。
   修复为等待 capture_stage=2 后再播放。同步后的板上录音通过本地 ASR 恢复
   两种语言的完整音节（转写为“小燕/小贤”等同音字），这不是人工发音验收。
2. 高播放档普通话有183个ADC限幅计数；降档后100个，粤语0个。导出PCM无满幅
   样本。没有证明这些计数来自启动瞬态还是语音峰值，因此保留为链路限制。
   共两次音量调整后冻结设置，没有按正式成绩调参。
3. 旧默认阈值550会在重启后覆盖新模型工作点，已改为训练版默认920、旧版仍550。
   正式测试前重新构建、受保护烧录、重做固定PCM对齐，设备状态验证默认920。
4. 正样本40条已全部完成；进入首个负样本时，空的 wake_end_sample 导致脚本异常。
   保存原报告与脚本，不重跑正样本；修复空值后单独补跑20条负样本。
   因此还有1次脚本中断的未计分负样本播放，不能将总物理播放次数称为恰好60。
5. 审计又发现负样本脚本未统一等待播放结束后尾部，20条负样本只保留为观测，
   不将1/20当作完整验收成绩。已修复尾部等待并新增回归测试；按失败退出预算
   没有再次播放20条，也没有利用此修复改变已经明确的正样本失败结论。
6. 同一批40条原始音频输入已冻结的主机C实现，全部有检测事件；两条校准源音频
   也有事件，但对应板上录音重放到同一C实现均无事件。结合板上整数对齐通过，
   支持“实录输入与训练材料存在差异”的诊断方向，尚不能确定具体频响/噪声/
   电平因素。手动录音与唤醒使用相同的抽取和去直流PCM路径，但采集不是同时
   进行，不能当作正式测试当时的逐样本输入证明。
