# 小言 Phase 1：计算与资源样机验收

2026-09-21。本阶段通过。已在当前完整 C11 Agent 和实际 ESP32-C3 上验证专用
INT8 后端的数值、资源、连续流和功能切换；测试结束已恢复 0.6.3-context / 嗨乐鑫。
**没有训练“你好，小言”，没有测得普通话或粤语识别率。** 测试权重固定种子、
明确 `trained=false`，核心禁止发出实际唤醒；零唤醒计数不能解释为零误唤醒率。

## 数值与构建验证

- 参数核算：6384权重、6673训练参数、折叠权重+bias6964 B；3056 B历史缓存；
  每512样本12768 MAC；2048 ms声学感受野。
- 浮点整段/流式：256帧、batch 2，最大绝对差5.587935447692871e-9。
- 独立Python整数参考、PyTorch Conv1d整数算子参考、主机C：4096帧，
  **1,085,440个逐层值完全相同**；检查了PyTorch与C权重布局转换。
- 固定PCM通过USB送板：512帧，**176,640个前端、输入与网络层值完全相同**。
  包含静音、正负满幅DC、Nyquist、脉冲、扫频和随机噪声。
- 独立浮点FFT检查250/1000/4000 Hz测试音，峰值频带正确，峰带log2误差小于
  2个Q8.8单位。Windows和WSL重新生成探针/表的哈希一致。
- C ASan/UBSan：4096块极值/随机音频、舍入、饱和、重置、冷却和错位工作区；
  malloc/calloc/realloc/free包装检查每帧路径无分配。5项Python契约测试通过。
- 原Agent主机测试27组、无音频15组通过。完整probe、旧后端legacy、noaudio
  三种固件编译成功；关闭新后端时链接报告无KWS库运行存储。

上述探针是确定性非零测试权重。模型层结构可训练、梯度有限，但本阶段没有进行
正式数据训练、校准或导出真实checkpoint；不得将probe exporter称为已完成训练导出器。

## 设备回归与修复

最终验收运行了GPIO输入/输出/PWM、受保护引脚拒绝、计划取消与状态恢复、灯光、
麦克风开关、短旋律；DeepSeek流式直接GPIO调用和非流式定时计划均实际完成。
两种网络请求均在监听开启时进行，请求结束后自动恢复监听。

另完成20次创建/销毁监听状态、间插诊断会话、坏CRC/错序拒绝、冲突命令拒绝、
取消释放、30秒空闲释放与重开。执行一次2000 ms本地录音与回放，状态均为ok，
未上传录音。音量恢复80。这里只确认功能链，不评价人声清晰度。

保留了以下失败及修复，没有将失败记录改为成功：

1. IDF提前展开依赖时看不到普通构建开关，首次漏传kws.h路径。固定公共依赖后，
   通过链接报告确认关闭时没有运行开销。
2. Windows/WSL的JSON换行差异。导出统一LF，两端重建哈希相同。
3. 复核去除了同地址memcpy。修改后重新执行了主机、板上和连续流检查。
4. 网络请求后的状态重建曾报memory。ESP-IDF普通分配仅保证4字节对齐，状态因
   64位样本计数需要8字节；改为显式对齐分配，USB会话也采用其声明对齐。
   修复后的20次启停及两种真实网络切换通过。没有降低堆门槛来掩盖错误。
5. 初次云脚本要求直接GPIO工具，而LLM合法采用了控制计划；之后明确提示所测路径。
   另一处脚本把查询先前主动取消的计划当作新失败；修正为仅接纳已记录的历史取消
   状态，新计划仍须成功完成。对应原始失败报告保留。

早期两个镜像分别完成过600秒，但不能替代最终对齐修复版的600秒证据。最终验收
使用上面的23f840…镜像；旧记录在first-image和pre-alignment-fix中分开保存。
