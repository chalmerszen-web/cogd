# 千问快速语音：实现与验收状态

目标是用户说完到设备扬声器开始**有用回答 ≤1 秒**；提示音、占位话语、
首 token、首 PCM 包均不能代替实际声音。**当前未达标，不提升为正式发布包。**

## 已实现

- 普通单轮问答走 `qwen3.5-omni-flash-realtime` / Tina，16 kHz 输入、24 kHz
  输出，省去独立 ASR→DeepSeek→TTS 三段请求；复杂任务可委派 DeepSeek。
- 历史、记忆保存和快速路由不提供的硬件能力，增加本地保守路由保护，
  防止模型忽略委派工具后声称“不记得”。普通“你叫什么名字”仍走千问。
- 使用空闲预连接、TLS 会话票据、TCP_NODELAY、单 TLS 写入；保留证书验证。
  流式解析 PCM，不保存完整云端音频。只跳过开头最多100ms全零填充，
  不删非零语音或句中停顿。实测该模型常有约80ms全零前缀。
- 完整校验工具后才执行；有副作用或已播音时禁止自动重播/改走另一模型。
  空ASR、最终ASR之前的PCM和无效事件保守失败，不把未知输入播成成功回答。
- 云端端点后，先停止采集、提交Flash并交还工作区，再处理回复。
  快速采集不运行TEN确认网络，专用任务栈1536B；经典路径仍4096B。
- `agent voice mode fast|classic` 选择路径，仅本次开机有效，默认classic。
  `agent voice on/off` 沿用已有开关。实验版本不替换 `firmware/latest`。

## 声学证据与失败

电脑以固定音量播放合成语音，外部麦克风记录实际设备回复，本地SenseVoice
核对内容。输入与录音按频带相关对齐；录音开始返回时间不等于WAV零点。
数值是少量样本的起点候选，复核余量约±80–100ms，不是P95或真人泛化证明。

| 测试配置 | 输入结束到回复声音 | 结果 |
|---|---:|---|
| 初始冷连接快速路径，蓝灯 | 约7.57s | 正确工具动作，连接开销大 |
| Audio3.0预连接＋本地400ms，介绍/蓝灯 | 约1.90/2.70s | 无法达到1s |
| Audio3.0云端300ms，介绍 | 约1.32s | 同组长指令截断、曾错误设红，整组否决 |
| Omni3.5云端300ms，介绍 | 约1.04s | 同组长句截断；不能算稳定1s |
| Omni3.5云端800ms，完整记忆语句，两次 | 约1.77/1.76s | 回复内容相关；不能单凭口头确认证明记忆成功 |

原始材料位于 `artifacts/voice-fast/`。具体声学文件：
`device-fast-01`、`device-fast-window-01`、`device-omni-01`、
`device-radio-default-01/latency-radio.json`、`device-radio-low-01/latency-radio.json`。

800ms也出现过截为“请记住”、漏掉首句或“请简单回答”的情况；这些失败没有
删去。较早只检查传输完成的报告旁新增 `acceptance-correction.json`，新测试
检查完整指令关键词、实际RGB，以及历史请求是否真的委派。`device-regression-01`
还发现模型未查历史就回答不记得、空ASR后播音；0.11.5针对这两类业务错误加保护。

## 截断诊断

1. 测试语句“请记住，我给这盏灯取名叫小星星”的中间低能量停顿约530ms，
   未达到配置800ms；板端时间轴与源音频一致，未发现2倍采样率或packed丢样。
2. `device-omni-diagnostic-01`实际配置回显为semantic_vad/.1/800。
   云端speech_started=2040ms对应后半句起音，首句在板录中存在但未被接纳。
3. 该次成功上传的78336样本CRC32=`654f3776`，与导出的原始Flash前缀完全一致；
   已排除这一前缀的本地解码/游标错位。回调到达间隔不等于语音静音时长。
4. 同源实时上传录音与独立录音相比，停顿噪声约高9dB，1–3.5kHz约高18–20dB，
   首句与噪声更难区分。图和数据在 `capture-comparison-01`。这支持实时采集质量
   劣化，**尚不能只凭两条录音断言RF、电源或PDM中的某一项是唯一原因**。
5. 完整板录主机对照3次（semantic800/server800/高通）及32/20ms分片对照2次，
   都识别完整。高通或分片尺寸未显示解决问题；没有无限扩展参数搜索。
6. 同固件20→11dBm对照仅1对：低功率停顿能量低3.65dB，语音/停顿改善约
   1.5–2dB，但回复仍约1.76s。2dBm额外一次绿灯虽动作正确，仍漏尾部限定。
   无法据此宣布解决噪声或端点；已恢复原20dBm，不改变默认射频设置。

诊断命令 `agent wifi power N` 中N为SDK规定的0.25dBm单位，范围8–84；仅空闲
时可改，不写NVS，重启恢复默认。status包含实际功率上限和RSSI。此命令不是LLM工具。

## 资源、稳定性和回滚

- 不缩减2MiB上下文分区、200KiB历史选择预算或448KiB录音槽。
- 应用每次烧录前备份整个Flash并校验；只写应用，读回确认非应用字节不变。
  日志 `flash-fast-*.log` 记录镜像哈希和对应备份目录。
- 当前若干测试启动以来最低堆曾为37436B，未满足先前48KiB目标；某次采集任务
  采样最低41860B。两者口径不同，未将常态约98KiB空闲当作峰值通过。
- 全局最低堆由各内存区域各自历史最低之和组成，不必对应同一时刻。
  未发现确定可回收的10KiB闲缓冲；关闭WSS已销毁活动TLS，保留票据不是16KiB
  收包缓冲。真实DeepSeek任务剩余栈曾仅2652B，因此没有盲缩网络栈。
- `cancel-01`：采集/播放取消确认各约203ms，约2.7–2.9s恢复监听；这是USB
  确认与恢复测试，未把确认时间当精确声学停止时间。取消未新增上下文事件。
- `silence-01`：真实唤醒后未播放指令，约10s有界超时、无工具/回复、自动恢复。
  环境外录保留，不能凭未播测试语音就假定绝对静音。
- `device-regression-01`发生一次播放欠载和协议失败，保留失败记录。
- 已有0.9.0正式安装包与此前可编译回滚源保留。不会用实验镜像覆盖它。
