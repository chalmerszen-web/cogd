# 连续语音连接复用：0.11.61 有限实测

本文件记录61的历史实测。当前部署已更新至[0.11.68 TCP队列实验](VOICE_TCP_QUEUE_REPORT.md)，
复用仍开启、预取仍关闭。以下数值保持原始记录，不混用后续结果。

2026-09-26。本阶段设备为 **0.11.61-turn-reuse 实验版**，fast/capture/listening，
`reuse on`、`prefetch off`，灯关闭。电脑录音已停止，COM5 已释放。正式安装包仍为
0.9.0；本实验没有通过整体验收，所有候选保持 `accepted:false`。

## 已实现的范围

用户提出在听话时推测意图、准备回答，本项目把准备与执行分开：部分 ASR 可选择
暂定路由；实验预取可产生绑定输入代号的可撤销音频；新语音或改口使旧候选失效。
只有最新完整输入通过校验，才允许播放对应回答和调用工具。关键词不直接授权
GPIO、记忆写入或“已经完成”的承诺。

此前预取的九轮冷连接需要1787–2005ms，两次候选接流也在本地收音结束后才收到
首 PCM。因此61先消除连续普通对话的重复连接。它没有证明提前准备有效答案，
也没有在半句话阶段发起 DeepSeek 请求。预取仍关闭，历史实测见
[预响应说明](VOICE_PREFETCH_SPEC.md)。

同一连接最多处理三个完整普通回合，空闲保留窗口为初次准备连接后的60秒。
已经开始的回合沿用原有超时上限，60秒不是强行截断正在播放的总寿命限制。只有完整最终 ASR、完整
响应、扬声器排空和历史落盘之后才保留连接；无工具、委派或未完消息。清空
未提交输入并等待明确应答，保留历史输入/响应 ID，拒绝迟到和重复事件。
清空失败即关闭连接，不重播已经说过的答案。取消、委派、工具和超时沿用关闭路径。
清空音频不等于清空服务端会话历史；三轮限制同时限制历史积累。
协议依据：[千问客户端事件](https://help.aliyun.com/zh/model-studio/client-events)、
[服务端事件](https://help.aliyun.com/zh/model-studio/server-events)。

## 有界实机结果

每组三轮连续普通话/粤语/普通话唤醒，业务正文为普通话。轮间不重开 voice，
不等待 fast_ready。每组只运行一次，失败留在分母，不补测覆盖。
外录延迟是输入有效声结束至回答的信号/独立 ASR 候选；不是精确首音素或人工听感。
咻音、接话及操作提示不计入有效答案。

| 用例 | 完整输入与任务 | 外录有效回答候选延迟 |
|---|---:|---|
| 自我介绍 | 3/3 | 第一轮波形匹配不足，未知；1.699 / 1.420秒 |
| 记住灯名“小星星” | 3/3 | 15.844 / 13.181 / 12.238秒 |
| 蓝色→不要蓝色→绿色 | 2/3 | 9.094秒 / 收音超时无回答 / 9.142秒 |

首次唤醒9/9，完整输入及任务8/9，DMA丢失0，未观察到复位。改口成功的两轮
只调用绿色；失败轮以 `@error timeout` 结束，没有调用灯控。它使用新连接，
未进入复用路径；仅凭这组数据不能将收音超时归因于复用，也不能认定问题已解决。
上传159232样本但完整性为false，未把已上传前缀当成完整命令执行。

问候第一轮连接就绪耗时1855ms，后两轮复用仅1/0ms。对应三轮 VAD→首 PCM 为
573/862/850ms，VAD→扬声器为581/870/861ms。**连接省时不等于端到端一秒回答**，
也不是随机对照实验，不能据此报告固定提速比例。三轮后连接按上限关闭。
记忆与改口需要完整 Agent，均新建连接，未声称复杂任务也复用了会话。

八次完成收音各有一次结束咻音事件；七次可定位外录通过原频谱门槛，一次波形
匹配不足保持未知。三个记忆接话在外录中识别到“小星星，我来记一下”或同音
字转写，三个保存提示另行记录。接话有2/2/1次供音不足计数，且最终回答仍慢，
自然衔接未通过。累计最低空闲堆35296B，未达到48KiB；后续回合未刷新最低值
不能代替长期泄漏或峰值内存验收。
