# UX182：同一 C3 上重放漏掉的改口弱音

2026-09-30。UX181 已证实，第三轮的电脑提示完整播放，ESP-HI 却在后半句抵达前停止收音；已录入的“不对”一段低于严格能量门槛。本轮只把保存的板上 16kHz 原录音送入已冻结的 ESP32-C3 官方 VAD 双模式探针，补出原先没有保存的逐帧频谱位。没有重新播放、录音、唤醒、联网请求、ASR、工具或上下文写入，也没有更改生产代码。

输入是 UX180 的 60,288 样本录音，按完整 20ms 帧重放 188 帧，余下 128 样本不补零、不计分。旧探针 `0.11.207-vad-modes` 同时调用 MODE2（现用 Very Aggressive）与 MODE0（Normal），两者使用独立句柄；其二进制、官方 C3 库、录音和主机原 C 滤波结果在运行前均通过固定 SHA256。每帧校验序号和 CRC，整段输入 CRC 为 `690d8b45`；MODE2 与 MODE0 元数据 CRC 分别为 `e62edb6a`、`694f1bcf`。两模式的能量字段均与主机原 C 滤波逐字节一致，没有不同能量帧。MODE2 全段 82 个频谱语音帧，MODE0 为 112 个；这些是同一段数据的配对诊断，不是识别率。

UX181 对齐出的弱句设备时间约为 2920–3270ms。取**完整落在该区间的 17 个 20ms 帧**（索引 146–162）：MODE2 有 6 个频谱语音帧，MODE0 有 11 个；MODE2 阳性集中在最后的 157–162 帧。两路滤波能量最大分别为 344、328，均未超过冻结噪声 176 对应的强门槛 352；强语音 0 帧。弱门槛 264 的双路能量通过 5 帧。若把末端仅与区间重叠 10ms 的第 163 帧也计入，则是 18 帧、MODE2 7、MODE0 12、弱能量 6；自动设备报告保存了这项重叠口径，结论使用完整帧口径。**设备收到并由 VAD 标出了部分弱语音，但现有强能量条件阻止它们重置静音计时。**

这只定位了 UX180 第三轮的必要判据。它不证明弱音的来源是麦克风、播放位置、环境或滤波器，也不能解释第二轮空转写：第二轮没有同样的板上录音。单独把 MODE2 换成 MODE0 仍受相同能量门槛约束；UX169 八份固定材料已显示，仅换 MODE0 未修复三个完整改口样本的结束点。直接放宽能量或增加等待，也可能让噪声续听和短问候变慢；UX172 的四弱帧尝试使一个短问候延后 460ms，仍漏掉另一段改口。因此本轮不把探针改动合入固件，不声称三轮正常对话或一秒有效答复通过。

`flash_guard.py` 安装探针和恢复稳定版时都先备份并校验完整 4MiB Flash，仅改写应用，核对读回及非应用分区。安装前整片哈希与恢复后哈希均为 `935ecd783a5e96607b93c3693257a2098302320752c0679bd9838a68e012062a`，中间探针安装状态为 `4b2263e834900da3531ed675554de398f6ddd7a22ba93cd9293280174bb1ed78`。上下文前后均 1197 事件、849824B；稳定应用 SHA 恢复为 `22faca4f0c6bf12030d924db38904d330af9585493ea307e29f18d4da2309c07`。设备现为 `0.11.72-summary`，Wi-Fi 在线、fast/capture/listening、reuse 开、prefetch 关、灯灭、DMA 丢失 0。

对“边听边猜”的产品思路，当前代码已经有增量 ASR、一份异步候选和静默 PCM 缓存，以及完整输入后撤销/采用的检查。此轮证据强调先要保证**最终话语被录完整**；提前取回“蓝色”候选不能覆盖后面“不要蓝色，改成绿色”。可提前预热连接和准备不含具体设备动作的接话语，但应只在最终意图核对后播放事实性答案或执行 GPIO。下一步若改端点，需拿固定短句、背景声、改口样本配对验证弱语音证据和采样上界，先证明不会普遍拖慢短句，再进行一次正常三轮实机试验，同时满足最低空闲堆 48KiB。尚无可靠的一秒首个**有效**回答或真人泛化成绩。

证据在 `artifacts/voice-fast/vendor-tail-ux182/`：冻结清单、`expected-energy.bin`、探针逐帧原始串口/`mode2.bin`/`mode0.bin`、一次重放的 CRC 与统计、两次 guard 报告、实验前后状态和 `closure.json`。第三轮原 WAV、外录与源提示在 UX180，时间对齐在 UX181。整体语音目标仍未完成。
