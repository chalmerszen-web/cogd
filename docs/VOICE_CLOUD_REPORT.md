# ESP-HI 语音对话集成实测报告

本报告冻结记录 0.8.0 的交付结果。后续 0.8.1 的当前状态及响应速度对比见
[提速报告](VOICE_SPEED_REPORT.md)，下文版本和资源数字不代表后续固件。

2026-09-22。已安装 **0.8.0-voice-exp**，开启语音监听，COM5 已释放。
完成设备端唤醒、VAD、VocalignTech ASR、原有 DeepSeek/工具、TTS 播放及自动恢复监听。
当前是实验版；合成语音自测与真人泛化、主观音质分开记录。

## 版本与实现

应用 1,377,312 字节，SHA256：
e12e35616614c5a2692936be65925dd6d43b2a25cf8b69951b158e95887e365b。

本地唤醒沿用 xiaoyan_ds_tcn24_ek3，阈值 740、输入增益 1。本次没有再训练或扩大唤醒测试；
普通话/粤语及近似词限制保留在 [Phase 6 报告](WAKE_XIAOYAN_PHASE6_REPORT.md)。

单个网络 worker 串行处理语音事务。ASR 逐块读取 Flash 录音；TTS 借用空闲 LLM 消息区的
12 KiB PCM 队列，不把整段 WAV 或 200 KiB 历史放进 RAM。麦克风、录音槽、扬声器和模型
切换有明确所有权。用户指定本机 Key 文件只用于配置，语音凭据独立存入 NVS；
原 Wi-Fi、DeepSeek、上下文保留。对象上传和签名下载不携带平台 Key，HTTPS 校验保持开启。

plugins/speech/speech.h 保留 ASR/TTS 的 begin/feed/finish/cancel 和 provider_state 契约。
当前 ASR 是异步文件服务，TTS 是非流式模型；capability 为 false，未实现钩子为 NULL。
WAV 分块下载播放属于传输流式，不宣称模型流式或实时双向对话。

## 故障与修复记录

1. 平台 WAV 使用近 2 GiB 未知长度占位值，最初 ASR 因错误时长返回 400。
   电脑改用实际 PCM 长度；设备识别已观测占位值、限制真实样本数、拒绝不完整采样及
   不合法固定长度。没有重复购买同一 TTS 来修复文件头。
2. 最初设备 PCM 输出失真，外部 ASR 只有标点。原因为有符号采样参与无符号除法。
   修复为明确有符号运算并增加测试，随后实录可识别完整语音。
   tts-device-01 失败和 tts-device-02 修复证据均保留。
3. 对象上传 TLS 失败。完整 CA bundle 加 IDF 交叉签名校验后通过，没有关闭证书验证；
   失败期间未提交收费 ASR 任务。
4. ASR 结果签名 URL 返回 403。同一任务在电脑证明额外 JSON Content-Type 导致
   SignatureDoesNotMatch。GET 不再隐式加该头，诊断未重复提交收费任务。
5. stability-01 第八次真实回答完成后，测试工具把迟到状态错配给下一类查询。
   保留 incomplete 报告，不用错配字段统计资源；原始串口和外录仍可核对。
   修复字段匹配后完成余下四轮，另补取消确认乱序测试。
6. 空闲 agent cancel 曾使状态显示开启、实际唤醒关闭。改为资源释放后由主循环
   有界恢复并清除待处理录音；取消恢复和明确 voice off 均已实测。
7. 首次附加音乐测试使用不支持的 240 BPM，正常拒绝；合法 180 BPM 后完成。
   未把被拒绝请求计入音乐成功。

主机故障注入还覆盖不确定 POST 超时不重放、有限 GET 重试、429、失败任务、不安全结果
URL、180 秒截止和预先取消。已提交而取消的云 ASR 任务只查询到终态，没有再次收费提交。
板载麦克风靠近自身扬声器时音量计可能饱和，并发音量检测不代表回声消除或全双工识别。

旧应用不接受 200 KiB 预算检查点。实测回滚先保存 128 KiB 兼容检查点、核对事件数及序号
不变，再完整备份且只写旧应用；重装新版后恢复 200 KiB。
使用 tools/voice/rollback.py --apply 执行这一顺序，不能直接覆盖旧应用。

本报告不改变 M0 实机 Gateway、真实拔插断电或 LCD 实物可见性此前的验收状态。
