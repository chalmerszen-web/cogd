2026-09-28。本轮继续处理提前备答所需的完整输入。完成一个端点候选的固定重放和六次

## 一次有界的续听原型

候选方案：当已提名的回复还没有首块PCM，原本要结束的本地端点最多继续接收50个20ms
帧，累计最多1000ms；现有严格语音票数确认续说后照常继续。原有参数等待额度、云端
结束提议和10秒硬上限仍保留。生成准备不获得播放、GPIO或历史提交权限。

仅用主机原型包装当前C端点，没有集成到生产者或烧录。七份固定材料2102帧，包括UX132
三份完整录音及实际提示顺序。关闭原型时逐帧重现原行为；另用“始终未就绪”和“已经
就绪”检验依赖连接快慢的后果。旧负向材料使用恒定文字压力条件，不冒充原ASR时序。

| 输入 | 原端点 | 回复仍在准备 | 回复已经就绪 |
| --- | ---: | ---: | ---: |
| 改口录音1 | 3260ms | 6260ms | 3260ms，仍截断 |
| 改口录音2 | 5880ms | 6900ms | 5880ms |
| 改口录音3 | 3280ms | 6360ms | 3280ms，仍截断 |
| RF18旧问候 | 2600ms | 3620ms | 2600ms |
| Gate19旧问候 | 3040ms | 文件结束3160ms仍在收音 | 3040ms |

周期预算为1000ms，但释放发生在下一20ms帧，第二条和RF18的端点偏移为1020ms。
另一个四秒背景尾音的两条路径都未结束，数字静音两条路径均为NO_SPEECH；没有补造
保存文件以外的音频。三条真实冷连接的首PCM墙钟投影与“仍在准备”结果相同，但这只是
投影，既不是源帧实际消费的就绪信号，也不能证明首块PCM已经可播放。

**否决理由：**它让输入完整性依赖回复是否缓存就绪。冷连接给了改口机会，热连接又回到
原截断；同时可能增加短句等待。不能将该策略当作通用修复，也未扩大或扫描等待值。

## 同三份录音的六次实时ASR调用

随后按追加的有限计划，比较当前`qwen3-asr-flash-realtime`与项目已有的`fun-asr-realtime`。
旧0.9.0曾运行后者，但其总回复时间包含VAD、DeepSeek和TTS，不能当作ASR临时文字速度。

[官方客户端协议](https://help.aliyun.com/zh/model-studio/fun-asr-client-events)支持二进制PCM
和VAD静音参数；[服务端协议](https://help.aliyun.com/zh/model-studio/fun-asr-server-events)
区分中间结果与最终结果。这里只选现有模型，未购买服务、部署新模型或改设备凭据。

每份八秒设备原录音加同样700ms数字静音，16kHz/PCM16/单声道，共139200样本，以464样本
为块按真实时长上传。先当前模型三次，再Fun三次，每份每模型一次；未随机交错，不推算
总体提升比例。Qwen请求阈值0.2、静音700ms并核对回显；Fun请求关闭语义断句、静音700ms。
两个模型配置并不等价，Fun的task-started也不是完整配置回显。

两组各900个上传块，逐块样本数、顺序、SHA256完全相同。六次会话正常结束，无重试。
首次在IDF Python启动时缺websocket依赖，**远程尝试0次**；保留失败目录后改用已有的
tts-python环境，没有重发一个已创建的服务任务。本轮没有新录音、播放、TTS或工具动作。

下表为Fun比Qwen更早收到对应文字的毫秒数，正数表示较早，负数表示较晚。时间从各自
PCM上传起点计算，完全不是ESP32采集、VAD或扬声器回答延迟。

Fun第二段把“不对”转成“我”；Qwen第一、三段和Fun第三段缺“请”。关键词出现不证明
全句正确、硬件效果正确或可以使用早先猜测。本轮没有执行这些文字对应的业务，因此
不把转写分数冒充灯控成败。两模型全文严格匹配都只有1/3，不能据此替换默认接口。

六份真实事件流送入当前C解析器：Qwen94条、Fun114条，共208条全部通过，最终合并文字
与原服务记录一致；Fun额外采用随机字节分片检验。ASan/UBSan未报错。
旧Fun适配对每次会话的8/9/7个非空临时结果分别只发出一个asr_partial回调。这是旧代码的
已核实限制；将来接入候选回复前必须处理后续修订与整段合并，不能仅改模型名称。
当前独立Qwen路径使用其自己的分段器，本轮没有把这个旧回调限制误认作当前路径的缺陷。

第一次离线重放因WSL启动器警告被当作C程序stderr而失败；第二次跨壳重定向失败。
第三次把整个离线编译/重放放在WSL内执行，分别保留编译和程序stderr，六份程序stderr
均为空。未为重放错误重新调用云服务，也未放宽C解析检查。
