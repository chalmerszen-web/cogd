# UX109：记忆请求的续听与缺参保护

2026-09-28。两组各三轮连续对话验证了144预连接之后的记忆与DeepSeek接续路径。
发现一次在“记住”后提前停录，且后续模型根据旧记录继续保存。145补上裸记忆
动词的续听提示和最终缺参保护。**整组验收仍未通过，稳定一秒与自然接话仍开放。**

源码、正常构建和冻结包保留0.11.145实验版；正式安装包未更新。测试后设备恢复
0.11.72-summary的fast/capture监听，reuse开启、prefetch关闭、灯关闭，串口释放。

## 实际改动

- `agent_speech_pending_argument`增加“记住/記住/記低/记低”的裸动词形式，包含
  已有礼貌前缀及句尾标点处理。它使用原有每轮累计1000ms续听额度；重复转写
  不能续杯，完整内容到达即取消这项提示。原700ms静音门槛、声音判定和上限不变。
- 候选结束后的缺参检查覆盖记忆、灯控缺参及未完成的改口。仍缺内容时进入
  现有只追问路径：请求不带工具，`tool_choice=none`，工具响应不能执行。不会
  用历史中的灯名补齐用户这次没说完的内容。
- 完整请求沿用原Agent处理；没有新增录音缓冲、任务、栈或持久化字段。

主机测试覆盖普通话/粤语裸动词、已完整的内容、取消和引用等反例；800ms停顿
后恢复说话、完整内容释放提示，以及重复提示最多消费原50个20ms帧。候选所有权
测试检查缺参时不播放旧候选、不执行本地灯控、不留下缓存，并交给只追问路径。
原流式引擎测试继续验证不发送/执行工具、取消、错误和历史解锁。

## 连续实机结果

使用原有固定输入“请记住，我给这盏灯取名叫小星星”，增益0.25；每组普通话/
粤语/普通话唤醒。轮间不关闭监听，不加逐轮状态查询；仅测试前后检查已有事实。
两组共六次首次唤醒成功，未发现复位、DMA丢失、播放欠载或USB日志丢失。
