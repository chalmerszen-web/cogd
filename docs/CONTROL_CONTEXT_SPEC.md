# M2 评估：动作链与更长的模型上下文

状态：IMPLEMENTED AND VALIDATED，COM5 上运行 0.3.0-dev。用户于 2026-09-10 授权按本评估实施，以下保留原设计及基线，文末给出完成结果。目标是充分利用 DeepSeek、解决只有四轮历史的问题；“1 MB”不是必须一次发送的固定字节数。原 M0 的 Gateway 网络和真实 USB 断电限制仍单独保留。

## M1 评估基线（保留历史）

| 层次 | 原 0.2.0 实现 | 依据 |
|---|---|---|
| 工具 | 四个基础工具和五个音频工具；没有任意 GPIO、录音回放或动作链接口 | `plugins/tool/tools.c` |
| 麦克风 | 样本仅计算音量；关闭后保留上次读数 | `boards/esp_hi/audio_board.c` |
| 历史候选 | 最近最多四个完整对话轮次 | `AGENT_RECENT_MAX`，`plugins/context/context.h` |
| 历史装载 | 从候选中选择总记录长度小于 6000 字节的连续后缀；也可能不足四轮 | `agent_context_history`，`plugins/context/context.c` |
| RAM 缓冲区 | 消息 16 KiB，请求 24 KiB；构造请求时复制消息 | `plugins/llm/llm.h`、`core/agent.h`、`plugins/llm/engine.c` |
| Flash 日志 | 1 MiB，两个 512 KiB bank；记录头和快照另占空间 | `partitions.csv`、`plugins/context/wal.c` |
| 已记录堆余量 | 音频、麦克风、DeepSeek 和灯控并发时最低 75352 字节；测试后空闲 116204 字节 | `artifacts/logs/audio-hardware.json`，先前实测，非本次实时采样 |

四轮历史是本工程选择，不是芯片或模型上限，也不同于每个回答最多四工具、最多四次工具续调的限制。DeepSeek 当前列出的 `deepseek-flash` 上下文为 1M tokens；token、UTF-8 字节和 Flash 容量不能互换。[模型说明](https://api-docs.deepseek.com/quick_start/pricing/)

## 模型上下文的建议实现

优先采用按字节预算选择完整轮次、从 Flash 分块发送的 DIRECT 路径，不依赖当前无法从设备访问的电脑 Gateway。

| 项目 | 初始实施目标，均待测试 |
|---|---|
| 候选历史 | 最多 128 个完整轮次的 Flash 描述符，正文不常驻 RAM |
| 默认历史预算 | 64 KiB 序列化历史，实际轮数随对话长度变化 |
| 扩展档 | 128 KiB 历史，通过并发、超时和耐久测试后才启用 |
| 单轮数据 | 沿用输入、回答、工具参数和单条日志记录上限 |
| HTTP 请求 | 单独计入系统说明、记忆、工具 schema 和当前续轮，精确计算 Content-Length |
| 分块传输 | 复用现有 24 KiB scratch，每次处理一条记录，网络写入块不超过 4 KiB |
| 新增常驻 RAM | 索引与控制状态目标不超过 8 KiB，不分配 64/128 KiB 连续数组 |

transport 需新增已知总长度、可取消的 body producer。请求依次写出系统消息、Flash 历史、当前轮次和工具定义；响应继续使用现有 SSE。每次最多解析一条已通过 CRC 校验的记录，工具调用及其结果与所属轮次一起保留或裁剪。

请求前固定记录选择，发送期间禁止压缩移动记录。重试读取同一份选择，保留已输出内容或已产生副作用后不自动重放的策略。取消在分块读写之间检查，USB 保持可用。

64 KiB 大约能容纳 2 万个三字节汉字的字节数，实际需扣除 JSON 和工具记录，不能保证固定轮数或 token 数。64/128 KiB 是设计目标，不是已经完成的实机能力或芯片硬上限。

增加遥测：候选轮数、实际发送轮数/字节、裁剪数量、完整请求大小，明确区分日志容量和模型可见历史。后续增加关键词/事件检索及带覆盖序号的摘要；摘要与用户原文分开，保留原文追溯，不能静默丢弃待同步事件。需要更大的云端上下文时可让 Gateway 汇总。

## GPIO 和动作链

LLM 生成计划，纯 C 状态机负责时间、资源和反馈。提供能力发现、计划校验、执行、状态、取消接口，用有类型的指令组合动作。首个建议用例是“亮灯提示 → 限时采集 → 结束采集 → 回放 → 熄灯”，再扩展音量触发灯效、等待完成和有限并行动作。

```mermaid
flowchart LR
    L[LLM 计划] --> V[参数与资源检查]
    V --> E[设备状态机]
    E --> D[ADC / PDM / RMT / 已验证 GPIO]
    D --> O[实际执行结果]
    O --> L
```

- USB18/19、Flash 引脚固定保留；GPIO2/3/6/7/8 由现有麦克风、功放、PDM、灯驱动持有。未启用的 LCD/身体接口不因此变成已验证空闲输出。
- 通用 GPIO read/write/PWM 只对连接和用途已验证、未占用的引脚开放。整份计划先验证，再统一申请 GPIO/ADC/I2S/RMT；模型不能扩大板级权限。
- 微秒级时序由硬件外设和本地驱动执行。初始计划预算拟定为最多 32 步、有限重复、总时长最多 60 秒；禁止任意寄存器地址、运行时 C 和无限循环。
- 内存、步骤、时长、频率、占空比和并发都有上限；分配失败在动作开始前返回。超时/取消释放资源、静音并还原本计划拥有的输出，已发生的物理动作不可宣称被撤销。
- USB 状态和取消独立；验收最低堆、连续空闲块、栈水位、ADC 溢出和延迟。看门狗是最后恢复措施，不能替代有界执行，也不能承诺任意模型输出下的绝对稳定。

ESP-IDF 明确说明重配 GPIO18/19 会禁用原生 USB，GPIO12–17 通常用于 Flash；引脚模式与外设映射也会互相影响。[GPIO 文档](https://docs.espressif.com/projects/esp-idf/en/stable/esp32c3/api-reference/peripherals/gpio.html)

## 录音回放

放开 GPIO 不会自动产生缓存和回放能力。16 kHz、16-bit、单声道的 5 秒 PCM 需要 160000 字节，超过已有并发测试的堆余量。实现应采用短时压缩缓存或独立音频存储，与长上下文共同验收；可先顺序采集和回放，减少扬声器反馈。

当前强声音测试出现过 ADC 削波，回放质量需另行实测。截图里 mic_enabled=false 时的 RMS 是先前数值，不能证明此刻有人说话；新状态应提供读数时间和有效性。原声回放不需要 ASR，理解说话内容需要 ASR 或能接收音频的模型服务。

## Flash 容量候选与迁移

若要保存约 1 MiB 日志，可将 ctx 扩大到 2 MiB，保留双区轮换；单 bank 为 1 MiB，内容容量扣除元数据。候选布局：

| 区域 | 起始 | 长度 |
|---|---:|---:|
| NVS | 0x9000 | 0x6000 |
| PHY | 0xf000 | 0x1000 |
| factory | 0x10000 | 0x180000（1.5 MiB） |
| ctx | 0x190000 | 0x200000（2 MiB） |
| 未分配 | 0x390000 | 0x70000（448 KiB） |

当前应用仍余 605728 字节空间。候选表 `artifacts/plans/context-2m.csv` 用安装的 ESP-IDF 6.1 `gen_esp32part.py --flash-size 4MB` 验证；布局合法不等于迁移完成。[分区文档](https://docs.espressif.com/projects/esp-idf/en/stable/esp32c3/api-guides/partition-tables.html)

旧 ctx 在 0x2a0000–0x3a0000，与新布局重叠。不能直接修改 CSV 普通烧录：先备份当前 Flash、校验日志/快照/序号/游标，再生成并验证迁移内容。候选新 bank A 0x190000–0x290000 与旧 ctx 不重叠，可在验证旧 app 有效长度后用于暂存。修改 store 适配层必须为 1 MiB 的检查，先支持新旧布局，保留旧日志直到切换验证成功。分区表切换中断可能需要 USB 恢复，不属于普通双区日志提交的掉电保护范围。

## 验收顺序

1. 实现 64 KiB 分块历史和遥测，验证跨 4/16/32 轮的事实回忆、工具续调完整性和重启装载。
2. 检查截断、取消、慢网络、畸形历史和存储满，并与音频/灯控共同运行 100 轮。初始目标为最低堆约 48 KiB，不足则降低缓存或并发预算；这是目标而非已有保证。
3. 独立验收 128 KiB 档的资源和响应时间。
4. 实现 GPIO 资源所有权及动作链，验证非法计划没有副作用，再验证板上已确认的外设。
5. 按实际记录需求迁移 Flash；录音回放、摘要和检索分别验收。原 M0 的 Gateway 网络和真实拔插阻碍保持原记录。

## 完成结果与边界

独立 M2 测试通过 13 组 C11/ASan/UBSan 主机测试、10 组无音频测试、6 组 HTTPS mock 测试及 100/100 轮真实 DeepSeek 并发。64/128 KiB 档实发历史峰值为 65519/131019 字节，请求峰值 144781 字节；最低堆 49400 字节，预热后空闲堆中位数变化 +40 字节。旧检索超时和同名测试变量回忆失败均保留记录，修复后独立复测通过。

板上完成能力发现、非法 GPIO 无副作用、资源互斥、32 步 × 8 次重复、取消、超时、音量触发灯效及最大 10 秒录音回放。用户确认新 PDM DAC 模式在音量 80 时人声清楚、沙沙声减轻，生成旋律正常。此板仅开放 GPIO0/1/9 输入；通用输出/PWM 需要另一块具备已验证可用引脚的板级配置。

日志已迁移为两个 1 MiB bank，独立 PCM 分区 448 KiB。压缩、摘要、来源、序号和软件重启通过实测。按用户明确选择归档了验收填充数据，实际对话与摘要来源原样保留；普通运行不会自动丢弃待同步事件。最终保留 1190 条事件，占用 519768 字节，历史预算设为 128 KiB。

逐项证据见 `TEST_REPORT.md`、`BUILD_REPORT.md`、`M2_MIGRATION.md` 和 `ACTIONLOG.md`。有限测试不保证任意输入/硬件故障下绝对稳定；未增加 ASR、音频上传、LCD、舵机或生产 Gateway。
