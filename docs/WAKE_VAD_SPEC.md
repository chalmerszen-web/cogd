# 当前唤醒与录音基线

0.6.0-upgrade 采用 1000 次同板对比的 B 版语音链路，作为实验性 Agent 功能收尾，不继续训练。固定上游与来源见 [基线说明](BASELINE.md)。这不是完整 ASR、TTS 或语音对话。

## 操作和状态

`agent wake on` 开启监听，说“嗨乐鑫”，听到开始提示音后说指令。`agent wake status` 查询；`agent wake off` 或 `agent cancel` 停止。重启后默认关闭。对话或扬声器占用时暂停监听，资源释放后可恢复。

流程是监听 → 唤醒确认 → 准备/提示音 → 本地采集 → 端点确认/提交 → 完成提示音 → 重新监听。单轮最长录音10秒，唤醒后没有指令有4秒等待边界；校验/提交失败不发布有效录音。新录音会替换单个录音槽。没有自动转写或上传。

## 固定实现

- 原始 WakeNet9s hilexin 命中后用固定关键词特征筛选；不在运行时训练。
- ADC 32 kHz 采集，抽取至16 kHz，12 dB 衰减；Wi-Fi省电关闭。
- Flash后端的TEN确认与前台采集通过原子发布进度配合；处理落后不能假装看到了尚未处理的样本。
- 保留 B 的 source_stream/source_bound、confirmation_tail、tonal规则以及阶段观测。
- 唤醒采集写 lossless packed v3，读v1/v2/v3；手动采集保持v1。CRC和提交标记保护数据有效性，详见 [录音格式](AUDIO_CLIP_FORMAT.md)。
- 大缓冲使用现有工作区租约，不降低2 MiB上下文和128 KiB历史预算。默认开启关键词/TEN能力，但开机不监听。

## 已测结果和限制

冻结的B在500个试验中：正例395/400成功、负例0/100误唤醒、无指令2/100误录、0次触及10秒上限、无板上DMA丢帧。A对应393/400、8/100、22/100、19次、0丢帧。B启动录音中位数602ms，比A慢251ms；本轮最低堆49,804B。

这些是重复的已知/开发素材，不是盲测，也不是0.6.0合并镜像的新1000次验收。报告保留全部误判、两次电脑采集失败、声学定位不确定性和资源代价。[完整结果](VOICE_AB_1000_REPORT.md)。没有主张“零误唤醒”、普适超过官方或完全无截断。

本次只验证迁移集成及资源/取消/GPIO等基本行为；原M4未达目标不因用户采纳实验基线而改成通过。无需重新开始长循环测试。
