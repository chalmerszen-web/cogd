# 提前生成时序对照与同连接补发：UX53–54

2026-09-27。两组电脑端三轮协议实验完成。推迟提前请求的一组完整转写 3/3；
但同连接补发回复没有挽救实际缺失的那轮。没有把固定提前量或补发行为加入固件，
没有播放、录音或烧录。源码应用仍为 90，设备保留此前验证的 72、预取关闭。

## UX53：只改变请求时点

基线为 [UX52](VOICE_REUSE_FINAL_ASR_REPORT.md)：一个连接三次相同的介绍素材，
每轮 47040 样本，400 ms 前导和 700 ms 尾部静音，464 样本一包，尾包 176 样本。
模型、提示词、Tina、16 kHz 输出和手动提交均不变。

本组沿用完全相同的执行脚本，只把 `draft_after_samples` 从 37120 改为 44080。
零请求预检查逐字段比较，除了触发样本数和对应派生字段，配置及完整输入哈希
均相等。每轮只上传一次、提交一次、生成一次。实际一个连接 13.078 秒，无重试。

| 轮次 | 请求早于提交 | 提交至首 PCM | 提交至最终 ASR | 完整输入 |
| --- | ---: | ---: | ---: | --- |
| 1 | 187 ms | 328 ms | 266 ms | 通过 |
| 2 | 203 ms | 219 ms | 250 ms | 通过 |
| 3 | 203 ms | 250 ms | 250 ms | 通过 |

三个最终转写均为完整的“请用一句话介绍你自己”。三份回复 PCM 为 67840、72960、
64000 样本。116 个服务端事件、315 次发送、输入计数和 WAV 字节哈希均通过离线
核对。当前 C 解析器重放三轮通过，共解码 204800 样本。

基线约 640 ms 提前量的三轮均缺最终转写，本组约 200 ms 提前量的三轮均成功。
这是时序影响的证据，但两组并非交错随机对照，云端条件和随机生成仍可能变化；
不能把 200 ms 写成可靠的生产窗口。两组请求都发生在原录音标称结束之后，也
不能将其计作在用户说完前准备好回复，表中数字更不是扬声器实际起声延迟。

## UX54：一次额外生成是否能补回最终转写

恢复基线 37120 样本的提前请求时点。每轮最多一个候选；若完整输入已收到提交
确认、候选已完成、提交后至少 350 ms 仍无最终转写，则在同一连接再生成一次。
不重复上传、不再次提交、不清空当前输入，也不修改提示词。额外生成是一次
模型调用，不是免费轮询。最多三轮、六次生成；实际三轮只触发一次额外生成，
共四次。连接含关闭持续 18.937 秒。

| 轮次 | 首候选 PCM 早于提交 | 是否额外生成 | 提交至最终 ASR | 结果 |
| --- | ---: | --- | ---: | --- |
| 1 | 140 ms | 是，提交后 360 ms | 等待 8 秒仍无 | 失败 |
| 2 | 188 ms | 否 | 250 ms | 通过 |
| 3 | 188 ms | 否 | 265 ms | 通过 |

第一轮两份回复都正常结束，但没有最终转写。额外回复未修复缺失，整组
`complete=false`，保留退出码 1。后两轮发生在同一个已有额外回复的会话中，
不能把这两轮成功归功于补发，也不能作为稳定成功率。

这两轮的首候选音频也早于提交，却仍收到最终转写，因此“首 PCM 先于提交”
并不是最终转写必然缺失的充分条件。下一步需要处理协议隔离，不能只靠比较
这两个时间戳来决定播放或重试。

131 个服务端事件、316 次发送、每轮 47040 样本及四份 WAV/PCM 哈希核对通过。
三份原候选为 52480、55040、62720 样本，第一轮额外回复为 60160 样本。
当前 C 解析器重放第一轮两份回复，59 个事件、112640 样本解码正常；
由于 `input_final=false`，在发送清空前正确拒绝继续复用。主机脚本为收集证据
而继续观察下一轮的行为没有加入设备。

## 验证与下一步边界

两项相关 ASan/UBSan 检查 `qwen_realtime`、`realtime_rejection_state` 通过，0.08 秒。
本轮只改主机诊断脚本、重放入口和文档，没有改产品 C 代码、编译或烧录应用。
普通话/粤语唤醒、VAD、实际起声、压力堆和复杂任务仍需实机验证，本轮不计通过。

当前官方文档分别定义了
[提交音频和生成响应](https://help.aliyun.com/zh/model-studio/client-events)、
[临时与最终转写](https://help.aliyun.com/zh/model-studio/server-events)，没有给出
本实验这种提前生成组合的可靠时序保证。当前 `conversation.item.create` 文档
说明的是工具结果回传，不能照搬其他厂商 API、假设支持任意文本输入项或独立
响应上下文。本轮也没有发送这类未证实的字段。

保留猜测、缓存和最终改口检查的目标。后续应先核实能独立完成最终转写的受支持
链路及 C3 内存代价，再决定如何并行预测；本轮已排除将补发一次响应直接作为
修复方案。没有用云端文字或成功轮次掩盖整体失败，没有追加第三组取最好结果。
