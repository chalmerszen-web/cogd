# 重新监听保护期的决策修正

2026-10-01，UX215。已修正并验证保护期内的命中消耗检测器冷却的问题。**背景人声和近似词的分类误触仍未解决；不能把这项修正视为误唤醒验收完成。**

原音频代码在重新加载模型后至少保护 500 ms，期间继续推理，但忽略命中动作。检测器并不知道这项保护，仍然把命中记为成功并启动 24000 样本、约 1.5 秒的冷却。因此，系统没有响应的那次命中可能压住下一次有效唤醒。仅丢弃返回值不能撤销检测器内部的决定。

使用实际原 C 检测器复现这一条件：在保护期输入高分，之后输入低分间隔和新的有效高分序列。原两票／三块和四块连续模式都产生一次被忽略的事件，后续有效序列均无事件，残余冷却为 8640／9664 样本。该固定分数实验证明这个条件下的错误路径，并不证明用户遇到的每一次失败都由它引起。

修正增加每个 512 样本块的明确决策开关。保护期仍推进前端、神经网络、平滑分数和样本时钟，并累计必要的预热；清除决策票数，不产生事件或新的冷却。已经接受的事件仍保留原冷却。保护时长、模型权重、阈值、录音和网络流程不变，不增加状态、缓冲或任务。原接口继续采用正常开启的决策行为。
