# 0.7.2 P4 交互与预览优化

2026-11-05。实物 ESP32-P4-WIFI6-Touch-LCD-3.5，16 MiB Flash、32 MiB PSRAM、200 MHz。

**软件优化已完成，已烧录 `0.7.2-p4-smooth`。** 最终功能回归通过，应用、字体和分区表均独立读回一致。用户确认暂时无法调整镜头，本轮先交付软件优化，真实场景清晰度延期验收。

改动集中在 **4 个现有生产文件，净增 120 行**（相对本轮开始时备份，不计测试及报告）。[固件与烧录说明](firmware/0.7.2-p4-smooth-20261105/FLASH.md)、[当前架构](ARCHITECTURE.md)、[完整证据目录](evidence/smooth-20261105)。

## 改动范围

- `p4_vision.cpp` 继续集中管理摄像头和画布。在原采集任务旁增加一个仅识别模式启用的推理任务，最多一个待推理画面，不积压视频队列；关闭/切换模式时先等待推理结束再释放模型及输入。
- 仍采集 800×640 RGB565，完整画面按比例显示为 320×256；保持 LCD 方向。用像素中心双线性采样替代点采样，降低缩放边缘的跳动，不把插值当作新增真实细节。
- 缩放在 LVGL 锁外完成，持锁部分只复制显示区、画标记及必要的文字更新；仅刷新变化区域，锁竞争时放弃旧帧。预览目标上限 15 fps，不承诺所有负载下固定 15 fps。
- 识别框携带采集时间，超过 700 ms 或画面质量不足时清除；同步重置面朝稳定计数和靠近面积基线，避免旧目标状态延续。近黑画面不再直接报告“有人”。
- `runtime.c` 仅调整 P4 普通问答的进度回执：没有合适候选时直接预热正式答案 TTS，省去固定“让我想一想”等套话；搜索、生成媒体等任务进度仍保留，模型和音色不换。
- `sdkconfig.defaults` 将普通 malloc 的内部优先阈值从 16 KiB 改为 0，内部预留从 32 KiB 改为 64 KiB；普通分配优先 PSRAM，明确指定内部/DMA 内存的驱动和 TLS 分配仍保持原策略。状态查询增加 `dma_free/min/largest`，避免把总空闲量当作可分配连续块。没有关闭 TLS、修改 SDK 加密代码或增加另一套语音引擎。
- `CMakeLists.txt` 更新版本。测试脚本、临时探针和报告留在 `evidence/smooth-20261105`；诊断构建不用于交付。

## 对照与证据

旧版本为 0.7.1 官方 WakeNet10。同一位置、同一固定合成音频通过耳机→P4 实际麦克风回放，不是 USB 注入，不代表真人成功率。

| 测项 | 旧版 | 优化版负载实测 |
|---|---:|---:|
| 纯预览 | 4.54 fps | 12.14 fps |
| 人形识别运行时预览 | 4.56 fps | 10.60 fps |
| 面朝检测运行时预览 | 4.44 fps | 10.97 fps |
| 两轮普通问答：ASR 最终文本→正式答案开始播放 | 6,541 / 5,650 ms | 3,570 / 3,261 ms |

摄像头数据见 `baseline-02` 与 `inference-load4`。后者临时强制推理，以免暗画面跳过模型使帧率虚高；除该诊断提交条件外，使用最终缩放和内存策略。它只测运行负载，不能当作真人识别准确率。人形推理约 125 ms、面朝推理约 33 ms，最长屏幕锁占用 5.12 ms。帧率口径为十秒内成功提交预览的计数差除以主机测得时长，没有用高速相机逐帧测量 LCD 的物理刷新。

纯预览最终值来自 `release-camera-final`。最终暗场的人形/面朝模式约 12.18/12.16 fps，但质量门控没有执行模型，不能拿这两个数代替上表的识别负载结果；三个模式均验证了暗帧区间推理计数不增长、检测数为 0。

语音数据见 `voice-before`、`voice-after`；平均延迟在这两轮中减少约 44%，网络、云端排队和历史长度会改变结果，不是所有问题的性能保证。这两次免唤醒接话与约十秒告别均完成，没有网络错误。

### 保留的失败

- `voice-load-barge` 在发出唤醒音频前因诊断 JSON 被厂家日志插入而超时；只读查询增加有限重试，不能把这一项计为漏唤醒。
- `voice-load-barge-02`、`voice-load-barge-03` 的并发长回复遇到 AES 内存分配失败；没有删除失败记录或把它归为云端偶发错误。
- `voice-heapdiag` 抓到一次 8,192 B、`MALLOC_CAP_DMA` 分配失败：当时空闲 60,883 B，最大连续块 6,528 B。打断和接话已完成，但告别以 network 错误结束。
- 旧测试脚本只检查关闭事件，误将上述告别错误计为通过。`voice-heapdiag/review.json` 明确判为失败；脚本现要求正常关闭且无非取消错误。原始串口日志与旧结果保留，不能引用其 `transport_passed:true` 作为验收。
- 最后发现恢复源码时保留了旧时间戳，增量构建沿用了强制推理的诊断目标文件。`release-camera/review.json` 记录此问题；已删除该生成的目标文件并重编译模块，保留编译日志，新增暗帧区间推理计数不增长的设备断言。后续只分发独立读回一致的最终二进制。
- `regression-attempt1/2` 保留测试脚本遇到播放期状态查询 busy、未退出密码编辑即尝试自动重连的中断。按同一个视频任务继续，没有重发媒体生成；脚本现等待播放租约释放，并先退出编辑再自动重连。最终完整回归另存 `regression-final`。

修复配置后，`voice-load-barge-04` 在强制人形推理的诊断构建上完成唤醒、长回复播放、唤醒打断、上下文追问、10,037 ms 静默和正常告别；0 次失败分配、AES 错误或网络错误，采音 DMA 丢失及溢出均为 0。内部堆低水位 138,956 B，明显高于失败运行的 55,248 B。这里只证明这一次固定声学并发流程，不是长时间稳定性或真人通过率。

## 清晰度边界

`baseline-02/sensor.png` 是直接从板载摄像头导出的画面，平均亮度约 9/255，范围约 20–24。外置 Insta360 的曝光使 LCD 看起来比原始输入亮，不能只看外拍推断传感器正常。该原始画面缺少可辨认的正常房间细节，当前尚未验证真实场景清晰度恢复。

用户已明确目前无法调整镜头，要求先完成软件优化，因此真实场景清晰度验收延期。未获得可用新场景前，不能报告“人脸清晰度已修复”、真人识别率或远距辨识能力。没有用锐化或过度提亮把噪声当作细节。静态图片识别只能验证模型、解码和显示链路。

## 架构与资源口径

`麦克风 → 官方 WakeNet10 / 原端点检测 → 千问 ASR → COGD engine / 工具 → 统一 TTS → 喇叭` 保留。视觉路径为 `OV5647 → 采集 → 锁外缩放 → LVGL`，旁路一帧送 `ESP-DL 推理 → 带时效的标记`。视频仍在 P4 本机解码准备与同步播放；电脑只在测试时发送原文件及用 Insta360 观察 LCD。

预览临时缓冲 192,000 B；识别另用一个 1,024,000 B 的完整输入快照及 8 KiB PSRAM 任务栈，模型工作区另计。退出后释放，纯预览不创建推理任务。原画布 307,200 B、双相机帧缓冲约 2,048,000 B 均保留。没有新增产品文件或独立服务。

32 MiB 是物理 PSRAM，`psram_heap_total/free` 仅表示纳入堆的部分；XIP 的代码/只读数据和保留区不包含在空闲堆内。Flash 需分别列应用实际大小、6 MiB 应用分区余量、字体和现有数据/媒体分区，不能把预留缓存区称为未分配空间。

## 运行内存与 Flash

硬件是 **16 MiB Flash + 32 MiB PSRAM**；6 MiB 指应用分区。以下空闲量为设备实际回报：

| 项目 | 最终值 |
|---|---:|
| 重启后联网、官方唤醒监听：PSRAM 空闲 | 25,132,024 B，约 23.97 MiB |
| 同状态内部动态堆空闲 | 187,763 B，约 183.36 KiB |
| 同状态 DMA 堆空闲 / 最大连续块 | 149,019 / 143,360 B |
| 最终回归和对话期间 PSRAM 最低空闲 | 14,824,736 B，约 14.14 MiB |
| 同一测试期间内部堆 / DMA 低水位 | 131,284 / 92,540 B |
| 官方唤醒模型常量 | 845,392 B，已包含在 app；XIP 配置也占 PSRAM |
| 官方唤醒检测器/VAD 初始化工作堆 | 817,108 B，约 798 KiB；不是全部语音 RAM |
| 应用实际大小 | 5,677,440 B，约 5.41 MiB；比旧版增加 4,400 B |
| 6 MiB 应用分区余量 | 614,016 B，约 599.63 KiB，使用约 90.24% |
| 原字体资源（含头部） | 1,329,960 B，未改变 |

监听时物理 PSRAM 的非空闲/保留部分约 8.03 MiB，包含 XIP、保留区和堆分配，不是“仅模型占用”。低水位是分配器统计，不能与另一次启动的空闲量当作同一时刻相减。内部堆与 DMA 有重叠，不能相加。内存分配策略见 [ESP-IDF 外部 RAM 说明](https://docs.espressif.com/projects/esp-idf/en/stable/esp32p4/api-guides/external-ram.html)。
