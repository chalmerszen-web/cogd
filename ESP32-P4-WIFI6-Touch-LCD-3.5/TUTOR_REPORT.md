# 0.9.0 拍题教学与异步调度实测

日期：2026-11-05。设备为 ESP32-P4-WIFI6-Touch-LCD-3.5，16 MiB Flash、32 MiB PSRAM；运行频率实测 200 MHz。本版已写入当前 COM3 设备，并完成应用、分区表、字体资源读回校验。P4 直接访问千问，电脑只用于串口、固定语音播放、测试图片服务和 Insta360 观察，不参与产品运行。

当前应用 SHA-256：`50c1b8f930130669f80e4e26ad0f90b816d9a605ef83b267ee16cf2b52fc3fa4`。

入口：[固件与烧录说明](firmware/0.9.0-p4-tutor-20261105/FLASH.md)、[固件清单](firmware/0.9.0-p4-tutor-20261105/manifest.json)、[软件架构](ARCHITECTURE.md)、[最新验收索引](evidence/async-tutor-20261105/acceptance-summary.json)。

## 发现的问题与修正

1. 原实时链路在工具返回后立即请求下一条回复；新 `response.created` 会清理旧 PCM，导致本来还没播完的解释中断。本版将工具回执改为有界 FIFO，逐条确认，并等待实际播音结束才继续生成；平台自动送来的新回复也先等待旧音频排空。
2. 单个待确认 call ID 会被连续工具回执覆盖；旧用户的话轮结果还可能替新用户触发回复。本版分别保留回执及来源 item ID。迟到结果仍记录，过期话轮不多播一遍。用户真正插话的取消链路继续保留，已经提交的后台任务不跟着清空。
3. 联网搜索原来占用公共工具线程。本版复用现有云任务执行搜索，短工具可以继续运行。云端重任务仍同时限一个，冲突明确返回 busy，没有增加服务或第二套任务框架。
4. 缓存视频的进度回调可能覆盖后来云任务的状态。回调现在核对所属任务与画布代数，旧视频不能改写新搜索或解题结果。
5. 基线实测发现音箱回声尾音被当成插话。静音确认现在先排除 96 ms 尾音，要求麦克风与 AEC 的语音证据，并提高票数；疑似声持续确认窗口为 420 ms。固定混合长回复仍有一次确认后恢复的短暂停顿，因此不能宣称彻底消除了所有卡顿。

实现主要修改已有 `p4_conversation.c`、`p4_cloud.cpp`、`p4_vision.cpp`、`p4_audio.c` 和共用工具表；视频只补状态回调的归属校验。没有增加常驻任务、电脑代理或额外应用 UI。普通话/粤语自研唤醒仍禁用，待机沿用官方“你好小智”。

## 拍题交互

1. 说“你好小智”，提示音后说“教我做这道题”。打开板载摄像头，提示将题目放到镜头前。
2. 新采集的 800×640 图像以 JPEG 送给 `qwen3.7-plus`。识别结果带完整题干、短摘要和题目 ID，屏幕与语音询问是否是这道题。
3. 说“我要第二题”“右下角那道题”等，会重新取景、选择并再次确认。重复进入教学不会丢掉正在等待确认的题目。
4. 用户后续一轮确认“是的”后，才接受对应题目 ID，保存确认时的原图与题干，关闭摄像头并显示“正在解题中”。同一话轮自确认、旧题号、重复确认和已取消题目会被拒绝。
5. 解题使用同一视觉模型，启用 4096 token 思考预算，显示完整答案正文、步骤和检查，不显示内部思考。屏幕为白底深色的竖向文档，可上下滑动，滚动到首尾即停止。点击文档不控制视频。

文字不按固定页数截断；超过一次输出时可续取。受 RAM 和请求预算约束，保护上限为 4 段、128 KiB 正文，达到上限或接口失败会明确显示未完成，不能承诺真正无限长。当前是纯文本数学排版，支持常用运算符、希腊字母和编号；复杂公式不是 LaTeX 排版引擎。

读题最多在 45 秒窗口内尝试 3 次；没看到清楚题目会要求调整画面再看，不猜题。确认等待期间不触发普通闲聊的 30 秒结束。取消或新显示任务使旧结果失效；已提交到平台的请求可能仍完成并计费。

## 资源与读回

应用、分区表及字体资源均独立从 Flash 读回，SHA-256 与构建产物一致；重置后自动连 Wi-Fi 并进入官方唤醒监听。[启动状态](evidence/async-tutor-20261105/final-status.json)记录时网络时间尚未完成同步；[交接状态](evidence/async-tutor-20261105/handover-status.json)已自动同步，无主机设置时钟，音量已设为 100，会话关闭且等待唤醒。

| Flash 项目 | 实际大小 |
|---|---:|
| 应用二进制，含链接进来的唤醒/视觉等模型 | 5,735,936 B = 5.470 MiB |
| 应用分区 | 6 MiB，使用 91.17%，剩余 542.5 KiB |
| 相对进入本轮时 0.8.1 应用的增加 | 22,784 B = 22.25 KiB |
| 含头部的字体资源 | 1,349,308 B = 1.287 MiB，位于 `0x880000` |
| media 分区 | 7.5 MiB：前 1.5 MiB 字体区，后 6 MiB 视频缓存 |
| 持久上下文 / 录音区 | 2 MiB / 448 KiB，布局不变 |

应用分区 6 MiB 不等于芯片只有 6 MiB Flash。媒体缓存和持久上下文是已分配用途的分区，不能把它们当作应用增长余量。上表应用加字体也不代表全片实际写入量。

| RAM 测量口径 | 内部堆空闲 | PSRAM 堆空闲 |
|---|---:|---:|
| 重置后 Wi-Fi + WakeNet10 待机 | 180,335 B，约 176.1 KiB | 24,835,680 B，约 23.69 MiB |
| 最新语音解题完成，实时连接仍开启 | 172,459 B，约 168.4 KiB | 23,073,340 B，约 22.00 MiB |
| 最新候选这次启动以来的各自最低值，含视频/搜索/教学回归 | 117,300 B，约 114.6 KiB | 16,960,148 B，约 16.17 MiB |

这些是堆测量，两个最低值不保证在同一时刻。当前注册内部堆为 542,451 B、PSRAM 堆为 27,952,512 B；其余物理内存还包含静态/驱动等保留区域，不能简单将整片 32 MiB 减空闲堆称为模型 RAM。待机 WakeNet10 报告的模型分配为 817,764 B；实时下行缓冲上限 45 秒，约 2.16 MB。拍题还会临时分配全帧快照、JPEG/base64、HTTP 响应及文档，结束相机后释放采集缓冲。

## 待现场验收与限制

- **NOT RUN**：真实纸张/手写题/复杂图表在不同距离、姿态、光照下的识题正确率，以及真人自然确认、换题的完整体验。
- **NOT RUN**：手指上滑/下滑、边缘触摸。已验证的是同一原生滚动容器的程序边界与实拍显示。
- **NOT RUN**：数小时连续运行、网络抖动压力、多轮复杂题的答案正确率，以及所有模型、摄像头识人、配网的全量回归。既有实现保留不等于这些项目在本版全部重测。
- 仍可能出现约 420 ms 的疑似插话确认暂停；本轮没有证明任意场景都不中断，也没有达到此前提出的约 500 ms 自然回复目标。
- 云模型读题和数学答案仍可能出错，需核对题干与结果。思考预算改善了测试题的步骤质量，也增加等待及 token 消耗。原始 usage 继续即时输出，不新增计费存储。

现场建议：先用清楚的印刷题测试“教我做这道题 → 不是，第二题 → 是的”，确认关相机后再解题；要求“步骤详细一点”测试长文上下滑动，再测试“讲解圆形的用途并画一个圆”和“联网搜索后同时绘图”是否仍截断播报。

接口依据：[千问视觉能力](https://platform.qianwenai.com/docs/developer-guides/multimodal/vision)、[思考模式与预算](https://platform.qianwenai.com/docs/developer-guides/text-generation/thinking)。具体可用性以上述真实设备调用回执为准。
