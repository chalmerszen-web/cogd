# 0.6.3：唤醒打断、连续接话与静默结束

2026-11-02 至 11-03，实际设备 ESP32-P4-WIFI6-Touch-LCD-3.5，200 MHz，16 MiB Flash / 32 MiB PSRAM。

**对讲流程已经实现，并完成下述有限实机验证；本轮新唤醒权重没有通过对照，已经撤回。最大音量下的早期插话仍有漏检，不能宣布四组唤醒词达到 95% 或整体验收通过。**

## 设备行为

1. 待机时说“你好，小言”或“Hi，小言”（普通话/粤语），听提示音后说问题。
2. 设备回复过程中再次命中唤醒词，立即请求停止 PCM，取消旧 LLM/TTS 并等待资源收尾，再响提示音。原问题及“回复被中断”的标记保留给下一轮。
3. 完整回复结束后，开放约十秒免唤醒接话；直接继续说即可。保留 480 ms 语音开头缓存，接话不重复响开始提示音。
4. 十秒内没有有效语音，由同一个 LLM 根据上下文生成一句短告别，再回到唤醒待机。十秒是开始请求告别的时间，云端响应和播音另需时间。

没有另建对话引擎或菜单；复用 COGD 的取消、端点、ASR、上下文和统一 TTS。屏幕方向、中文字库及语音音量工具保留。结束的是收音会话，已有持久上下文不清空。这里实现的是用户描述的交互，不声称与 DOT 的内部实现完全相同。

## 实机功能证据

声源为电脑连接的 Misiom-Shooter，实际经过 P4 麦克风、KWS、云端 ASR/LLM/TTS 和板载扬声器。全部是固定合成声回放，没有真人新采音，也没有声压、真实距离或方位标定。

| 检查 | 结果与证据 |
|---|---|
| 默认音量 80，开始播放后插入唤醒词 | 最终固件通过一次完整流程；[final-barge80-02](evidence/conversation-20261102/final-barge80-02/report.json) |
| 提示音后先安静 3 秒，再说新问题 | 未提前录音，仍剩 6,822 ms 接话时间；之后正确识别“蓝莓” |
| 不说唤醒词再次追问 | 正确回答“它是猫，名字叫蓝莓”；接话计数增加两次 |
| 回复播完后静默 | 10,035 ms 后开始 LLM 告别，只关闭一次，最终 `listening`、`duplex=false`、接话窗口为 0 |
| 被打断问题的上下文 | [final-dialogue-04](evidence/conversation-20261102/final-dialogue-04/report.json)：此前未提交过的“花生八号”故事被打断后，正确回答名字，随后正确回答物种与名字；这是同版本前一候选的证据，最终候选保留同一引擎实现，另修提示音尾段和接话准入 |
| 普通语音不能直接打断 | 上述故事播放中说普通追问，打断计数不变；随后说唤醒词才打断 |
| 设备自己说唤醒词 | 最终固件音量 100，从“你好，小言”开头，含两次你好、两次 Hi，没有新增自打断；[final-self-02](evidence/conversation-20261102/final-self-02/report.json) |
| 最大音量 100，刚开始播放即插话 | **仍有漏检**；[final-barge100-04](evidence/conversation-20261102/final-barge100-04/report.json)。前一增益候选有命中记录，但不抵消本次失败，也不合并成一个稳定成功率 |
| 主机回归 / 串口测试 / C3 构建 | 99/99、11/11、构建通过；未刷写 C3 |

此前失败和诊断记录均保留。`final-dialogue-01` 在 Wi-Fi 连接前开始测试；`final-dialogue-02/03` 遇到串口测试脚本错误；`final-barge100-01` 的 JSON 被启动日志穿插。这些不能计为完整语音功能通过。串口脚本已修复流式文字前缀解析、异步事件处理和超时变量覆盖，并补回归；长期播放时持续排空串口。

提示音后的短噪声曾使旧的三帧判定提前收音，最终改为复用现有端点的 160 ms 内七帧语音准入。提示音先排空 I2S，结束后前 200 ms 保留 PCM、暂不触发语音起始；上述等待三秒的测试验证了该场景，不能外推为所有环境零误接话。

## 一轮唤醒训练与取舍

新增候选训练 4,000 步，三头仍为 24/24/48，使用已有 TRAIN 集的 44,713 个扩增实例。三个头各 300 帧 C/Python/Torch 整数结果一致。训练监测数据含已退役到 TRAIN 的旧开发来源，监测命中率不是独立成功率。

用本轮事先固定的同一批 60 次弱音开发回放比较，阈值 740、KWS 输入增益 1：

| 发音 | 修改前 R2 | 新训练 R1 |
|---|---:|---:|
| 普通话“你好，小言” | 0/9 | 2/9 |
| 普通话“Hi，小言” | 1/9 | 0/9 |
| 粤语“你好，小言” | 1/9 | 2/9 |
| 粤语“Hi，小言” | 1/9 | 0/9 |
| 反例误唤醒 | 0/24 | 2/24 |

总正例从 3/36 变为 4/36，Hi 两组退步且新增误触发。因此最终保留 R2，模型文件与本轮开始前逐字节相同，没有以放低阈值换取表面命中率。[修改前](evidence/conversation-20261102/wake-before/report.json)、[新候选](evidence/conversation-20261102/wake-after/report.json)、[选择记录](evidence/conversation-20261102/model-selection.json)、[整数一致性](evidence/conversation-20261102/parity-r1/integer-parity.json)。

这里的 0.10 / 0.06 是电脑数字播放增益，另有滤波和短反射条件；实际位置没移动。这批比以前普通音量测试苛刻，不能拿不同声源条件的百分比直接声称进步或退步。新模型没有达到采用门槛是本轮结论，不将训练完成等同于优化成功。

## 当前固件的新独立回放

| 发音 | 成功 / 回放 | 比例 |
|---|---:|---:|
| 普通话“你好，小言” | 7/8 | 87.5% |
| 普通话“Hi，小言” | 5/8 | 62.5% |
| 粤语“你好，小言” | 8/8 | 100.0% |
| 粤语“Hi，小言” | 6/8 | 75.0% |

反例误唤醒 **5/24（20.8%）**，均为“小燕／小杨”等近音人名。原始结果：[final-wakes/report.json](evidence/conversation-20261102/final-wakes/report.json)。本批没有达到四组各 ≥95% 的目标。

这 56 次测试在最后的接话 PCM 尾段修正之前完成；最终固件的模型、AEC、增益和阈值相同，该修正只在免唤醒接话起始时执行，唤醒独立测试关闭该路径。结果文件保留对应候选的独立二进制哈希，不冒充为最终二进制逐字节相同。

最终测试在选回 R2 后冻结：四组各八条，反例二十四条，共五十六次，电脑播放增益 0.35。来源来自先前未评分的保留集；本轮未据结果调参。普通话新音色与训练来源分开，粤语为新录音、已见过的 Rocky/Kiki 音色；八次不等于八位独立说话人。反例比例不是长期每小时误唤醒率，更不是用户本人在 20–50 厘米处的成功率。

## 回声与资源

ES8311 的麦克风和真实 DAC 参考在同一 I2S 时钟下采集，使用 `esp-sr` 高性能语音识别 AEC，512 样本 / 32 ms。临时四秒四路诊断确认高播放音量下外部唤醒被混合声掩盖；降低模拟输入增益本身没有解决全部漏检。最终保留播放时 ADC 30 dB、AEC 后乘 4，静音恢复 42 dB；输出 DAC 从 100 校准为 84。

**代价：同一主音量下，最大模拟输出比 0.6.2 低约 8 dB；比早期 65 设置仍高约 9.5 dB。** 0–100 口述音量继续有效。这个取舍改善了可测的双工条件，但最高音量的早期唤醒仍不稳定，不应说降低响度就解决了所有问题。

| 项目 | 占用 |
|---|---:|
| 四组唤醒共用推理工作区 | 17,096 B，16.70 KiB |
| 三头权重与描述常量 | 35,931 B |
| 静音状态种子 | 12,992 B |
| 权重、描述与种子合计 | 48,923 B，47.78 KiB；本轮未增加 |
| AEC 与三路处理缓冲的实测堆增量 | 114,044 B，其中内部堆 11,536 B |
| 接话开头缓存 | 15,360 B 静态 RAM |
| 采音任务额外栈 | 4,096 B |

四词共用模型，不是每个词分别占一份。AEC/接话缓存/额外栈合计主要新增运行占用约 130.37 KiB，另有程序代码、对齐和少量状态；不是整机总增量。常量位于 Flash rodata，本配置还映射/复制到 PSRAM。[链接结果](evidence/conversation-20261102/memory-static.json)。临时 512,000 B 四路录音缓冲及导出命令已从最终运行源码删除。

最终音量 80 的有界对话中 AEC 观测最大墙钟耗时 11,159 µs/块；其他诊断候选在 Flash/网络活动中出现过超过 32 ms 的观测，不能据本次峰值保证所有场景实时性。此批设备统计的采音队列丢样为 0；没有增加硬件 RX 溢出的独立测量。摄像头/原片视频解码与双工语音同时运行的压力测试未执行。

仍可优化混合回声条件的训练、弱音与声调特征、麦克风和喇叭的声学隔离。更多参数本身不保证提高成功率，既有大模型实验也未通过误唤醒门槛。最高可达多少目前没有可信实测依据；95% 仍是目标。代价可能是更低最大响度、额外训练数据/模型调用、CPU/RAM/功耗，或声学硬件调整。
