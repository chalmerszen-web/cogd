# P4 独立实时语音：实施、实测与边界

2026-11-05，Waveshare **ESP32-P4-WIFI6-Touch-LCD-3.5**。用户选择 P4 直接连接千问：电脑仅播放固定测试语音、录音和采集串口证据，设备运行不需要电脑代理。原始 Word [实施方案](docs/ESP32P4_千问实时语音终端实施方案.docx) 已原样存档（58,565 字节，SHA-256 `a3147ada65f4abdb371bcc955427bed8d8b59382ea52455563a2ee90c14bfda8`）；[段落索引](evidence/realtime-20261105/source-document.txt)保留其建议与验收指标。项目架构见 [ARCHITECTURE.md](ARCHITECTURE.md)。

## 用户能体验到的变化

从“你好小智”进入交流后，P4 使用同一条经 TLS 校验的连接，持续送入 16 kHz 单声道语音，接收千问 24 kHz 流式回复。默认模型为 `qwen-audio-3.1-realtime-flash`，音色 `longanqian_v3.1`，语义判停 `smart_turn_v2`。正常接话不用再唤醒，播音时可以插话；可以说“先聊到这里，再见”，或者等约 30 秒，由设备说一句告别，再回到本地唤醒。待机不上送麦克风音频。

原来的 ASR → 路由 → 主模型 → TTS 链路保留作兼容模式。自然对话不使用固定占位套话。用户要绘图、调音、搜索或调用其他现有工具时，由实时模型走同一个 COGD 工具表；慢任务与说话分开调度，插话不会取消任务。摄像头、视频、屏幕方向和配网没有另建一套实现。参考[千问客户端事件](https://help.aliyun.com/zh/model-studio/fun-audiochat-client-events)、[实时语音指南](https://help.aliyun.com/zh/model-studio/qwen-audio-realtime-user-guides)。

## 实际诊断

- 账号能建连，不等于能正常出声。最初完整工具表的握手成功，正式生成却返回服务端错误；在同一账号逐项缩减后，定位到模型对工具 JSON Schema 的兼容性。只改对外公布的形式，本机仍校验实际参数。另一处限制是单个音频事件约 25.8 kB，超过 COGD 文字 JSON 的旧上限；只有受限的实时接收路径放宽，其他路径保留原限制。
- 设备发出的声音会回到单麦。实测四秒扬声器单播的 AEC 输出 RMS 为约 204；叠加耳机人声时为约 1965，单位为 16 位 PCM 计数，并非声压。对照在[固定条件声学采集](evidence/realtime-20261105/acoustic-01/report.json)。仅看残余音量的早期版本会在无人插话时自行停声，原始失败记录保留。当前策略结合真实 DAC 参考、同帧近端语音证据和可恢复的短暂停播。
- 服务端有时先发回答、再发用户的最终转写。按输入项 ID 配对，并把已经播放的真实话轮写入原有上下文。旧的“回答被打断”标记、后台状态等不会拿来充当用户对话。长回答堵住旧连接时，只允许在旧连接尚未受理新话轮的条件下切换，避免重复执行。
- 图片、视频、绘图和音量仍通过原有工具。账号返回的绘图参数有时将整个图形数组编码为字符串，[真实协议样例](evidence/realtime-20261105/g0-draw-contract/trace.json)可复现。适配层严格按已知类型解包，同一话轮重复的操作复用已有结果。实时回执读取 `response.usage`，不自行换算价格，也不持久化账单。

## 验证口径

硬件回归采用电脑的 Misiom-Shooter 耳机对着开发板的麦克风播放固定语音；P4 自己识别、联网和驱动喇叭。测试脚本没有把 PCM 从串口注入。云端文本契约、主机状态机、板端真实采音和真人主观体验是四种不同证据。串口的“开始播音”为播放器首次向 I²S 送样；与测试文件最后一个有声帧的差值是设备时延估计，不等于用户实际听到可懂首字的时延。其中还含 Windows 声卡调度和串口观测误差。板上“停止命令用时”更不能当成整机打断延迟。

[共享主机回归](evidence/realtime-20261105/host-tests-02.log)：101/101，包含响应代数、重复调用、迟到 PCM 和超界 JSON；[C3 发布配置交叉编译](evidence/realtime-20261105/build-c3-final.log)通过，本轮没有刷 C3。100 轮状态机循环属于主机测试，不能代替 100 次真机打断。文档给出的 P95 打断 200 ms、P95 首声 1.5 秒、双麦户外/多人和两小时连续稳定运行分别验收，不能用几段录音折算。现有 ES8311 一路麦克风和一路 DAC 参考，不具备双麦方向性。

## 运行内存和 Flash

| 当前项目 | 实测/构建值 |
|---|---|
| 实物 | 16 MiB Flash、32 MiB PSRAM；6 MiB 是应用分区大小 |
| 应用镜像 | 5,711,648 B（5.45 MiB），占 6 MiB 应用分区 90.8%；余 579,808 B |
| 资源及数据 | 字体、查找表等资源 1,329,960 B；上下文独立预留 2 MiB。Wi-Fi、密钥和用户上下文不在分发包内 |
| 冷启动联网、本地监听 | 内部堆空闲 178.5 KiB / 可分配 532.2 KiB；PSRAM 堆空闲 23.75 MiB / 可分配 26.68 MiB |
| 自然会话已就绪（短问用例快照） | 内部堆已用 365.6 KiB，余 166.5 KiB；PSRAM 堆已用 4.57 MiB，余 22.11 MiB |
| 上述语音用例采到的最低剩余量 | 内部堆 147.5 KiB，PSRAM 堆 22.03 MiB |
| 随后跑过摄像头、视频、配网的同一次开机低水位 | 内部堆 120.9 KiB，PSRAM 堆 14.84 MiB；是实测负载的低水位，不是所有场景的保证 |

会话最大下行 PCM 缓冲 2,160,000 B、WebSocket 单事件接收区 262,144 B；另有 192,000 B 的麦克风环形缓冲，给短暂重连留余量。这些预算与真实空闲堆是两种口径，不能叠加计算。Flash 的应用大小不等于整片 Flash 写满，也不是运行 RAM 用量。

## 建议用户验收

1. 说“你好小智，给我讲个故事，主角叫栗子”；它播音时直接说“先停一下，主角叫什么？”。
2. 等答完直接说“我给你一个新名字，嗯……白桃”，再问“刚才的新名字是什么？”。
3. 说“做一个三十秒慢速查询测试”；受理后说自己的名字，再追问；观察任务结果是否等你说完才播。
4. 说“在黑底上画一个红圆，写你好”，然后说“先聊到这里，再见”；另试一次安静约 30 秒，看是否先告别再回到待机。

目前不宣称达到文档的 200 ms / 1.5 秒 P95；上面区分了测试音源时钟、板端时钟及独立声学转写。100 次真机连续插话、两小时耐久、真人远场、户外多人和声源方向均未作为本轮通过项。早期候选版曾出现扬声器自打断、长音频队列满、工具只口头答应或重复重试；保留在同目录的 acceptance-05～09，不把其中失败或测试器误判的结果计为最终通过。
