# COGD P4 四项联合开发方案

日期：2026-11-03（Asia/Shanghai）。状态：**已执行有限开发与测试，已刷入 0.7.0；唤醒候选未达标并按停止条件保留基线**。结果、实际资源和验收入口见 [INTERACTION_REPORT.md](INTERACTION_REPORT.md)。本文保留原方案及尚未完成的验收目标，不能把计划表当作通过记录。

执行范围修订：第四项只获取当前实际调用模型的返回回执，转交瞬时回调；不保存、不估价、不建立账本，后续再接平台上报。全模型文档评估仍保留作为接口资料，不把它扩大成本轮实现范围。

用户要求先评估并记住方案，再将四项纳入同一轮开发：唤醒优化、视频等待与触屏播放、触屏配网、千问全模型回执用量与计费。第四项覆盖未使用过的模型，不能只覆盖 WAN3/ASR/TTS，也不能将 OpenAI 兼容 `/models` 列表当作整个平台的模型集合。

沿用实际 3.5 板、200 MHz 稳定档、现有 COGD 引擎和工具生命周期；P4 屏幕方向不变。电脑可用于训练、构建和自动测试，产品运行与视频处理仍由 P4 独立完成。四项的证据分别记录，不将方案、接口定义或固定回放算作真人验收。

## 一、实际收音/回声训练与预训练声学特征

### 已知基础

- 已有 R2 三头 INT8 模型、后级复核、AEC 和完整对话机制。再增加一个相同复核器、扩大通道或调低阈值，不能视为新方案。
- 最近普通回放四组为 7/8、5/8、8/8、6/8，近音挑战集误触发 5/24；弱音开发集及扩大模型失败记录保留。见 [CONVERSATION_REPORT.md](CONVERSATION_REPORT.md)、[WAKE95_REPORT.md](WAKE95_REPORT.md)。
- 普通话“小言/小燕”声调不同，可以研究声调区分；完全同音的人名无法仅凭声音辨字，不能把正反标签矛盾的数据放进训练。

### 实施路径

1. 冻结新的开发集和独立验收集，按原始音源/音色隔离。已用于选模的历史验收样本仅做回归。
2. 千问生成经发音审核的普通话/粤语四组样本；通过现有耳机与板载麦克风实际回放录制，并采集设备自身 TTS 叠加时的麦克风、DAC 参考和 AEC 输出。训练、推理使用一致的前端参数。改变音量/滤波不能等同于已经实测不同物理方位或距离。
3. 先离线评估具有普通话和粤语支持的预训练声学特征是否改善弱音/近音可分性。SenseVoiceSmall 是可研究的教师候选，其官方支持语言包含普通话、粤语；不把整个 ASR 模型直接塞进 P4。只有显示收益后，才迁移或蒸馏到可部署的流式 INT8 唤醒模型。
4. 强化自身播报、近音人名和普通连续讲话反例；独立检查“设备说唤醒词不自触发”和“用户在设备说话期间说词可以触发”。被拒绝的候选不得消耗唤醒冷却。
5. 在 200 MHz 下测量工作区、常量、内部堆、PSRAM、每个音频块的耗时与最差调度；合格后才替换 R2。保持现有唤醒打断、上下文、免唤醒接话和十秒静默告别契约。

### 验收和停止条件

- 四组分别统计正常/弱音/TTS 重叠的命中率，以每组每场景至少 100 次独立回放作为计划中的最终样本量；95% 是验收目标，不是保证或理论上限。音色确实独立与仅录音独立分开报告。
- 近音反例至少 200 次，另做持续背景语音/音乐误触发统计，单位为次/小时。长时测试安排在候选通过短测后；单次零误报不宣布真实误唤醒率为零。
- 先限制为两条预训练特征/蒸馏候选路线。若固定开发对照未改善召回且不增加误触发，停止扩大样本，保留基线并报告失败原因；不为了达到数字反复挑选验收样本。
- 暂不要求用户真人录音。合成回放自测达标后，用户正常使用作最终验收。

来源：[SenseVoice 官方仓库](https://github.com/QwenAudio/SenseVoice)。

## 二、视频准备与触屏播放

### 为什么现在等待很久

当前 `p4_cloud.cpp` 固定提交 720P、9:16、默认 5 秒 WAN3；`p4_media.cpp` 顺序读取 MP4，软件完整解码 High/B 帧，缩放、JPEG 编码并写入 Flash，音频转为 16 kHz PCM。整段完成后才播放。目标 15fps 是缓存播放速度，不能当成 High 解码速度。

此前同一条 5 秒视频实测：云端生成 **442.333 秒**，板端准备 **270.672 秒**，播放约 **5.236 秒**。板端准备阶段尚无完整分项计时，不能将其中全部耗时归因于 CPU 或网络。原片为 720×1280/30fps High；全部 150 帧需按依赖关系解码，最终仅展示 75 帧。见 [ACCEPTANCE-NATIVE-20261102.md](ACCEPTANCE-NATIVE-20261102.md)。

### 推荐方案

- WAN3 默认改为平台文档支持的 **480P、5 秒、竖屏、有声**；用户明确指定时长时按支持范围处理。仍按比例显示于 320×480，播放目标保持 10–15fps。当前文档说明 WAN3 输出 30fps，未证实可以指定 Baseline/10–15fps 源片；不发送虚构参数。480P 降低源像素工作量，但不能预先承诺首播几秒内完成。
- 新增云端排队/生成、网络读取、MP4 解析、H.264、AAC、缩放/JPEG、Flash、首帧的分项计时。进度用实际完成帧数表示；云端没有百分比时显示阶段和已用时间。
- 优先优化实际瓶颈：避免不必要的 HTTPS Range 连接重建和重复读取；验证 P4 像素处理/整数缩放路径；按解码依赖安全处理帧，不能跳过任意 P/B 帧后仍声称画面正确。
- 缓存保留最近一段完成的视频及有界索引、音频和时间戳。缓存有版本、长度和 CRC，全部完成后提交有效标志；下载/解码失败或断电留下的半成品不能被重播。重播不重新提交模型、不下载、不解码原片、不重写整段 Flash。
- 按源片实际解码吞吐量决定首播缓冲策略。只有吞吐持续覆盖播放所需进度时才启用边准备边播；否则保持完整准备，避免“快出首帧但之后频繁停顿”。P4 的 H.264 编码硬件不能当作 High 解码硬件。

### 触屏交互

| 状态 | 单击视频画面 |
|---|---|
| 生成/准备中 | 保持现有任务并显示进度，不重复提交或重置任务 |
| 播放中 | 暂停画面及声音，保存实际播放位置 |
| 已暂停 | 从暂停位置继续，重新对齐音画时钟 |
| 已结束/已停止且缓存有效 | 从缓存第一帧重播 |

首次准备完仍自动播放，不增加常驻播放按钮；自然结束保留末帧。新图片、绘图或摄像头画面接管后，点击属于当前内容，不意外恢复旧视频。轻触按一次完整按下/抬起计一次，长按与拖动不反复切换。暂停后释放音频资源可恢复语音，续播需重新取得同一媒体租约，避免与 TTS 同时驱动 I2S。

验收：480P 原始 WAN3 全链路一次生成；首次各阶段计时；点击暂停/续播与结束重播至少各 10 次；暂停 30 秒后续播；恢复音画差目标绝对值 ≤100ms；暂停响应目标 ≤300ms、有效缓存重播首帧目标 ≤2 秒（均待实测）。断网下缓存重播、坏缓存、任务切换、准备取消与恢复语音也要检查。不得用电脑转码片替代 WAN3 原片验收。

来源：[WAN3 创建接口](https://platform.qianwenai.com/docs/api-reference/video-generation/wan30-video/create-task)。

## 三、30 秒离线自动触屏配网

当前只有一组 `settings_v1.ssid/password`，有退避重试，没有 AP 列表、键盘或多网络优选。BSP 已初始化电容触摸与 LVGL 输入设备，可复用。

### 行为

1. 启动/断线后先扫描并尝试已保存网络，优先信号较强且认证方式匹配的候选；失败后按退避切换下一项。
2. 连续 **30 秒未连接 AP 或未取得有效 IP**，自动进入配网页。短暂断线恢复则取消计时。已经连上 AP 但外网/模型服务故障单独显示，不把 API 错误当成 Wi-Fi 密码错误。
3. 展示附近 2.4GHz AP，按信号强弱排列，显示加密、已保存、当前连接状态；同名 AP 适当合并并保留连接候选，不让重复条目淹没列表。提供刷新、返回和隐藏 SSID 手动输入。
4. 点击 AP 后进入密码页。参照用户两张图片，采用九宫格 **abc / ABC / 123 / 符号** 切换，包含空格、退格、清空、显示/隐藏密码和连接。字母采用确定性的多次点击循环选择（例如 ABC 键循环 a/b/c），并支持立即确认当前字母；密码输入不使用词语预测，避免输入内容被自动替换。
5. 认证并获得 IP 后才保存成功凭据；错误密码、超时保留输入供修改，不覆盖已验证网络。保存少量多网络配置（计划最多 8 组，需检查 NVS 剩余空间），迁移现有配置并保证重启自动连接。
6. 信号优先用于开机/重连选网；正常稳定连接时不因为几 dB 波动频繁切换，避免中断对话/下载。用户正在输入时后台扫描不得清空输入或抢走焦点。

配网页需要明确的显示所有权：离线超时出现时，正在播放的缓存视频暂停并保留位置；后台云任务保留 task_id；键盘触摸不能同时触发视频暂停/播放。联网恢复后退出配网，恢复此前可恢复的显示状态。

硬件限制：C6 为 2.4GHz Wi-Fi 6；纯 5GHz AP 不可连接。SSID 包含 `_5g` 本身不是频段判据，应以实际扫描结果为准。

验收覆盖无配置冷启动、29/30 秒边界、瞬断恢复、AP 消失、错误密码、数字/大小写/符号密码、保存后重启、多网络优选、无 AP、已连 AP 但外网中断，以及视频/键盘触摸事件互斥。实拍验证触摸坐标，保持屏幕方向原样。

来源：[微雪 3.5 硬件](https://docs.waveshare.net/ESP32-P4-WIFI6-Touch-LCD-3.5/)、[C6 频段说明](https://www.espressif.com/en/products/socs/esp32-c6)。

## 四、千问全模型的用量与费用

### 全量评估范围

将当天模型接口清单、全站模型文档/价格表、专用 API 定义与设备能力目录取并集。为每个明确模型 ID 建立索引，记录所属协议、回执字段路径、终态/流式/异步获取时机、计量单位、累计或增量口径、目录来源和证据等级。仅文档存在不代表当前 Key 已开通；不存在逐模型 schema 的条目明确列出缺口。完整结果置于 `evidence/plan-20261103/model-usage-audit/`。

已完成该轮全目录评估：[全模型评估](evidence/plan-20261103/model-usage-audit/REVIEW.md)、[427 项逐模型索引](evidence/plan-20261103/model-usage-audit/ALL_MODELS.md)。范围由实时目录 184 项、价格表 326 个明确 ID、107 份 OpenAPI、Sambert 型号表及设备旧目录合并；不是只看已调用模型，也不是 427 个型号均已开通/付费验证。382 项可关联协议字段，45 项字段缺口；369 项有目录价，58 项缺精确价格。新增收费调用 0 次。

覆盖文本/推理/代码/视觉、深度研究和工具、全部图片和视频系列、3D、世界模型、ASR、TTS、实时多模态、音色复刻/设计、音效/音乐、文本/图片/多模态翻译、文本/多模态向量、重排序；平台服务额外费用另列，不能硬转换成 token。

已有实际回执示例：WAN3 返回 `usage.video_count/duration/SR/output_video_duration/input_video_duration/fps/ratio`；Qwen TTS 返回 `usage.input_tokens/output_tokens/total_tokens/characters`。这些只是实测证据，不代替其他模型的文档核对。

### 设备实现（按最新授权收窄）

- 复用现有 HTTP/SSE/WebSocket JSON 解析点，覆盖主 LLM、实时路由、ASR、TTS、搜索、图片、视频和通过通用 skill 实际调用的模型。兼容文本流消费只含 usage 的尾块。
- `agent_model_usage` 提取原始 `usage` / `payload.usage` / `response.usage` / `output.usage`，连同模型和返回的 request/task/response ID，调用 `esp_agent_model_receipt`。
- 回调为同步借用数据，返回即释放；当前输出 `@usage` 诊断事件，后续可在同一位置接入上报。设备不保留明细、汇总、NVS 记录或费用面板。
- 保留原始单位和嵌套字段，不自行累加；累计中间回执与终态不能相加。终态未返回用量标记 `not_returned`，不能当作零消耗。未返回实际费用时不推算账单金额。

### 验收

以当前协议响应样例与实际调用校验字段；覆盖 usage 尾块、嵌套音频/字符/视频单位和未返回用量。开发其它三项时顺带核对真实返回，不为验证账本调用全部模型，不声称获得实扣金额。

## 联合实施顺序与交付

1. 保留已完成的全目录字段评估，按当前范围接入用量回执回调，不实现保存和费用估算。
2. 接入触摸事件分发、配网与多网络保存，再在同一显示所有权下实现视频缓存/暂停/续播/重播；同步比较 480P 首播准备时间。
3. 采集最终音频前端下的弱音/回声数据，做预训练特征对照与有限候选训练，合格者才进入联合固件。
4. 合并后执行语音/触摸/断网/云任务/媒体内存与取消的组合回归；构建、烧录、读回校验及摄像头实拍后交付。逐项列 PASS/FAIL/NOT RUN 和资源差异，更新架构文档。

资源需按并发峰值测量：旧 720P 视频准备时最低剩余堆约 2.1MiB，不能把待机约 27MiB 当作任何时候都可用。尚不引入电脑转码、第二套 Agent、全量大模型本机部署或未经验证的 400MHz 档。
